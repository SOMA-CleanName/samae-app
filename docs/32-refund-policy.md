# 32. 환불·취소 정책

> 확정: 2026-08-29 · 상태: **정책 확정 / 코드 미반영**
> 이 문서가 환불의 진실이다. 화면 문구(`PolicyNote`)·봇 전역 정책(`PLATFORM_POLICY`)·
> 어드민 환불 처리는 모두 여기서 파생된다. 문구를 고칠 일이 생기면 이 문서를 먼저 고친다.
>
> ⚠️ [06-payment-settlement](06-payment-settlement.md) 는 **직접 계좌이체 모델 시절 문서라 낡았다.**
> 현재 자금 흐름은 [23-inquiry-chat-system](23-inquiry-chat-system.md) 의 **사매 계좌 에스크로**다.

---

## 1. 한눈에

기준 시점은 **촬영일**이다. "7일"은 촬영일까지 남은 기간을 말한다.

| 상황 | 고객 환불 |
|---|---|
| 촬영 7일 이상 남음 · 결제 후 **24시간 이내** | **100%** |
| 촬영 7일 이상 남음 · 24시간 경과 | **50%** |
| 촬영 7일 이상 남음 · **연락처 교환 이후** | **50%** (24시간 이내여도) |
| 촬영 **7일 이내** | **환불 불가** |
| 천재지변 (교통 마비급 · 양측 모두에 영향) | **100% 환불 또는 날짜 변경** |
| 작가가 약속을 깸 | **100% 환불 또는 날짜 변경** + 작가 패널티 |
| 고객이 약속을 깸 | 환불 없음 · 작가 허가 시 **날짜 변경 1회** |
| 단순 날짜 변경 (천재지변 아님) | 변경 성사 시 **이후 환불 불가** |

환불 비율은 **고객이 실제로 낸 총액(촬영비 + 출장비)** 기준이다. 촬영비만 따로 세지 않는다.

## 2. 금액 계산

현재 구조:

```
고객 지불액 = 촬영비 + 출장비
사매 수수료 = 촬영비 × 수수료율        ← 출장비에는 붙지 않는다
작가 수령액 = 촬영비 + 출장비 − 사매 수수료
```

### 수수료 모델 — 정액과 정률이 공존한다

지금은 전역 정액 6,000원(`PLATFORM_FEE_KRW`, `src/lib/platform-fee.ts`)이고, 앞으로는
**작가별 정률**로 간다. 다만 **한날한시에 갈아엎지 않는다** — 두 방식이 동시에 살아 있고,
작가 단위로 하나씩 옮겨갈 수 있어야 한다.

그래서 수수료는 상수가 아니라 **작가별 설정(어드민 관리)** 으로 둔다:

```
작가 수수료 설정 = { mode: "flat", amountKrw }   ← 정액 (현행, 기본값 6,000)
                 | { mode: "rate", rate }        ← 정률 (촬영비 × 요율)

수수료 = mode === "flat" ? amountKrw : 촬영비 × rate
```

- 설정이 없는 기존 작가는 **전역 기본값(정액 6,000)** 을 따른다 → 마이그레이션 시 아무도 안 깨진다.
- **정률로 전환할 때의 기본 요율은 10%** 다. 어드민에서 작가 한 명씩 `flat → rate` 로 옮기고,
  필요하면 그 작가만 다른 요율로 조정한다. 전환 전 작가는 계속 정액이다.
- 신규 작가에게 어느 쪽을 기본으로 줄지는 정률 전환이 끝나는 시점에 `rate 10%` 로 바꾼다.
- **계산은 한 곳에서만.** 화면·정산·환불이 각자 `PLATFORM_FEE_KRW` 를 읽는 지금 구조를
  `resolveFee(photographer, 촬영비)` 한 함수로 모은다. 두 모델이 공존하는 동안
  숫자를 직접 읽는 자리가 하나라도 남으면 그 화면만 옛 금액을 보여준다.

**예약 시점의 수수료 설정은 예약 건에 스냅샷으로 굳힌다.** 나중에 요율을 바꾸거나 정액↔정률을
전환해도 지난 거래의 정산·환불 금액이 소급해서 흔들리면 안 된다. 스냅샷에는 계산된 금액만이
아니라 **모드와 요율까지** 남긴다 — 부분 환불을 나중에 다시 계산할 수 있어야 한다.

### 50% 환불

**사매 수수료는 환불하지 않는다.** 입금 확인 시점에 이미 발생한 매출이고, 사매는 중개를
이미 완료했다. 환불 부담은 **작가가 진다.**

```
고객 환수  = (촬영비 + 출장비) × 50%
사매 수수료 = 그대로 유지
작가 최종  = 촬영비 + 출장비 − 사매 수수료 − 고객 환수
```

**예시** (촬영비 100,000 · 출장비 20,000 · **정률 10%** 인 작가)

| 항목 | 정상 진행 | 50% 환불 |
|---|---:|---:|
| 고객 지불 | 120,000 | 120,000 |
| 고객 환수 | — | **60,000** |
| 고객 실부담 | 120,000 | 60,000 |
| 사매 수수료 (100,000 × 10%) | 10,000 | **10,000** |
| 작가 최종 수령 | 110,000 | **50,000** |

작가는 일하지 않고도 절반을 받는다 — 촬영일이 임박해 다른 예약을 못 받은 손실을 메우는 몫이다.

### 100% 환불 — 수수료는 귀책으로 가른다

전액 환불이라도 사매 수수료를 면제할 때와 아닐 때가 다르다. **가르는 기준은 작가 귀책 여부**다.

| 100% 환불 사유 | 사매 수수료 | 작가 최종 | 취지 |
|---|---|---:|---|
| 결제 후 24시간 이내 변심 | **면제(`waived`)** | **0** | 아무도 손해 보지 않는 구간 |
| 천재지변 (교통 마비급) | **면제(`waived`)** | **0** | 누구의 잘못도 아니다 |
| **작가가 약속을 깸** | **유지** | **− 수수료** | 패널티의 일부 |

```
고객 환수  = 촬영비 + 출장비                      (항상 전액)
사매 수수료 = 작가 귀책이면 유지, 아니면 면제
작가 최종  = 작가 귀책이면 −수수료, 아니면 0
```

**예시** (촬영비 100,000 · 출장비 20,000 · 정률 10%)

| 항목 | 24시간 변심 / 천재지변 | 작가 귀책 |
|---|---:|---:|
| 고객 실부담 | 0 | 0 |
| 사매 수수료 | 0 (면제) | **10,000** |
| 작가 최종 | **0** | **−10,000** |

정산 전(사매가 아직 돈을 들고 있음)이라면 사매가 그대로 전액을 돌려주면 끝이고, 작가 귀책 건만
수수료가 **작가 미수금**으로 남는다. 정산 후라면 작가가 받은 돈을 반환한다. → §4

## 3. 상황별 규정

### 3-1. 촬영 7일 이내 — 환불 불가

작가가 그 날짜를 비워둔 채 다른 예약을 받지 못한 시점이다. 취소는 가능하되 환불은 없다.

**경계 판정 — 날짜가 아니라 시각으로, 고객에게 유리하게.**

```
환불 가능 =  촬영 시각 − 지금  ≥  7일(168시간)
```

- 기준은 **촬영 시각(`bookings.shoot_at`)** 이다. 자정으로 자르면 오전 9시 촬영과 오후 8시
  촬영이 같은 취급을 받는데, 작가가 하루를 비운 정도는 실제로 다르다.
- **정확히 168시간 남은 순간은 환불 가능** 쪽에 넣는다. 경계에서 다투게 되면 "1분 차이로
  전액을 잃었다" 는 쪽이 반드시 문제를 제기한다. 경계는 고객 쪽으로 연다.
- 시각이 없는 옛 예약(`shoot_at` 없이 `shoot_date` 만 있는 건)은 **그날 23:59(KST)** 를
  촬영 시각으로 본다 — 같은 원칙(고객 유리)이다.

### 3-2. 결제 후 24시간 — 100% 창구

**기산점은 고객이 채팅에서 `입금 완료` 를 누른 시각(`bookings.transfer_marked_at`)** 이다.
사매가 확인한 시각이 아니다 — 고객이 "결제했다" 고 인지하는 시점이 기준이어야 하고,
운영 확인이 늦어졌다는 이유로 고객의 창구가 줄어들면 안 된다.

잘못 눌렀거나 마음이 바뀐 걸 되돌릴 수 있는 유일한 구간이다.
단 아래 두 경우엔 이 창구가 닫힌다:

- 촬영일까지 7일이 안 남았다 → 애초에 환불 불가 구간
- **연락처를 교환했다** → 아래 3-3

### 3-3. 연락처 교환 이후 — 무조건 50%

**연락처 교환은 입금 확인 이후에만 허용한다.** (그 전까지는 검열 유지 — `src/lib/moderation.ts`)

교환이 이루어진 순간부터는 24시간 규칙이 사라지고 50%가 적용된다. 이유: 연락처가 넘어가면
사매 밖에서 거래를 이어갈 수 있게 되므로, 그 시점 이후의 "100% 환불"은 무상 이탈 통로가 된다.

### 3-4. 천재지변 — 정의부터 좁게

**천재지변 = 작가와 고객 *양쪽 모두* 에게 영향을 미치는 사건.**
한쪽에만 영향을 주는 사정은 천재지변이 아니라 **약속을 깬 쪽의 귀책**이다.
(작가가 아파서 못 감 → 작가 귀책 / 고객 개인 일정이 틀어짐 → 고객 귀책)

**판별 강도는 높게 잡는다 — 실제로 교통이 마비되는 수준**이어야 한다.
그 수준이 아니면 **고객측 귀책으로 본다.** (비가 좀 온다, 길이 막힌다 정도는 해당 없음)

| 판정 | 결과 |
|---|---|
| 교통 마비급 천재지변 | **100% 환불 또는 날짜 변경** — 고객이 고른다 |
| 그 미만 | 고객 귀책 → 아래 |

### 3-5. 귀책 — 약속을 깬 쪽이 진다

**고객이 깬 경우**
- 환불은 §1 표의 일반 규정을 그대로 따른다 (7일 이내면 환불 없음).
- **작가가 허가하면 날짜 변경 1회**가 가능하다. 2회는 없다.

**작가가 깬 경우** — 천재지변이 아닌데 어떤 이유로든 촬영 장소에 갈 수 없는 경우
- 고객에게 **100% 환불 또는 날짜 변경**을 제공한다. 선택권은 고객에게 있다.
- 여기에 더해 **작가에게 패널티**를 부여한다. (실체는 §5 미확정)

### 3-6. 날짜 변경 (천재지변·귀책 아님 — 단순 요청)

- **원칙적으로 불가.**
- 다만 **기존 촬영일까지 7일 이상 남아 있고, 새로 잡는 날짜도 7일 이상 뒤인 경우**에 한해
  작가가 재량으로 수용할 수 있다. 어느 한쪽이라도 7일 안쪽이면 작가도 수용할 수 없다.
- 변경이 성사되면 **그 예약은 이후 환불 불가**임을 고객에게 명시하고 동의를 받는다.
  (날짜를 미루는 것으로 이미 한 번의 배려가 소진됐다는 뜻)

## 4. 실행 경로

현재 자금은 사매 계좌를 거친다(에스크로). 따라서 환불 시점이 정산 전인지 후인지에 따라 갈린다.

| 시점 | 처리 |
|---|---|
| 고객 입금 알림 전 (`accepted`, 미입금) | 취소 자유 · 환불 개념 없음 |
| 입금 알림 ~ 사매 확인 전 | 사매가 받은 돈에서 그대로 환불 |
| 사매 정산 완료 후 (작가가 이미 수령) | 작가가 부담분을 사매에 반환 → 사매가 고객에게 환불 |

현재는 전 구간 **운영진 수동 처리**다. 채팅 예약 카드에서 입금 표시(`transfer_marked_at`) 이후
취소 버튼이 감춰지는 것도 이 때문이다 — 환불이 걸리면 사매를 거치게 하려는 설계.

## 5. 미확정 — 코드 반영 전에 답이 필요한 것

1. **작가 귀책 패널티의 실체.** 100% 환불 부담(= −수수료) 외에 추가 제재가 있는지.
   요율 가중? 노출 제한? 경고 누적? (§3-5 의 "패널티" 가 여기로 연결된다)
2. **날짜 변경 1회 카운트.** 고객 귀책 변경 1회 제한을 시스템이 세는지, 작가가 기억하는지.
3. **연락처 교환 시점의 판정.** 입금 확인 후 검열을 풀면 시스템에 교환 기록이 남지 않는다.
   50% 룰을 자동 적용하려면 "입금 확인 = 교환 가능 시점" 으로 갈음할지, 별도 기록을 남길지.
4. **환불 요청 접수 창구.** 고객이 채팅에서 버튼으로 요청하는지, 사매에 직접 문의하는지.
5. **요율 상·하한.** 작가별 조정을 허용하는 범위 (예: 5~15%).
