# 21. 사용자 전환 화면 UI 개선 (2026-08-02)

> 문서 상태: 구현 반영 완료, 배포 전

> 범위: 탐색(`/explore`) → 사진 상세(`/photos/[id]`) → 문의(`/inquiry`)로 이어지는 사용자 전환 플로우와 작가 상세 CTA
>
> 선행 문서: [17. UI/UX 전면 개편](17-ui-overhaul.md), [20. 탐색 에디토리얼 큐레이션](20-explore-editorial-curation.md)

## 1. 변경 목적

이번 작업은 사용자가 사진을 탐색하고, 촬영 조건을 이해하고, 문의를 제출하는 과정에서 생긴 다음 문제를 개선한다.

1. 탐색 큐레이션 첫 카드에서 이전 카드가 보이지 않아 순환형 캐러셀로 인식하기 어려웠다.
2. 취향 테스트가 탐색 화면 마지막에 있어 개인화 진입 우선순위가 낮았다.
3. 문의 첫 화면이 아래 정렬되고 세로 사진이 화면을 과도하게 차지했다.
4. 문의 선택지와 연락 방법이 실제 운영 방식보다 복잡했다.
5. 사진 상세의 가격·패키지·작가 정보 위계가 약하고 CTA와 안내 카드가 지나치게 둥글었다.

핵심 원칙은 **첫 화면 이해 속도 향상**, **문의 단계 간소화**, **촬영 조건의 명확한 전달**이다.

## 2. 탐색 화면

### 2.1 오늘의 큐레이션 무한 순환

- 캐러셀 트랙 앞에 마지막 카테고리, 뒤에 첫 카테고리를 복제한다.
- 첫 카테고리에서도 왼쪽에 마지막 카드가 회색·블러 상태로 보인다.
- 마지막→첫 번째 및 첫 번째→마지막 전환은 복제 카드까지 애니메이션한 뒤 같은 모습의 실제 카드로 전환 효과 없이 이동한다.
- 기존 조작은 유지한다.
  - 좌우 탭: 이전·다음 사진
  - 좌우 스와이프: 이전·다음 카테고리
  - 길게 누르기: 자동 재생 일시정지
  - 자동 재생: 전체 사진 타임라인 순환

관련 코드:

- `src/app/(user)/explore/MovingCoverCarousel.tsx`

### 2.2 섹션 우선순위 변경

탐색 메뉴와 실제 콘텐츠 순서를 다음과 같이 통일했다.

1. 내 취향 테스트
2. 추천 무드
3. 사매 인기 스냅

함께 변경된 항목:

- 탭 배열 순서
- 섹션 DOM 순서와 `sec-*` 이동 대상
- 화면 섹션 번호 `01/02/03`
- 스크롤 스파이 활성 순서
- 마지막 섹션 하단 폴백
- 로딩 스켈레톤 순서

`ExploreTabBar`는 전달받은 탭 배열 순서대로 스크롤 위치를 판정하므로 별도의 활성화 로직 변경 없이 새 UI 순서와 동기화된다.

관련 코드:

- `src/app/(user)/explore/page.tsx`
- `src/app/(user)/explore/ExploreTabBar.tsx`
- `src/app/(user)/explore/loading.tsx`

## 3. 문의 화면

### 3.1 첫 대화 상단 정렬

원인은 채팅 본문 위의 `flex-1` 스페이서와 첫 선택지 생성 시 실행되던 하단 스크롤이었다.

변경 후 정책:

- 첫 질문이고 답변이 없으면 채팅 컨테이너의 스크롤 위치를 `0`으로 유지한다.
- 두 번째 질문부터는 새 선택지의 하단을 화면에 맞추는 기존 진행형 스크롤을 유지한다.
- 연락처 입력과 완료 단계는 계속 하단으로 이동한다.

### 3.2 문의 사진 크기 제한

단일 문의 사진은 원본 비율을 보존하되 다음 제한을 적용한다.

- 최대 높이: `min(42svh, 20rem)`
- 최대 너비: 컨테이너 너비
- 표시 방식: `object-contain`으로 자르지 않고 축소

여러 장 문의는 기존 `80×80px` 썸네일 레일을 유지한다. 문의 로딩 스켈레톤도 축소된 사진 크기에 맞췄다.

### 3.3 질문 선택지 정리

촬영 목적:

- 커플·우정 스냅
- 웨딩
- 개인·프로필
- 단체·행사
- 그 외 목적

삭제·변경 사항:

- `가족` 삭제
- `웨딩·본식` → `웨딩`
- `행사·기타` → `단체·행사`
- `아직 고민 중이에요` → `그 외 목적`

촬영 희망일:

- `이번 주말` 빠른 선택 삭제
- `2주 이내`, `한 달 이내`, `날짜 직접 선택`, `날짜는 미정이에요` 유지

### 3.4 연락 방법 간소화

문의 화면에서 제공하는 연락 방법은 다음 두 가지다.

- 전화번호
- 카카오톡 ID

이메일 선택·아이콘·클라이언트 검증·클라이언트 제출 경로는 제거했고 버튼은 2열로 변경했다. 서버 액션의 이메일 필드는 기존 데이터 및 다른 경로와의 호환을 위해 유지한다.

### 3.5 접수 완료 안내 분기

제출 시 선택한 연락 채널을 클라이언트 상태에 저장하고 완료 모달 문구를 분기한다.

전화번호:

> 입력한 전화번호로 작가님이 고객님께<br>
> 메시지를 보냅니다.

카카오톡:

> 입력한 카톡 아이디로 작가님이 고객님께<br>
> 카톡 메시지를 보냅니다.

완료 후 안내 단계는 다음 두 개만 노출한다.

1. 보통 1시간 내 연락드려요
2. 채팅에서 일정·컨셉을 협의해요

관련 코드:

- `src/app/(user)/inquiry/InquiryChat.tsx`
- `src/app/(user)/inquiry/loading.tsx`
- `src/app/(user)/inquiry/page.tsx`

## 4. 사진 상세 화면

### 4.1 상단 정보 위계

사진 아래 정보는 다음 두 행으로 구성한다.

| 위치 | 왼쪽 | 오른쪽 |
|---|---|---|
| 첫 번째 행 | 공유·담기 | 촬영 시간 · 보정본 수 |
| 두 번째 행 | 사매 파트너 작가 | 가격 |

- 촬영 시간·보정본은 테마 전경색(`text-fg`)을 사용한다. 다크 모드에서는 밝은 글자, 라이트 모드에서는 어두운 글자로 표시된다.
- 촬영 장소는 상단 요약에서 제거하고 펼친 패키지 정보 안에서만 노출한다.
- 파트너 뱃지가 왼쪽에 배치되므로 팝오버가 오른쪽으로 펼쳐지도록 정렬 옵션을 추가했다.

### 4.2 작가·패키지 정보 카드

기존 `작가 · 상세 정보` 텍스트 행을 다음 구조의 접이식 카드로 교체했다.

- 보조 문구: `이 사진에 관심있나요?`
- 제목: `작가 · 패키지 정보`
- 작가 홈 카드
  - `이 촬영을 진행하는`
  - `작가 홈 가기`
- 패키지 정보 카드
  - 패키지명
  - 가격
  - 촬영 시간
  - 제공 보정본
  - 촬영 장소
  - 패키지의 저장된 설명
- 협의 안내
  - `패키지 제공 내용(시간, 장소 등)은 작가님께 문의하면 협의할 수 있어요.`
- 하단 설명 라벨
  - `패키지 설명`

패키지 연결은 사진 가격과 가장 가까운 활성 패키지를 기준으로 한다. 정확히 같은 가격이 있으면 해당 패키지가 선택되고, 패키지가 없으면 제공 가능한 필드만 노출한다.

### 4.3 CTA 모서리

- 사진 상세 `무료로 견적 받아보기`: 아래 `작가 · 패키지 정보` 카드와 동일한 인라인 `border-radius: 16px` 적용
  - 공통 버튼 크기 클래스와 개별 radius 유틸리티가 동시에 존재할 때 CSS 생성 순서로 공통 radius가 우선하던 문제를 피하기 위해 인라인 값으로 고정했다.
- 패키지 협의 안내 카드: `rounded-lg`
- 작가 상세 `예약·문의하기`: 로그인·비로그인 모두 `rounded-lg`

## 5. 데이터·서버 영향

- DB 마이그레이션 없음
- API 계약 변경 없음
- 문의 서버 액션의 기존 이메일 필드 유지
- 사진과 패키지 연결 규칙 변경 없음
- Mixpanel 및 Meta Lead 이벤트 지점 변경 없음
- 모든 변경은 사용자 UI, 클라이언트 상태 및 표시 순서에 한정

## 6. 확인 항목

- 탐색 캐러셀 첫 화면에서 왼쪽에 마지막 카테고리가 보이는지
- 캐러셀 마지막↔첫 번째 양방향 전환이 순간 역주행 없이 이어지는지
- 탐색 탭 클릭 및 스크롤 활성 순서가 실제 섹션 순서와 일치하는지
- 문의 첫 진입 시 첫 메시지가 본문 상단에서 시작하는지
- 세로 사진이 문의 화면 높이를 과도하게 차지하지 않는지
- 전화번호·카카오톡 제출 후 완료 문구가 선택 채널과 일치하는지
- 사진 상세의 상단 장소가 제거되고 펼침 카드 안에는 장소가 남아 있는지
- 패키지가 없는 사진에서도 빈 값 때문에 레이아웃이 깨지지 않는지
- 다크·라이트 모드에서 촬영 조건과 패키지 정보 대비가 충분한지
- 파트너 뱃지 팝오버가 모바일 화면 밖으로 잘리지 않는지

작성 시점 확인:

- 변경 컴포넌트 중심 ESLint 및 `git diff --check` 통과
- 기존 전체 파일 검사 이슈는 별도 유지: 탐색 페이지의 랜덤 썸네일(`Math.random`) 순수성 규칙, 문의 `Reveal`의 effect 내 상태 갱신 규칙
- 로컬 `/explore`, `/inquiry`, `/photos/[id]` HTTP 200 및 개발 서버 컴파일 확인
- `dev` 브랜치에 커밋·push하며 PR 생성과 서비스 배포는 별도로 진행
