1.2

주력 동선 — 리드 언락

현재 매출 동선은 예약·에스크로가 아니라 리드 언락이다. 작가에게 브리프와 신청 사진은 그대로 보여주고 연락처만 잠근다. 리드의 가치를 먼저 보게 하고, 해제에 과금한다.

2.1

AI 활용 전략 — 자산 3층

AI는 세 층으로 나뉘어 있고, 각 층이 언제 돌아가는지가 서로 다르다. 이 “언제”가 비용 구조와 응답 속도를 결정한다.

층모델실행 시점소비처상태
1 · 언어/비전 Claude (2단계) 사용자가 시작한 이벤트 페르소나 이벤트 → 목적·무드 → 홈 피드 개인화 가동
2 · 이미지 임베딩 SigLIP2 naflex 오프라인 배치 사진 상세 유사 추천 · 홈 클릭 기반 개인화 가동
3 · 파생 태그 SigLIP 텍스트 타워 오프라인 배치 (임베딩 재사용) 미연결 — 처방할 증상이 실측되지 않음 보류

2.2

유지할 설계 원칙

  1. 조회 시점 추론 0사용자가 화면을 여는 경로에는 어떤 모델도 돌지 않는다. 추론은 오프라인 배치이거나, 사용자가 명시적으로 시작한 이벤트일 때만 발생한다. 응답 지연과 GPU 상시 비용이 구조적으로 0이 된다.
  2. LLM 출력은 신뢰하지 않고 검증한다스키마는 Zod로, 값은 서버측 화이트리스트로 이중 검증한다. 모델이 없는 카테고리를 지어내도 화면까지 도달하지 못한다.
  3. durable 산출물과 파생물을 분리한다임베딩은 durable(재계산이 비쌈), 태그는 파생물(어휘만 바뀌면 저렴). 그래서 어휘를 바꿔도 사진을 다시 내려받지 않는다.
  4. 실측되지 않은 증상은 처방하지 않는다자동 무드 태그를 만들어놓고 연결하지 않은 것은 미완성이 아니라 판단이다. 지표 없이 붙인 AI 기능은 되돌리기 어려운 부채가 된다.
  5. 배치 스크립트는 사고를 구조적으로 못 내게 만든다dry-run 기본 · --apply 명시 필요 · update는 항상 id 단건 · 건드리는 컬럼 3개 고정. service_role이 RLS를 우회하는 위험을 이 규칙들이 감싼다.
2.3

비용 구조

AI 비용은 사용자 수가 아니라 이벤트 참여 수에 비례한다. 피드와 추천은 트래픽이 늘어도 AI 비용이 증가하지 않는다.

항목과금특징
이미지 임베딩 · 자동 태그0원오픈 웨이트 로컬 실행. 공개 사진 약 1,800장 전량 백필이 수 분
벡터 근접검색Supabase 포함조회당 추가 과금 없음
페르소나 이벤트Anthropic + Apify유일한 가변비. 1회 = Stage1(이미지 포함) + Stage2
참고 단가 (per MTok)입력출력용처 후보
Claude Opus 5$5$25Stage1 — 이미지 포함 심리 추론
Claude Sonnet 5$3$15Stage2 — 카탈로그 내 매핑

1회 실비는 count_tokens로 실측한 뒤 확정한다. 현재는 두 단계 모두 같은 모델을 쓰고 있어, 단계별 분리만으로도 절감 여지가 있다.

2.4

로드맵

단기 — 이미 아는 결함부터 (0~1개월)

#과제내용
S1모델 기본값 갱신기본값이 claude-opus-4-8. Opus 5로 이관하되, Opus 5는 thinking이 기본 on이고 disabled는 effort ≤ high에서만 허용되므로 현재 조합을 함께 점검
S2단계별 모델 분리Stage1은 상위 모델, Stage2는 Sonnet 5 / Haiku 4.5 후보로 A/B — 품질 손실 없는 지점 탐색
S3취향 ‘목적’ 축 재배선커플 판정 사용자에게 웨딩 사진이 55% 섞인다. 탐색 슬러그가 아니라 타겟 멤버십을 보도록 고치고, 슬러그 드리프트 경고를 남긴다
S4임베딩 백필 자동화신규 사진이 수동 배치 전까지 추천 후보에서 빠진다. 업로드 훅 또는 크론 스윕 — 현재 유일한 운영 수동 개입

중기 — 기존 자산 재활용 (1~3개월)

#과제방식
M1검색 벡터화이미 쓰고 있는 SigLIP 텍스트 타워로 같은 공간에 검색어를 태운다. 신규 모델·추가 비용 0
M2자동 무드 태그 연결원칙 4에 따라 먼저 측정 — “태그 미부착 사진의 노출 결손”을 수치화한 뒤에만 연결
M3문의 브리프 정규화자유서술 메모를 구조화해 작가 카드 가독성과 언락 전환 개선. 접수당 1회 호출이라 비용 예측 가능
M4작가↔리드 적합도작가 포트폴리오 임베딩 평균 vs 신청 사진 임베딩 코사인 → 운영 배분 보조. 추론 없이 벡터 연산만

장기 — 데이터가 쌓인 뒤에만 (3개월+)

#과제전제 조건
L1클릭·언락 로그 기반 학습형 랭킹현재 개인화는 세션 한정(최근 8장). 계정 단위 장기 취향 프로필은 의도적으로 미적용 — 로그량 확보가 선결
L2리드 가격 최적화언락 전환율 · 작가 유형별 데이터 축적 후
L3자동 큐레이션 제안편집형 큐레이션의 운영 부하가 실제 병목이 된 뒤

리스크와 가드레일

리스크현재 방어보강
환각 없는 카테고리 · 과장된 심리 단정화이트리스트 필터 + 확신 차등 규칙 + 부정 프레이밍 금지 프롬프트결과 샘플 정기 리뷰

한 문장 요약

samae의 AI는 “조회 경로에서는 절대 추론하지 않는다”는 하나의 규칙 위에 서 있다. 무거운 계산은 오프라인 배치로 밀어 벡터로 저장하고, 언어 모델은 사용자가 직접 시작한 이벤트에서만 돌리며, 그 출력은 반드시 서버가 검증한 뒤에야 화면에 도달한다. 그래서 사용자가 늘어도 AI 비용은 늘지 않고, 모델이 틀려도 화면은 깨지지 않는다.
