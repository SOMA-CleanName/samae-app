# 관심사진 기반 유사사진 진입 및 탐색

## 1. 목표

현재 관심사진 펼침 화면의 카드 배치, 상단 제목, 선택 기능과 개별 사진 상세 흐름은 그대로 유지한다. 사용자가 **현재 관심사진을 4장 이상** 담았을 때만 화면 오른쪽에 유사사진 진입 버튼을 추가한다.

관심사진을 홈 피드 개인화 신호로 사용하는 기존 기능은 유지한다. 이번 기능은 사용자가 관심사진 화면에서 의도적으로 여는 별도 추천 탐색면을 추가하는 작업이다.

## 2. 확정한 화면 동작

### 진입 버튼

- 관심사진 펼침 화면에서만 표시한다.
- 현재 관심사진이 4장 이상일 때 표시하고, 3장 이하이면 렌더링하지 않는다.
- 최초에는 오른쪽에서 펼쳐진 둥근 패널로 나타난다.
- 표시 문구는 `관심사진과 비슷한 사진 보기`만 사용한다.
- `취향 기반 추천` 보조 문구는 표시하지 않는다.
- 펼쳐진 상태를 약 2.3초간 유지한 뒤 오른쪽으로 접혀 원형 추천 아이콘만 남는다.
- 접히는 동안 문구와 화살표는 페이드아웃하고 아이콘 위치는 흔들리지 않는다.
- 한 번 접힌 뒤에는 사용자가 관심사진 화면을 닫을 때까지 아이콘 상태를 유지한다.
- 관심사진 화면을 다시 열면 발견 가능성을 위해 2.3초 안내를 다시 재생한다.
- `prefers-reduced-motion: reduce`에서는 슬라이드 이동 없이 문구가 사라지고 아이콘만 남는다.
- 선택 모드와 개별 사진 확대 상태에서는 버튼을 숨겨 기존 조작과 겹치지 않게 한다.

### 버튼을 눌렀을 때

- 기존 오버레이 안에서 `비슷한 사진` 모드로 전환한다.
- 상단 제목은 `비슷한 사진`, 그 아래 실제로 보이는 추천 장수를 표기한다. 왼쪽 뒤로 버튼은 관심사진 목록으로 돌아간다.
- 관심사진과 추천사진을 한 화면에 섞지 않는다.

**앵커별 가로 스크롤 줄로 배치한다.** 관심사진의 폴라로이드 배치를 재사용하지 않는다(§10 개정 참조).

- 줄 하나 = 앵커 하나. 줄 왼쪽 머리에 **사용자가 담은 그 사진**의 썸네일과 `이 사진과 비슷한` 문구를 붙인다. 줄별 장수는 표기하지 않는다.
- 줄 안은 가로 스크롤이며 세로로 쌓지 않는다. 관심 없는 줄은 지나칠 수 있어야 한다.
- 카드에는 회전을 주지 않는다. 훑어보고 비교하는 화면이므로 기울기는 방해가 된다.
- 카드는 **높이 150px 고정, 폭은 비율대로** 늘린다. 폭을 고정하면 가로 사진이 납작해져 세로 사진보다 작게 보인다. 필름 스트립처럼 높이를 맞추면 가로 사진이 면적을 회복하고 줄의 아래위 선도 가지런해진다. 폭은 84~260px 로 제한해 파노라마가 줄을 독차지하거나 극단적 세로가 실오라기처럼 얇아지는 것만 막는다.
- 줄 오른쪽 끝에 **검은 페이드**를 덮어 더 있다는 것을 알린다. 넘길 것이 없거나 끝에 닿으면 지운다 — 없는 콘텐츠를 약속하지 않는다.

**카드를 누르면 사진이 크게 보인다.**

- 탭의 기본 동작은 상세 이동이 아니라 **확대**다. 화면 높이의 64% 이내로 띄우고, 우상단 `✕`·빈 영역 탭·`ESC` 로 닫는다.
- 확대 화면의 액션은 `관심사진에 담기` 하나다. 담으면 `담았어요` 로 바뀐다.
- 관심사진 확대(`FloatingCart` 의 `focused`)와 같은 시각 언어를 쓰되 구현은 분리한다. 기존 확대는 폴라로이드 절대배치 카드에 transform 을 걸어 확대하는 방식이라 줄 카드에 그대로 붙지 않는다.

**카드에서 바로 담을 수 있다.**

- 카드 우상단 `+` 를 누르면 **확대를 거치지 않고** 관심사진에 담는다. 이미 담긴 사진은 `✓` 로 표시하고 다시 눌러도 중복 담기지 않는다.
- 담기 모션은 기존 장바구니 흡입 애니메이션([17 UI 개편](17-ui-overhaul.md) B3)을 그대로 쓴다.

**이 화면에서 사진 상세로 나가는 경로는 두지 않는다.**

- 오버레이는 클라이언트 상태라 브라우저 히스토리에 남지 않는다. 상세로 나갔다 뒤로 오면 **오버레이가 닫힌 홈으로 떨어져** 보던 자리를 통째로 잃는다.
- 상세는 관심사진에 담은 뒤 그쪽 화면에서 연다.
- 카드 탭과 확대 오버레이는 `stopPropagation()` 으로 전파를 끊는다. `FloatingCart` 의 카드 레이어가 빈 영역 탭을 '오버레이 닫기'로 처리하므로(`layerClick` → `dismissOverlay`), 끊지 않으면 카드 탭이 닫기로 먹힌다.

**하단 안내 문구는 `마음에 드는 사진을 담아보세요` 를 쓴다.** 이 화면의 목적이 담기이므로 상담이 열린다고 약속하지 않는다.

## 3. 추천 기준

- 추천 앵커는 현재 관심사진 ID만 사용한다. 30초 이후 관심목록에서 제거됐지만 추천 이력에 남아 있는 과거 ID는 이 전용 화면의 앵커로 사용하지 않는다.
- 최근에 담은 관심사진을 우선하며 최대 4개의 고유 ID를 앵커로 사용한다.
- 임베딩 유사도, 노출 낮춤 승격, 방향 다양성 보정 정책은 홈 피드와 동일하게 재사용한다.
- **앵커별 결과를 합치지 않는다.** 홈 피드는 한 줄로 흘러가므로 라운드로빈으로 섞는 것이 맞지만, 이 화면은 "무엇과 비슷한지"를 보여줘야 한다(§10).
- 클릭 이력은 이 전용 화면의 앵커 가중치에 합산하지 않는다. 사용자가 현재 담아둔 사진과 비슷한 결과라는 의미를 명확히 유지한다.
- 현재 관심사진 ID는 결과에서 제외한다.
- **줄 사이 중복도 제거한다.** 앵커들이 서로 비슷하면 같은 사진이 여러 줄에 걸릴 수 있다. 앞선 줄이 우선권을 갖는다.
- **결과가 0장이 된 줄은 내보내지 않는다.** 담은 사진 썸네일만 덩그러니 남으면 오해를 준다.
- 줄당 최대 100장을 가져온다. 앵커 4개면 최대 400장이며, 후보가 부족하면 가능한 수만 표시한다.
- 상단 장수 표기는 **중복 제거 후 실제로 보이는 카드 수**를 쓴다. 표시와 내용이 어긋나지 않게 한다. 줄별 장수는 표기하지 않는다.
- 추천 카드를 통해 상세로 이동하면 기존 클릭 기록 정책에 따라 이후 홈 피드 개인화에는 반영된다.
- 카드에서 바로 담으면 관심사진 조합이 바뀌므로, 다음 진입 시 추천이 다시 조회된다(§4 캐시 규칙).

## 4. 데이터 흐름과 구성요소

1. `CartProvider`가 제공하는 현재 `items`를 기준으로 진입 가능 여부를 계산한다.
2. `FloatingCart`는 관심사진 펼침 단계에서 `items.length >= 4`일 때 추천 진입 버튼을 표시한다.
3. 사용자가 버튼을 누르면 서버 액션 `loadInterestSimilarGroups(interestIds)`에 현재 관심사진 ID를 전달한다.
4. 서버 액션은 `fetchInterestSimilarGroups(interestIds, 100)`를 호출해 **`{ anchor, photos }[]`** 를 받는다.
   앵커 4개 + 사진 400장이면 id 가 400개를 넘는다. PostgREST 는 이 목록을 URL 쿼리로 보내므로 한 번에 조회하면 URL 길이 제한에 걸린다 → **150개씩 나눠 병렬 조회**한다(`fetchPhotosByIdsChunked`).
5. `toInterestRecommendationRows`가 이를 줄 모델로 바꾸고(줄 사이 중복 제거·빈 줄 제거), `InterestSimilarRows`가 렌더한다.
6. 관심사진 카드 배열과 추천 줄 배열은 상태를 분리한다. 추천 조회나 전환이 기존 장바구니 저장값과 순서를 바꾸지 않는다.
7. 추천 모드에서는 폴라로이드 배치 계산을 아예 거치지 않는다. 관심사진 카드는 `hidden` 으로 남겨두므로 뒤로 갈 때 위치와 배열이 그대로 복귀한다.
8. 카드의 `+` 는 `CartProvider.add(item, sourceEl)`를 호출한다. `sourceEl`은 그 카드의 프레임이며 흡입 모션의 출발점이 된다.
9. 확대 상태는 `InterestSimilarRows` 안의 지역 상태다. 오버레이를 닫거나 줄로 돌아오면 사라진다.

추천 화면 상태는 `idle | loading | ready | error`로 관리한다. 동일한 관심사진 ID 조합으로 다시 열 때는 현재 오버레이 생명주기 안에서 결과를 재사용한다. 관심사진 구성이 바뀌면 이전 추천 결과를 폐기하고 다음 진입 시 다시 조회한다.

## 5. 예외 처리

- 조회 중에는 오른쪽 진입 아이콘에 작은 로딩 표시를 적용하고 중복 요청을 막는다.
- 조회 실패 시 관심사진 화면은 그대로 유지하고 `비슷한 사진을 불러오지 못했어요` 안내와 재시도 동작을 제공한다.
- 결과가 없으면 `아직 보여드릴 비슷한 사진이 없어요`를 표시하고 관심사진으로 돌아갈 수 있게 한다.
- 조회 중 관심사진이 3장 이하로 줄면 완료 결과를 표시하지 않고 추천 모드를 닫는다.
- 추천 사진이 비공개·삭제 상태로 바뀌어 서버에서 제외되면 나머지 유효 사진만 표시한다.

## 6. 접근성과 분석

- 펼쳐진 버튼과 접힌 아이콘은 모두 `button`을 사용하고 접근성 이름을 `관심사진과 비슷한 사진 보기`로 유지한다.
- 키보드 포커스와 터치 영역은 접힌 상태에서도 최소 44px을 확보한다.
- 추천 화면의 뒤로 버튼에는 `관심사진으로 돌아가기` 접근성 이름을 사용한다.
- 각 줄은 `section` 이며 `담은 사진과 비슷한 사진` 이라는 접근성 이름을 갖는다. 줄 머리 썸네일의 대체 텍스트는 `담은 사진` 이다.
- 카드 담기 버튼은 `관심사진에 담기`(담긴 뒤 `이미 담긴 사진`) 이름과 `aria-pressed` 로 상태를 알린다.
- 카드 본체 버튼의 접근성 이름은 `사진 크게 보기` 다. 확대 화면은 `role="dialog"` · `aria-modal` 이며 `ESC` 로 닫힌다.
- 다음 이벤트를 기록한다.
  - 추천 진입 버튼 노출
  - 추천 진입 버튼 클릭
  - 추천 결과 수(`result_count`)·줄 수(`anchor_count`)와 로딩 성공·실패
  - 추천 카드 클릭

## 7. 검증 기준

### 순수 로직

- 관심사진 3장에서는 진입 불가, 4장부터 진입 가능
- 최근 관심사진 최대 4개 앵커 선택
- 현재 관심사진과 중복 추천 제외
- 앵커마다 별도의 줄로 분리 (한 화면에서 앵커가 섞이지 않음)
- 앞선 줄에 나온 사진이 뒤 줄에서 반복되지 않음
- 앞선 줄에 전부 선점된 줄은 제거
- 줄마다 `seq` 가 0부터 다시 시작
- 상단 장수 표기 = 실제로 보이는 카드 수의 합
- 관심사진 조합 변경 시 추천 캐시 무효화

### 컴포넌트 동작

- 펼친 버튼이 약 2.3초 뒤 아이콘으로 접힘
- 보조 문구 `취향 기반 추천`이 렌더링되지 않음
- 선택 모드·개별 사진 확대 상태에서 버튼 숨김
- 접힌 아이콘 클릭 시 추천 화면 전환
- 줄 머리에 담은 사진 썸네일과 `이 사진과 비슷한` 문구가 표시됨
- 카드 `+` 로 화면을 떠나지 않고 담기며, 담긴 카드는 `✓` 로 바뀜
- 카드 탭이 확대로 열리고 `✕`·빈 영역·`ESC` 로 닫힘
- 추천 화면 어디에도 `/photos/` 로 나가는 경로가 없음
- 줄이 넘칠 때만 오른쪽 페이드가 보이고 끝에 닿으면 사라짐
- 가로 사진과 세로 사진의 카드 높이가 같음
- 하단 안내 문구가 `마음에 드는 사진을 담아보세요`
- 추천 화면 뒤로 가기 시 기존 관심사진 위치와 배열 복원
- 4장 미만으로 줄면 버튼과 추천 화면 종료
- 로딩·빈 결과·오류·재시도 상태 표시
- 모션 감소 환경에서 위치 이동 제거

### 회귀 검증

- 관심사진 담기·삭제·전체 삭제
- 30초 관심 취소에 따른 홈 피드 개인화 신호 처리
- 관심사진 상세의 위·아래 순환 탐색
- 관심사진 가격·장소 협의 문구
- 홈 피드 무한 스크롤과 기존 유사사진 삽입

## 8. 제외 범위

- 추천 사진을 기존 관심사진 사이에 자동 삽입하지 않는다.
- 추천 화면에 별도의 필터·정렬·새로고침 버튼을 추가하지 않는다.
- 추천 결과를 로컬 저장소에 영구 저장하지 않는다.
- 임베딩 생성 방식과 데이터베이스 RPC를 변경하지 않는다.

## 10. 개정 — 앵커별 줄 배치·카드 담기·문구 (2026-08-17)

초기 구현(§9)을 로컬에서 확인한 결과 화면이 의도대로 읽히지 않았다. 원인과 결정을 남긴다.

### 무엇이 문제였나

**결과가 하나의 무드로 읽히지 않았다.** `fetchPersonalizedRecommendations` 는 앵커 4개의 이웃을 라운드로빈으로 섞어 한 배열로 돌려준다. 홈 피드는 한 줄로 흘러가므로 그것이 맞지만, 이 화면에서는 하얀 침실 사진과 사이버펑크 사진이 나란히 놓였다. 제목이 `비슷한 사진 · 36장` 으로 **한 덩어리처럼 약속하고 네 덩어리를 주는** 상태였다.

개별 카드는 정확했다. 문제는 후보 계산이 아니라 **묶는 방식**이었다.

**탭하면 화면 밖으로 나갔다.** 추천 카드의 유일한 동작이 상세 이동이라, 한 장 담으려면 오버레이를 닫고 나갔다 돌아와야 했다. 이 버튼을 누른 사용자는 탐색 중인데 그 흐름이 매번 끊겼다.

**하단 문구가 사실과 달랐다.** `사진을 탭하면 상담을 신청할 수 있어요` 라고 안내했지만 실제 동작은 상세 이동이었다.

### 무엇을 바꿨나

| | 이전 | 이후 |
|---|---|---|
| 배치 | 폴라로이드 흩뿌리기(관심사진 화면 재사용) | **앵커별 가로 스크롤 줄** |
| 근거 제시 | 없음 | 줄 머리에 **담은 사진 썸네일** |
| 서버 반환 | `GalleryPhoto[]` (합집합) | `{ anchor, photos }[]` |
| 조회량 | 전체 최대 36장 | 줄당 최대 12장 |
| 카드 동작 | 상세 이동만 | 상세 이동 + **담기(`+`)** |
| 하단 문구 | 상담을 약속 | `마음에 드는 사진을 담아보세요` |

폴라로이드를 재사용하지 않기로 한 근거는 **두 화면의 일이 다르다**는 것이다. 관심사진은 사용자가 직접 고른 것이라 애착의 대상이고 흩뿌린 폴라로이드가 그 정서를 살린다. 추천 화면은 훑어보고 고르는 곳이라 비교가 쉬워야 한다. 기울어진 카드는 비교를 방해하고, 폴라로이드 흰 테두리가 카드 면적의 20% 가까이를 차지해 사진이 작아진다.

담기 버튼은 **루프를 만들기 위한 것**이다. 담을수록 앵커가 갱신되어 추천이 정확해지고, 그래서 또 담게 된다. 모션은 [17 UI 개편](17-ui-overhaul.md) B3의 장바구니 흡입 애니메이션을 그대로 쓴다.

### 함께 정리한 규칙

앵커별로 나누면 새 경계 조건이 생긴다. 전부 테스트로 고정했다.

- 앵커들이 서로 비슷하면 같은 사진이 여러 줄에 걸린다 → 앞선 줄이 우선권을 갖고 뒤 줄에서 제거
- 그 결과 어떤 줄은 0장이 된다 → 그 줄은 내보내지 않는다. 담은 사진 썸네일만 남으면 오해를 준다
- 상단 장수는 중복 제거 후 실제로 보이는 카드 수를 쓴다

### 반영 파일

- `src/lib/discovery.ts` — `fetchInterestSimilarGroups`. 후보 계산은 홈 피드와 같고 **합치지 않는다**
- `src/lib/interest-similar-recommendations.ts` — `toInterestRecommendationRows`, `countInterestRecommendationCards`

- `src/components/user/cart/FloatingCart.tsx` — 추천 모드에서 폴라로이드 배치를 거치지 않고 줄 컴포넌트로 분기. 문구 수정

## 11. 2차 개정 — 조회량·확대 보기·이탈 경로 차단 (2026-08-17)

§10 을 로컬에서 다시 확인하며 정한 것들이다.

| | 이전 | 이후 | 이유 |
|---|---|---|---|
| 줄당 조회량 | 12장 | **100장** (총 400장) | 훑는 화면인데 금방 끝났다 |
| 카드 탭 | 상세 이동 | **확대 보기** | 상세로 나가면 자리를 잃는다(아래) |
| 상세 이동 | 확대 화면에 버튼 | **경로 없음** | 아래 참조 |
| 줄 머리 장수 | `100장` 표기 | **표기 없음** | 줄마다 같은 숫자라 정보가 없다 |
| 카드 크기 | 폭 104px 고정 | **높이 150px 고정** | 가로 사진이 납작해져 작게 보였다 |
| 줄 끝 | 표시 없음 | **검은 페이드** | 더 있다는 것을 알린다 |

### 상세로 나가는 경로를 없앤 이유

재현된 경로다.

```
비슷한 사진 → 사진 탭(확대) → 촬영 정보 보기 → /photos/{id}
                                                  ↓ 브라우저 뒤로
                                    홈(/) · 오버레이 닫힘 · 400장 보던 자리 상실
```

오버레이는 클라이언트 상태라 히스토리에 남지 않는다. **돌아올 지점이 없어서** 뒤로가기가 홈으로 떨어진다. 헤더 `‹` 뒤로가기는 정상이었고(관심사진으로 복귀), 원인은 사진에서 나가는 경로 하나였다.

### 400장을 조회하며 드러난 것

id 400개를 한 번에 `.in()` 으로 조회하면 **PostgREST 가 URL 쿼리로 보내 길이 제한에 걸린다**(400 × 37자 ≈ 15KB). 12장일 때는 드러나지 않던 문제다. 150개씩 나눠 병렬 조회한다.

### 잡은 버그

확대가 열리지 않았다. `FloatingCart` 의 카드 레이어가 빈 영역 탭을 오버레이 닫기로 처리하는데(`layerClick` → `dismissOverlay`), 카드 탭이 거기까지 전파돼 오버레이가 통째로 닫혔다. 카드 버튼과 확대 오버레이에서 `stopPropagation()` 으로 끊었다. **주석을 지우면 같은 증상이 재발한다.**
