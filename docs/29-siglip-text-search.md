# 29. SigLIP2 검색어 기반 사진 검색 (2026-08-25)

> 문서 상태: 로컬 코드·HTTP 통합 검증 완료 · 화면 수동 확인 필요 · 배포 전
>
> 작업 브랜치: `dev`

## 1. 목표

사용자가 홈 검색창에 자연어를 입력하면 SigLIP2가 검색어를 텍스트 임베딩으로 변환하고, 기존 사진 임베딩과 가까운 공개 사진을 보여준다.

기본 결과는 **SigLIP2 텍스트→이미지 유사도순**을 사용한다. 다만 사진 태그·앨범 제목·앨범 설명처럼 사진과 직접 연결된 메타데이터가 검색어 원문에 일치하면 해당 사진을 먼저 보여주고, 나머지는 SigLIP2 거리순을 유지한다.

## 2. 확정 범위

- 모델은 현재 사진 임베딩과 같은 `google/siglip2-so400m-patch16-naflex`를 사용한다.
- 검색창은 홈 히어로 바로 아래와 검색 결과 상단에만 노출한다.
- 검색어는 `/?q=<검색어>`로 유지해 새로고침·공유·뒤로가기를 지원한다.
- 문자열 점수와 벡터 거리를 수치로 가중합하지 않는다. 직접 일치 사진을 앞에 두고 SigLIP2 결과를 중복 없이 이어 붙인다.
- RRF, 패키지명·패키지 설명 검색, 검색 필터 UI, 검색 자동완성은 이번 범위에서 제외한다.
- 검색 로그는 기존 `search_logs` 경로를 유지한다.

## 3. 데이터 흐름

```text
검색창 제출
  → Next.js 서버에서 두 검색을 병렬 실행
    → 사진 태그·숨김 태그·앨범 제목·설명·장소·작가 메타데이터 직접 일치
    → 맥미니 POST /embed-text → SigLIP2 1152차원 벡터 → similar_photos_by_vector
  → 직접 일치 사진을 먼저 배치하고 중복 제거
  → 나머지는 SigLIP2 코사인 거리 오름차순을 보존
  → 홈 메이슨리 그리드에 표시
```

텍스트와 사진은 동일한 SigLIP2 임베딩 공간에 놓인다. 사진 임베딩의 모델·차원과 검색어 임베딩의 모델·차원이 다르면 비교하지 않고 실패 처리한다.

## 4. 구성요소

### 4.1 맥미니 텍스트 임베딩 API

`scripts/embed/serve.py`에 `POST /embed-text`를 추가한다.

요청:

```json
{ "texts": ["푸른 숲속 커플 사진"] }
```

응답:

```json
{
  "vectors": [[0.01, -0.02]],
  "count": 1,
  "infer_ms": 12,
  "model": "google/siglip2-so400m-patch16-naflex"
}
```

- 기존 `PERSONA_SERVICE_TOKEN` 인증을 그대로 사용한다.
- 공백 제거 후 1~120자만 허용한다.
- 한 요청의 검색어는 최대 8개로 제한한다.
- 기존 상주 SigLIP2 모델을 재사용하고 별도 모델을 띄우지 않는다.

### 4.2 앱 서버 클라이언트

`src/lib`의 서버 전용 모듈이 `/embed-text`를 호출한다.

- 브라우저가 맥미니 주소나 서비스 토큰을 직접 알지 못하게 한다.
- 응답 벡터가 1152차원인지 검증한다.
- 연결 실패·타임아웃·잘못된 응답은 예외를 사용자 화면까지 전파하지 않고 빈 결과로 처리한다.
- 검색어의 원문은 서버 로그에 남기지 않는다. 기존 집계용 `search_logs`만 사용한다.

### 4.3 벡터 검색

기존 `similar_photos_by_vector(halfvec, integer)` RPC를 서버의 service role로 호출한다.

- 최대 300개를 요청하고 코사인 거리 오름차순을 끝까지 보존한다.
- RPC 반환 순서인 코사인 거리 오름차순을 그대로 사용한다.
- 앱에서 `GalleryPhoto`에 필요한 작가·가격·지역 메타데이터를 사진 ID로 다시 조회한다.
- 비공개 사진, 미승인 작가, `feed_hidden=true` 사진은 최종 결과에서 제외한다.
- 결과가 부족하더라도 이번 검증 버전에서는 무관한 일반 사진을 뒤에 붙이지 않는다.

## 5. DB 변경 여부

첫 버전은 신규 테이블·컬럼·인덱스·함수를 만들지 않는다.

재사용 대상:

- `photos.embedding halfvec(1152)`
- 사진 임베딩 HNSW 인덱스
- `similar_photos_by_vector` (`0079`)
- 기존 `search_logs`

구현 전에 운영 DB에 `similar_photos_by_vector`가 실제 배포되어 있는지만 읽기 전용으로 확인한다. 함수가 없거나 현재 앱의 노출 규칙을 안전하게 만족시키지 못해 DB 수정이 필요해지면 **마이그레이션을 적용하지 않고 사용자에게 먼저 알린다.**

## 6. UI

### 홈

`FeedHero` 아래, 사진 피드 위에 둥근 검색창을 배치한다.

- 플레이스홀더: `원하는 사진 분위기를 검색해보세요`
- 예시 접근성 문구: `예: 푸른 숲속 커플, 비 오는 날 필름 감성`
- 검색 제출 시 `/?q=`로 이동한다.

### 검색 결과

- 홈 히어로는 숨기고 결과 상단에 같은 검색창을 표시한다.
- 입력값은 현재 `q`로 유지한다.
- 상위 결과를 48장씩 점진 노출하며, 하단 센티넬에 닿으면 다음 48장을 이어서 보여준다.
- 검색어별로 불러온 결과와 스크롤 위치를 세션에 유지하고 최대 300장에서 종료한다.
- 결과가 없으면 `다른 장면이나 분위기로 검색해보세요`를 표시한다.
- 검색어를 지우고 제출하면 `/`로 돌아간다.

## 7. 장애 처리

- 맥미니가 꺼졌거나 타임아웃이면 검색 결과를 비우고 재시도 안내를 표시한다.
- 이 검증 버전에서는 실패 시 기존 문자열 검색으로 자동 전환하지 않는다. 폴백 결과가 섞이면 SigLIP2 결과를 눈으로 평가하기 어렵기 때문이다.
- 홈 일반 피드와 사진 상세 유사도 추천은 검색 장애의 영향을 받지 않는다.

## 8. 검증

- `encode_text()`가 1152차원 정규화 벡터를 반환하는지 확인한다.
- `/embed-text` 인증·입력 제한·응답 형식을 테스트한다.
- 앱 클라이언트의 정상 응답·타임아웃·차원 불일치를 테스트한다.
- 벡터 RPC 결과가 공개 사진·승인 작가·`feed_hidden=false`만 노출하는지 확인한다.
- `웨딩`, `푸른 숲속 커플`, `어두운 실내 플래시 인물`, `바다에서 뛰는 사람` 등 대표 검색어로 결과를 눈으로 비교한다.
- 홈과 결과 화면의 모바일·데스크톱 배치, 뒤로가기, 검색어 유지, 빈 결과를 확인한다.

## 9. 배포 순서

1. 맥미니 런타임에 `/embed-text`를 먼저 반영한다.
2. 인증된 요청으로 모델명·벡터 차원·지연시간을 확인한다.
3. 운영 DB의 기존 `0079` RPC 존재 여부를 읽기 전용으로 확인한다.
4. 앱 검색 UI와 서버 검색 경로를 배포한다.
5. 검색 로그와 대표 검색어 결과를 확인한다.

앱 배포 전에 맥미니 API가 준비되어야 검색 화면이 빈 결과로 시작하지 않는다.

## 10. 구현·검증 결과 (2026-08-26)

- `dev`에서 `POST /embed-text`와 홈 검색 UI를 구현했다.
- 실제 응답 모델은 `google/siglip2-so400m-patch16-naflex`, 벡터 차원은 1152로 확인했다.
- 운영 DB의 기존 `similar_photos_by_vector` RPC가 정상 응답했다. **DB 마이그레이션은 만들거나 적용하지 않았다.**
- 워밍된 로컬 모델에서 대표 검색어 텍스트 임베딩은 26.2~94.5ms, RPC는 47.6~898.9ms였다.
- `푸른 숲속 커플 사진`, `어두운 실내 플래시 인물`, `바다에서 뛰는 사람` 세 검색어 모두 상위 8개 결과를 반환했다.
- 로컬 `http://localhost:3000/`과 검색 URL이 HTTP 200을 반환했고, 검색 결과 첫 화면에 48개 카드가 서버 렌더링됐다.
- 검색 후보 상한을 300장으로 확대하고, 기존 갤러리 센티넬을 이용해 48장 단위 무한 스크롤로 연결했다.
- 포트폴리오 메타데이터 직접 일치 결과를 SigLIP2 앞에 병합했다. 다단어 검색은 원문 단어를 모두 포함할 때만 승격해 일부 흔한 단어가 벡터 순서를 덮지 않게 했다.
- 운영 데이터에서 `만삭` 직접 일치 사진 6장이 검색 결과 0~5번에 배치되고, `푸른 숲속 커플 사진`은 기존 SigLIP 상위 8개 순서를 유지하는 것을 확인했다.
- Python 테스트 4개, Node 테스트 10개, TypeScript 검사와 프로덕션 빌드가 통과했다. 변경 파일 ESLint에도 오류가 없었다.
- 전체 저장소 ESLint에는 이번 변경과 무관한 기존 오류 21개가 남아 있다.
- 자동 브라우저 연결이 제공되지 않아 스크린샷·클릭 자동화는 실행하지 못했다. 3000 서버를 유지해 실제 화면을 수동 확인할 수 있다.
