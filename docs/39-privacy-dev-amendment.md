# 개인정보 처리방침 dev 개정안 — 미리 써 둔 것

작성 2026-09-04 · **발동 조건: 채팅 상주·에스크로 모델 배포(= PG 정식 출시)**
현행판 `src/app/privacy/page.tsx` (리드 언락 모델 기준) · 검토 근거 `docs/38-pg-model-legal-review.md` §2

---

## 0. 왜 고쳐야 하나

**현행 §3 이 dev 에서 거짓이 된다.**

> 서비스는 … 사진작가에게 상담 정보와 **연락처**를 제공합니다

dev 는 **연락처를 제공하지 않는다.** `platform-policy.ts` 도 봇에게 *"고객 연락처는
작가에게 공개되지 않는다"* 고 말하게 한다. 두 문서가 정반대를 말하는 상태로 배포하면,
그 자체가 **처리방침의 허위 기재**다.

그리고 **채팅이 서비스의 중심인데 수집 항목에 채팅이 없다.**

---

## 1. §1 수집 항목 — "채팅 상담" 신설

현행 배열(`COLLECTED`)에 아래 항목을 **촬영 문의 다음**에 넣는다.

```ts
{
  when: "채팅 상담",
  items:
    "대화 메시지의 내용, 첨부한 참고 이미지, 자동 응답 과정에서 수집된 상담 항목" +
    "(촬영 목적·희망 일시·희망 지역·인원 등), 읽음 여부와 시각",
},
```

↳ 실물 근거 — `messages`(`body` · `image_path` · `read_at` · `type`) ·
`conversations`(`bot_slots` · `source_photo_path` · `user_unread` · `last_message_at`)

**결제 항목도 함께 신설한다.**

```ts
{
  when: "예약과 결제",
  items:
    "예약 정보(일시·장소·인원·요청 사항), 결제 금액과 결제 상태, 거래 식별정보. " +
    "카드번호 등 결제수단 정보는 결제대행사가 처리하며 서비스는 보관하지 않습니다.",
},
```

⚠️ 마지막 문장은 **PG 계약 내용을 확인한 뒤에 쓸 것.** 가상계좌를 열면 입금자명 등이
서비스로 들어올 수 있다.

---

## 2. §2 이용 목적 — 한 줄 추가

```ts
"채팅 상담의 자동 응답과 작가 연결(자동화된 처리가 사용됩니다)",
```

↳ dev 의 상담봇은 LLM 이다. `docs/38` §8 — 봇 발언이 회사의 의사표시로 귀속될 수 있으므로
**자동화된 처리라는 사실을 방침에 남긴다.**

---

## 3. §3 제3자 제공 — 🔴 전면 교체

### 현행 (리드 모델)

> 서비스는 이용자의 촬영 상담·예약 연결을 위해, 이용자가 선택한(또는 매칭된)
> 사진작가에게 상담 정보와 **연락처**를 제공합니다.

### 개정안

> 서비스는 이용자의 촬영 상담·예약 연결을 위해 사진작가에게 아래 정보를 제공합니다.
>
> - 상담 정보 — 촬영 목적, 희망 일시, 희망 지역, 인원, 요청 사항, 첨부한 참고 이미지
> - 서비스 내 표시 이름
> - 채팅으로 주고받은 대화 내용
>
> **이용자의 전화번호·카카오톡 아이디·이메일 등 연락 수단은 사진작가에게 제공되지
> 않습니다.** 상담과 예약은 서비스 내 채팅에서 이루어집니다.
>
> 사진작가의 연락 수단은 예약이 확정된 이후, 작가가 전달을 선택하고 이용자가 안내를
> 확인해 동의한 경우에만 이용자에게 제공됩니다.
>
> 이 외의 목적으로는 이용자의 동의 없이 개인정보를 제3자에게 제공하지 않습니다. 다만
> 법령에 따라 수사기관 등이 적법한 절차로 요구하는 경우에는 관련 법령이 정한 범위에서
> 제공할 수 있습니다.

↳ **"대화 내용을 작가에게 제공한다"를 빠뜨리지 말 것.** 작가는 같은 방을 보고 있으므로
사실상 제공이다. 지금 방침은 그 사실을 적지 않았다.

## 4. §4 위탁 · §5 국외 이전 — 수탁자 추가

```ts
{ name: "<결제대행사 상호>", work: "결제 처리 및 대금 정산 대행", country: "대한민국" },
{ name: "<발송 대행사 상호>", work: "알림톡·문자 발송",           country: "대한민국" },
```

⚠️ 둘 다 **국내 사업자일 가능성이 높다.** 그러면 §5 국외 이전 목록에서는 빼고, §5 본문의
*"위 수탁자는 모두 국외에 소재한 사업자로"* 를 **"위 수탁자 중 일부는"** 으로 고쳐야 한다.
지금 문장은 전원이 국외라는 전제로 쓰여 있다.

## 5. §6 보유 기간 — 채팅·예약 추가

```ts
{ what: "채팅 대화와 첨부 이미지", how: "대화 종료 후 관계 법령이 정한 기간" },
{ what: "예약·결제 기록",         how: "거래 종료 후 관계 법령이 정한 기간" },
```

⚠️ **전자상거래법이 요구하는 보존 기간을 확인해 숫자로 적는 편이 낫다** `[verify]` —
계약·청약철회 기록 5년, 대금결제 기록 5년, 소비자 불만·분쟁 처리 기록 3년으로 알려져 있다.
숫자를 적으면 방침이 강해지지만, **적은 대로 지켜야 한다**(현행판에서 "로그 1년" 을
지운 이유와 같다 — `privacy/page.tsx` 의 `RETENTION` 주석 참고).

## 6. 함께 고쳐야 하는 것 — 네 곳이 같은 말을 한다

`docs/38` §1-C 에서 지적한 동기화 문제다. 연락처·환불 관련 문장이 네 파일에 흩어져 있다.

| 파일 | 무엇을 말하나 |
|---|---|
| `src/app/privacy/page.tsx` §3 | 작가에게 무엇을 제공하는가 |
| `src/lib/platform-policy.ts` | 봇이 고객에게 하는 설명 |
| `src/app/(user)/terms/page.tsx` | 약관 제10조의2(연락처 전달) |
| `docs/32-refund-policy.md` §3-3 | 환불 구간 설계 |

**한 커밋에서 함께 고칠 것.** 하나만 고치면 나머지 셋이 회사의 다른 약속으로 남는다.

---

## 7. 시행일

내용이 바뀌므로 `EFFECTIVE_DATE` 를 **정식 출시일**로 갱신한다.
처리방침은 약관과 달리 사전 공지 기간이 따로 요구되지 않지만, 이용자에게 불리한
변경이면 알리는 편이 안전하다. 이번 개정은 **연락처를 제공하지 않는 쪽**이라
이용자에게 유리하다.
