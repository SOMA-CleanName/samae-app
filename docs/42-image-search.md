# 42. 사진으로 검색 (카메라 버튼) — 구현 인계

> 문서 상태: **계획 (2026-09-21 작성, 2026-09-28 갱신).** 브랜치 `feat/image-search`.
> 코드는 검색창의 카메라 버튼 자리만 있다(`11e58fc`). 1단계부터 구현한다.
> 먼저 읽을 것: `CLAUDE.md`, [29 검색어 기반 사진 검색](29-siglip-text-search.md) §12, [38 맥미니 인계](38-macmini-search-handoff.md) §0.

## 0. 한 줄 요약

검색창 오른쪽 카메라 버튼을 누르면 **구글 렌즈와 같은 흐름**으로 사진을 올리고, **SigLIP 벡터만으로** 분위기가 비슷한
작가 사진을 보여준다. 모델·DB·결과 격자는 이미 있다 — 새로 만들 것은 대부분 화면과 API 하나다.

## 1. 따라갈 흐름 (Google Lens)

1. 카메라 버튼 → **PC**: 검색창 바로 아래로 패널이 펼쳐진다("이미지를 여기로 드래그하거나 **파일 업로드**").
   패널이 열린 동안 Ctrl+V 로 클립보드 이미지를 붙여 넣을 수 있다. **모바일**: 바로 OS 사진 고르기(카메라·갤러리)
2. 사진을 넣으면 패널에 잠깐 진행 표시 → 결과 화면
3. 결과 화면
   - 맨 위 검색창에 **올린 사진의 작은 썸네일 칩**. 칩 옆에 글을 더 쓸 수 있다(3단계). 칩의 X → 사진 검색 종료
   - 왼쪽(모바일은 위) 올린 사진 크게 + **선택 박스**(2단계). 오른쪽(모바일은 아래) 비슷한 사진 격자
4. 구글의 "정확히 일치"(같은 사진 찾기)와 "이미지 링크 붙여넣기"는 **하지 않는다** (§6)

## 3. 1단계 — 올리면 비슷한 사진이 나온다

**화면**
- 카메라 버튼 → PC 패널(끌어다 놓기 · 파일 선택 · Ctrl+V) / 모바일은 `<input type="file" accept="image/*">` 바로 열기
- 올리기 전 **브라우저에서 긴 변 512px JPEG 로 줄인다**(canvas). SigLIP 은 어차피 작게 보므로 결과는 같고 전송만 준다.
  줄인 뒤 약 100KB 안팎 — 서버액션 본문 한도(4MB, `next.config.ts`)와 Vercel 한도(~4.5MB)에 여유가 있다
- 결과 화면: 검색창에 썸네일 칩 + 기존 격자 재사용. 사진 원본은 **브라우저에만** 들고 있는다(objectURL)

**서버**
- 새 라우트(예: `POST /api/search/image`) 또는 서버액션: 이미지 형식(JPEG/PNG/WebP)·크기(줄인 뒤 1MB 이하) 검사
  → `/embed` 한 장 → 가까운 300장 → `loadPhotosInOrder` → `spreadAlbumsInBands` → 결과
- 맥미니 실패·타임아웃 → "사진 검색을 잠시 쓸 수 없어요" 안내(글 검색의 `SearchUnavailable` 톤). 결과 0장과 구분할 것
- 요청 제한: IP 기준 분당 몇 회(맥미니 보호)

**확인(완료 조건)**
- 작가 사진 한 장을 그대로 올리면 **그 사진이 1위**, 같은 앨범 사진이 상위권
- 결과에 비공개·피드에서 내린 사진·미승인 작가 사진이 없다
- 맥미니를 끄면 안내 문구가 뜨고 홈이 깨지지 않는다
- PC 끌어다 놓기·파일 선택·Ctrl+V, 모바일 사진 고르기가 모두 된다
- `npx tsc --noEmit`, `npx eslint`, 새 순수 함수는 `npx tsx --test` 테스트

## 4. 2단계 — 사진 일부만 (선택 박스)

- 결과 화면의 올린 사진 위에 선택 박스. 움직이면 **브라우저에서 잘라** 1단계 API 를 다시 부른다(서버 변경 없음)
- 처음 박스는 사진 전체

## 5. 3단계 — 사진 + 글

- 칩 옆 글은 기존 `/search-query`(형태소 분리)를 탄다: **목적은 필터**(글 검색과 같은 `photosForTags`), **무드는 글 벡터**
- 사진 벡터와 무드 글 벡터를 가중 합 후 정규화해 가까운 순. 같은 SigLIP 공간이라 가능하다. **비율은 실제 사진으로 재서 정한다**
- 무드 태그 검색(docs/29 §12.14)은 사진 검색에는 섞지 않는다 — 필요해지면 따로 정한다

## 6. 하지 않는 것

- **정확히 일치**(이미지 지문) — 범위 밖
- **이미지 링크 붙여넣기** — 남의 서버에서 사진을 받아 와야 해 보안(SSRF)·저작권 부담. 1단계에서 뺀다
- 올린 사진을 서버·Storage 에 **저장하지 않는다**(§7-1 기본값)
- 새 모델 추가 — SigLIP 만 쓴다. **맥미니에서 qwen·Ollama 는 절대 돌리지 않는다**(docs/38 §3-3)

## 7. 아직 정하지 않은 것 — 기본값으로 진행하고 PR 에 적을 것

1. **올린 사진 보관**: 기본값 = 저장하지 않음(새로고침하면 결과가 사라지고 다시 올려야 한다).
   다른 안 = 하루 동안 벡터(또는 사진)를 저장하고 주소에 id — 새로고침·공유가 되지만 새 표·삭제 작업이 필요
2. **로그인**: 기본값 = 로그인 없이 누구나 + IP 요청 제한
3. **검색 기록**: `search_logs`(0049)는 **원격 DB 에 적용된 적이 없어 표가 없다** — 글 검색 기록도 6월부터 버려지고 있다
   (앱은 넣기에 실패해도 조용히 넘어간다). 0049 적용 여부가 정해지기 전에는 사진 검색 기록을 만들지 않는다.

   **나중에 할 일 (2026-09-28 미룸): "사진으로 어떤 무드를 찾나" 를 남긴다.**
   올린 사진에는 태그가 없으니 **상위 결과 사진들의 목적·무드 태그를 세어** 그것만 남긴다
   (시각 · 무드 태그 · 목적 · 1위 유사도 · 결과 수 · 로그인 사용자 id). **사진 파일도 벡터도 저장하지 않는다** —
   얼굴이 담기고, 벡터도 사람을 특정할 여지가 있다. 태그만 남기면 동의·보관기간 부담이 사라진다.
   순서는 0049 적용(글 검색 기록 부활) → 사진 검색 기록 표 → 어드민 "사진 검색 무드 순위".
   무드 어휘가 정리되면 태그 이름이 바뀔 수 있다는 것만 감안한다.
   품질 개선용으로 **올린 사진 자체**를 모으려면 그때는 따로 동의를 받는다(구글도 "시각적 검색 기록" 설정으로 나눠 받는다).
4. 범위: 1단계 → 사용자 확인 → 2·3단계
