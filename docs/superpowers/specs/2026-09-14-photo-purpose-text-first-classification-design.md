# 텍스트 우선 사진 목적 분류 설계

> 작성일: 2026-09-14
>
> 상태: 설계 승인
>
> 기준 문서: [사진 목적 분류 원칙](../../35-photo-purpose-taxonomy.md)
>
> 대체 범위: 기존 SigLIP 단독 분류 설계의 입력·판정·출처 규칙

## 1. 배경과 목표

기존 `purpose-v3`는 포트폴리오 제목과 설명을 조회했지만 판정에는 사용하지 않고 사진 SigLIP 임베딩만 집계했다. 이 때문에 설명에 `커플 스냅`이 명시된 포트폴리오가 시각적 유사도만으로 `우정`으로 저장되는 문제가 발생했다.

새 분류기는 촬영 목적을 직접 설명하는 텍스트를 최우선 근거로 사용한다. 목적을 판단할 만한 텍스트가 없거나 텍스트가 모호할 때만 SigLIP 사진 점수를 주 근거로 사용한다.

대분류와 저장 코드는 기존과 동일하다.

| 저장 코드 | 화면 표시 |
|---|---|
| `personal` | 개인 |
| `couple` | 커플 |
| `friendship` | 우정 |
| `wedding` | 웨딩 |
| `pet` | 반려동물 |
| `commercial` | 상업/브랜드 |
| `event` | 행사 |

세부분류와 무드 분류는 이번 범위에 포함하지 않는다.

## 2. 핵심 원칙

1. 운영자가 수동 지정하거나 검수한 값은 자동 분류가 덮어쓰지 않는다.
2. 목적을 직접 나타내는 유효한 텍스트가 있으면 텍스트 판정을 우선한다.
3. 무드·장소·색감만 나타내는 텍스트는 목적 근거로 인정하지 않는다.
4. 텍스트가 없거나 목적 정보가 없으면 SigLIP 사진 점수를 사용한다.
5. 텍스트가 여러 목적을 단순 나열하거나 서로 충돌하면 이미지 점수를 보조 근거로 결합한다.
6. 강한 근거가 끝까지 충돌하면 임의 확정하지 않고 관리자 검수 대상으로 남긴다.
7. 기존 무드 관련 컬럼은 읽을 수 있지만 절대 수정하지 않는다.

## 3. 데이터 모델

### 3.1 포트폴리오와 패키지 연결

`public.albums`에 다음 컬럼을 추가한다.

| 컬럼 | 타입 | 규칙 |
|---|---|---|
| `package_id` | `uuid null` | `packages(id)` 참조, 삭제 시 `set null` |

한 포트폴리오는 패키지 하나를 선택할 수 있다. 사진은 `album_id -> albums.package_id`로 패키지를 조회하며 `photos`에 `package_id`를 중복 저장하지 않는다.

신규 포트폴리오 업로드와 수정에서는 가격 문자열이 아니라 실제 패키지 ID를 저장한다. 가격은 표시·스냅샷 용도로 기존 필드에 별도로 유지할 수 있지만 패키지 식별자로 사용하지 않는다.

기존 포트폴리오는 잘못된 연결을 막기 위해 작가나 가격만으로 자동 추정하지 않는다. 연결이 확실한 데이터만 별도 검증 후 백필하고, 나머지는 관리자에서 수동 선택한다.

### 3.2 사진별 텍스트

`public.photos`에 다음 nullable 컬럼을 추가한다.

| 컬럼 | 타입 | 의미 |
|---|---|---|
| `title` | `text null` | 사진별 제목 |
| `caption` | `text null` | 사진별 설명·캡션 |

기존 사진에는 해당 값이 없으므로 `null`로 시작한다. 신규 업로드·수정 화면에서 입력된 경우에만 분류 근거로 사용한다. 이 필드 추가가 일반 사용자 화면 노출을 의미하지는 않는다.

### 3.3 목적 판정 설명

기존 목적 전용 컬럼은 유지하고 `albums`와 `photos`에 다음 컬럼을 추가한다.

| 컬럼 | 타입 | 의미 |
|---|---|---|
| `admin_purpose_evidence` | `jsonb null` | 사용한 입력, 일치 키워드, 텍스트·이미지 후보와 충돌 여부 |

`admin_purpose_source` 허용값은 다음으로 확장한다.

- `text`: 유효한 텍스트가 단독으로 판정을 확정
- `siglip`: 유효한 목적 텍스트가 없어 이미지 점수로 판정
- `hybrid`: 모호하거나 복수인 텍스트를 이미지 점수와 결합
- `manual`: 운영자가 직접 지정

판정 근거에는 원문 전체 대신 필요한 필드명, 일치한 짧은 구문, 후보 점수만 저장한다. 불필요한 개인정보 복제를 피한다.

## 4. 분류 입력

분류기는 포트폴리오와 사진에 직접 연관된 다음 텍스트를 수집한다.

1. 사진 제목과 캡션
2. 포트폴리오 제목과 설명
3. 작가가 직접 입력한 사진 해시태그인 `photos.mood_tags`
4. 포트폴리오의 타깃 카테고리명
5. 포트폴리오의 탐색 카테고리명
6. 실제 `albums.package_id`로 연결된 패키지명과 설명

`generated_tags`와 `auto_mood_tags`는 작가가 직접 입력한 해시태그가 아니므로 이번 판정 입력에서 제외한다. 패키지 연결이 없는 포트폴리오에 같은 작가의 모든 패키지 설명을 섞지 않는다.

## 5. 텍스트 유효성 판정

텍스트가 존재한다는 이유만으로 우선하지 않는다. 정규화한 텍스트에서 촬영 목적을 나타내는 명시적 표현 또는 관리되는 카테고리 매핑이 발견될 때만 유효한 목적 근거로 인정한다.

예시:

- 강한 근거: `커플 스냅`, `데이트 촬영`, `웨딩 촬영`, `증명사진`, `만삭 촬영`, `제품 광고`
- 약한 근거: 목적에 매핑된 타깃·탐색 카테고리, 목적 단어가 포함된 작가 해시태그
- 목적 근거 아님: `필름`, `빈티지`, `따뜻한`, `자연스러운`, `서울`, `골목`, `노을`

대분류별 동의어와 구문은 코드의 버전 관리 대상 사전으로 둔다. 세부분류 용어는 저장하지 않지만 상위 목적 판정에는 사용한다. 예를 들어 `만삭`, `돌잔치`, `졸업 촬영`은 모두 `event` 근거다.

부정 표현과 단순 서비스 나열은 별도로 처리한다. `웨딩은 촬영하지 않습니다`는 웨딩 양성 근거가 아니며, `커플/우정/다인원 가능`은 특정 목적 확정이 아니라 후보 집합이다.

## 6. 근거 우선순위와 결합

같은 수준에서 충돌하지 않는 명시적 목적 표현은 다음 순서로 우선한다.

1. 사진 제목·캡션
2. 포트폴리오 제목·설명
3. 작가가 선택한 타깃·탐색 카테고리
4. 연결된 패키지명·설명
5. 작가 해시태그 중 목적 표현
6. SigLIP 사진 점수

판정 흐름은 다음과 같다.

### 6.1 텍스트 확정

한 목적을 직접 표현하는 강한 텍스트가 있고 같은 수준의 반대 근거가 없으면 그 목적을 저장한다. `커플 스냅입니다`와 같은 설명은 이미지에서 우정 점수가 조금 높더라도 `couple`을 유지한다.

### 6.2 하이브리드 판정

텍스트가 여러 목적을 서비스 범위로 나열하거나 약한 후보만 제공하면 SigLIP 점수는 그 후보 안에서 판정을 보조한다. 텍스트 후보 밖의 이미지 목적이 약간 높다는 이유만으로 후보를 벗어나지 않는다.

예를 들어 패키지가 `커플/우정/다인원`이고 포트폴리오 설명이 비어 있다면 이미지 점수로 `couple`, `friendship`, `event` 중 하나를 고른다.

### 6.3 SigLIP 폴백

수집한 글이 비어 있거나 무드·장소 정보뿐이면 기존 SigLIP 포트폴리오 집계를 사용한다. 출처는 `siglip`으로 기록하고 낮은 확신도는 관리자 검수 필터에 노출한다.

### 6.4 해결되지 않은 충돌

사진·포트폴리오의 강한 텍스트가 서로 다른 목적을 직접 주장하고 우선순위로도 해소되지 않으면 `admin_purpose=null`로 두고 충돌 근거를 저장한다. 기존 값이 검수 완료 또는 수동값이면 변경하지 않는다.

## 7. 포트폴리오와 사진 판정

포트폴리오 자동 판정을 기본으로 하고 결과를 예외가 아닌 소속 사진 전체에 적용한다.

- 포트폴리오 텍스트와 패키지·카테고리 근거로 앨범 목적을 먼저 판정한다.
- 사진별 제목·캡션에 다른 목적이 명시되지 않으면 포트폴리오 목적을 상속한다.
- 사진별 강한 텍스트가 포트폴리오 목적과 다르면 해당 사진만 자동 예외 후보로 기록한다.
- 첫 적용에서는 잘못된 자동 예외를 막기 위해 사진별 충돌을 관리자에게 보여주고, 운영자가 승인할 때만 `admin_purpose_overridden=true`로 확정한다.
- 수동·검수 완료·기존 사진 예외는 재분류에서 보호한다.

## 8. 관리자 UI

`사진 목적&무드` 화면에서 다음 내용을 확인할 수 있게 한다.

- 최종 목적과 분류 출처 배지: 텍스트, SigLIP, 혼합, 수동
- 분류에 사용된 짧은 근거: 예) `포트폴리오 설명: 커플 스냅`
- 텍스트 후보와 SigLIP 상위 후보
- 패키지 연결 여부와 연결된 패키지
- 텍스트 충돌, 낮은 이미지 확신도, 패키지 미연결 필터
- 기존 포트폴리오의 패키지를 수동 연결하는 컨트롤

일반 사용자 화면에는 목적 판정값과 근거를 표시하지 않는다.

## 9. 재분류와 배포

새 분류기 버전은 `purpose-v4-text-first`로 시작한다.

1. 스키마 마이그레이션을 적용한다.
2. 업로드·수정 경로에 실제 패키지 ID 저장을 연결한다.
3. 텍스트 수집과 유효성 판정 단위 테스트를 통과시킨다.
4. 전체 데이터 dry-run을 생성한다.
5. 기존 `커플 스냅` 오분류 사례와 목적별 경계 사례를 검증한다.
6. 운영자가 검수하지 않은 자동 결과만 새 버전으로 재분류한다.
7. 앨범 결과를 예외가 아닌 사진에 일괄 적용한다.
8. 적용 후 목적·출처·근거 수와 앨범-사진 일치 여부를 재조회한다.

기존 `manual`, `admin_purpose_reviewed=true`, `admin_purpose_overridden=true` 값은 보호한다.

## 10. 안전장치와 검증

### 10.1 DB 안전장치

- 마이그레이션은 목적 전용 컬럼, 사진 텍스트 컬럼, `albums.package_id`만 추가·변경한다.
- `mood_tags`, `generated_tags`, `auto_mood_tags`와 기존 카테고리 값은 쓰지 않는다.
- 분류 전후 기존 무드 관련 컬럼의 스냅샷을 비교한다.
- 패키지 삭제는 포트폴리오 삭제로 이어지지 않고 연결만 `null`이 된다.

### 10.2 단위 테스트

- `커플 스냅`이 `couple`로 확정되는지 검사한다.
- 무드와 장소뿐인 텍스트가 SigLIP 폴백으로 가는지 검사한다.
- `커플/우정/다인원`이 단일 목적 확정으로 오인되지 않는지 검사한다.
- 부정 표현이 양성 키워드로 계산되지 않는지 검사한다.
- 입력 출처 우선순위와 충돌 처리를 검사한다.
- 수동·검수·사진 예외 보호를 검사한다.

### 10.3 통합 검증

- 업로드에서 선택한 패키지 ID와 가격이 올바르게 저장되는지 검사한다.
- 패키지명·설명이 실제 연결된 포트폴리오에만 사용되는지 검사한다.
- 텍스트 판정이 앨범과 예외가 아닌 모든 사진에 일괄 저장되는지 검사한다.
- 기존 무드 관련 열의 전후 값이 완전히 동일한지 검사한다.
- 일반 사용자 화면에 목적값과 판정 근거가 노출되지 않는지 검사한다.

## 11. 완료 기준

- 설명에 `커플 스냅`이 명시된 확인 사례가 `couple`, `source=text`로 판정된다.
- 유효한 목적 텍스트가 없는 포트폴리오는 SigLIP 결과를 사용한다.
- 신규 포트폴리오는 실제 패키지 ID를 저장한다.
- 기존 포트폴리오는 잘못된 패키지를 추정 연결하지 않는다.
- 관리자 화면에서 판정 출처와 근거를 확인할 수 있다.
- 검수 완료·수동·사진별 예외가 재분류로 변경되지 않는다.
- 기존 무드 관련 열은 변경되지 않는다.
