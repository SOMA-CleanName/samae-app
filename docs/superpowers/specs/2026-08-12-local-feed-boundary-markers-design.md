# 로컬 홈 피드 경계 표시 설계

## 목적

로컬 `localhost:3000`에서 긴 홈 피드를 테스트할 때 일반 사진의 끝과 전체 사진 한 순환의 끝을 눈으로 확인할 수 있게 한다. 이 기능은 임시 진단 UI이며 운영 화면에는 노출하지 않는다.

## 표시 규칙

- 일반 사진 페이지가 소진되어 노출 낮춤 단계로 전환될 때 피드에 `일반 사진 끝 · 이제 노출 낮춤 사진이 이어집니다` 구분선을 한 번 삽입한다.
- 노출 낮춤 사진도 소진되어 다음 일반 사진 반복 순환으로 전환될 때 `전체 사진 끝 · 여기부터 사진이 반복됩니다` 구분선을 한 번 삽입한다.
- 구분선은 사진 목록과 함께 순서를 유지해, 이후 사진이 추가되어도 실제 경계 위치에 남는다.
- 검색 결과나 편집 큐가 아니라 무한 스크롤 전체 홈 피드에만 적용한다.

## 로컬 제한

- `process.env.NODE_ENV === "development"`인 클라이언트 빌드에서만 경계 항목을 생성하고 렌더링한다.
- 프로덕션 빌드에는 구분선 생성 경로가 비활성화되므로 사용자에게 노출되지 않는다.

## 상태 및 복원

- 피드 세션 캐시에 경계 항목을 함께 저장해 사진 상세를 열었다가 돌아와도 위치가 유지되게 한다.
- 각 경계에는 순환 번호와 경계 종류를 포함한 안정적인 ID를 사용해 중복 삽입을 막는다.
- 기존 사진 ID 중복 제거와 추천 클릭 이력에는 경계 항목이 참여하지 않는다.

## 검증

- 순수 함수 테스트에서 단계 전환별 경계 종류와 로컬 개발 환경 제한을 검증한다.
- 타입 검사와 프로덕션 빌드로 기존 홈 피드 및 운영 빌드에 영향이 없는지 확인한다.

## 단축 테스트 모드

- 개발 환경에서 홈을 `?feedDebug=1`로 열면 별도의 피드 세션 캐시를 사용한다.
- 일반 단계는 첫 48장만, 노출 낮춤 단계는 첫 24장만 보여준 뒤 각 단계를 소진된 것으로 처리한다.
- 서버 쿼리와 실제 데이터는 변경하지 않고 클라이언트의 페이지 수신 결과만 제한한다.
- 개발 환경의 일반 홈과 단축 테스트 홈 모두 화면 상단에 현재 단계, 순환 번호, 누적 로드 장수를 표시한다. 단축 모드에서는 `DEBUG`, 일반 로컬 홈에서는 `LOCAL`로 구분한다.
- `feedDebug` 쿼리가 없거나 프로덕션 빌드이면 기존 무한 스크롤 동작을 그대로 사용한다.
