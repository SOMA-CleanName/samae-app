# 홈·상세 추천 사진 노출 낮춤 설계

## 목적

운영자가 선택한 사진을 추천 후보에서 완전히 제거하지 않고 기본 노출 우선순위만 낮춘다. 사용자가 같은 스타일을 반복해서 선택하면 이 패널티를 점차 상쇄해, 강한 취향 신호와 일치하는 사진은 추천 상단까지 다시 올라올 수 있어야 한다.

## 용어와 데이터

- 기존 `photos.feed_hidden` 컬럼은 그대로 사용한다. DB 마이그레이션과 기존 선택 데이터 175장을 보존한다.
- 사용자·어드민 문구에서는 `숨김` 대신 `노출 낮춤`으로 표시한다.
- 코드에서는 호환성을 위해 컬럼명을 즉시 변경하지 않고, 의미를 `demoted`로 해석하는 함수와 타입 경계에서 감싼다.
- 최근 취향 신호는 홈과 사진 상세 추천에서 누른 사진을 합쳐 세션에 최대 8장 보관한다. 같은 사진의 중복 클릭은 한 번으로 센다.

## 추천 정책

### 일반 홈

첫 사이클에서는 정상 사진을 모두 먼저 노출한다. 정상 사진이 소진되면 노출 낮춤 사진을 별도의 마지막 구간으로 노출하고, 이후 새 시드의 반복 사이클을 시작한다.

노출 낮춤 사진이 정상 사진 사이에 무작위로 끼어들지 않도록 일반 페이지네이션과 낮춤 페이지네이션을 분리한다. 반복 사이클에서도 동일하게 정상 사진 전체 뒤에 낮춤 사진 구간을 둔다.

### 사진 한 장 기준 상세 추천

상세 하단 추천 순서는 다음 세 구간으로 구성한다.

1. 정상 유사 사진
2. 현재 사진과 유사한 노출 낮춤 사진
3. 연관없는 일반 시드 사진

노출 낮춤 사진은 임베딩 거리순을 유지한다. 임베딩이 없는 경우 기존 태그 유사도 폴백을 사용한다. 현재 사진 및 같은 앨범 사진은 기존과 동일하게 제외한다.

### 반복 취향에 따른 승격

최근 클릭 사진들의 유사 이웃 중복률로 기존 `styleConsistency`를 계산하고, 현재 추천 후보가 각 클릭 기준 사진에서 받은 유사도 순위를 함께 사용한다.

- 관련 클릭 1장: 정상 유사 사진 뒤에 배치
- 같은 스타일 2장: 유사 사진 구간의 하위 25% 안으로 승격
- 같은 스타일 3장: 유사 사진 구간의 중간 부근으로 승격
- 같은 스타일 4장 이상: 노출 낮춤 패널티를 대부분 해제하고 원래 임베딩 유사도 순위에 가깝게 배치

클릭 수만 많고 스타일 일관성이 낮으면 승격하지 않는다. 2장 이상 단계에서는 후보가 최근 클릭 기준 사진 여러 개에서 공통으로 유사하거나 기존 일관성 임계값을 충족해야 한다.

노출 낮춤 사진 자체를 클릭하면 이후에는 일반 사진과 동일하게 취향 앵커로 기록한다.

## 구성 요소

### 어드민

- `/admin/photos` 제목과 설명, 필터, 배지, 버튼, 접근성 라벨을 `노출 낮춤`과 `노출 복구`로 변경한다.
- 개별 및 앨범 단위 토글 동작은 유지한다.
- 서버 액션과 DB 권한 가드는 그대로 사용한다.

### 추천 데이터 접근

- 일반 조회 함수의 무조건적인 `.eq("feed_hidden", false)`를 목적별로 정리한다.
- 정상 피드 조회는 기존처럼 `false`만 반환한다.
- 낮춤 전용 조회는 `true`만 반환하며 승인 작가와 공개 사진 조건을 동일하게 적용한다.
- 유사도 RPC는 `feed_hidden` 값을 함께 반환하고 두 집합 모두 거리순으로 가져오도록 새 마이그레이션에서 갱신한다.
- 검색과 편집형 탐색은 이번 범위에서 기존 제외 동작을 유지한다. 이번 변경 대상은 기본 홈과 사진 상세·홈 개인화 추천이다.

### 세션 취향 신호

- 홈 `ExploreGallery`와 상세 `PhotoExplore`가 같은 세션 저장소 키와 직렬화 함수를 사용한다.
- 클릭 직후 동기적으로 저장해 페이지 이동 중 신호가 유실되지 않게 한다.
- 상세 페이지의 최초 서버 렌더는 현재 사진 한 장 기준 추천을 즉시 보여준다. `PhotoExplore`가 마운트된 뒤 공용 세션의 최근 클릭 ID로 서버 액션을 한 번 호출해 같은 그리드를 재정렬한다. 따라서 sessionStorage 값을 서버 컴포넌트가 직접 읽는 구조에 의존하지 않는다.
- 홈의 다음 페이지 요청과 상세의 재정렬 요청에는 최근 클릭 ID만 전달하고, 서버가 사진 메타데이터와 유사 후보를 검증한다.

## 데이터 흐름

1. 사용자가 홈 또는 상세 추천 사진을 누른다.
2. 클라이언트가 최근 클릭 ID를 공용 세션 기록에 추가한다.
3. 다음 홈 48장을 요청하거나 상세 추천 컴포넌트가 마운트될 때 최근 클릭 ID를 서버 액션에 전달한다.
4. 서버는 정상 후보와 노출 낮춤 후보를 분리 조회한다.
5. 서버는 클릭 수, 스타일 일관성, 후보별 유사 순위를 이용해 낮춤 후보의 승격 단계를 정한다.
6. 같은 48장 묶음과 현재 반복 사이클 안에서 중복 ID, 이미 노출된 사진, 클릭 기준 사진을 제거한 뒤 단계별 위치에 합친다.
7. 정상 사진과 노출 낮춤 사진을 모두 소진해 새 반복 사이클이 시작되면 이전 사이클의 노출 기록은 제외 조건에서 해제한다. 따라서 이전 사이클의 사진은 새 순서로 다시 나타날 수 있지만, 같은 48장 묶음 안에서는 중복되지 않는다.

## 실패 처리

- 임베딩 RPC가 실패하거나 임베딩이 없으면 태그 유사도로 폴백한다.
- 낮춤 후보 조회가 실패하면 정상 추천만 반환해 피드 자체는 유지한다.
- 세션 저장소를 사용할 수 없으면 현재 사진 한 장만 기준으로 추천한다.
- 일반 홈의 정상 사진이 비어 있어도 낮춤 사진이 존재하면 낮춤 구간을 노출한다.

## 테스트

순위 계산을 DB·React에서 분리된 순수 함수로 만들고 테스트를 먼저 작성한다.

- 클릭 1장: 낮춤 유사 사진이 정상 유사 사진 뒤, 일반 사진 앞에 위치한다.
- 일관된 클릭 2장: 낮춤 후보가 유사 구간 하위 25%로 승격한다.
- 일관된 클릭 3장: 낮춤 후보가 중간 부근으로 승격한다.
- 일관된 클릭 4장 이상: 강하게 유사한 낮춤 후보가 원래 유사도 순위 근처로 올라간다.
- 서로 다른 스타일 클릭 여러 장: 낮춤 패널티가 해제되지 않는다.
- 일반 홈: 정상 사진 전체 이후 낮춤 사진, 그 이후 새 반복 사이클 순서를 지킨다.
- 반복 사이클: 이전 사이클 사진은 재노출할 수 있고, 현재 사이클 및 같은 48장 안의 중복만 제거한다.
- 홈과 상세 클릭 기록이 같은 최근 8장 목록을 공유한다.
- 낮춤 사진이 검색·편집형 탐색에는 계속 나타나지 않는다.
- 어드민 개별·앨범 토글과 실패 롤백이 기존처럼 동작한다.

## 범위 제외

- `feed_hidden` 컬럼명 변경 및 기존 데이터 마이그레이션
- 검색 결과와 편집형 탐색에서 낮춤 사진 재노출
- 사용자 계정에 영구 저장되는 장기 취향 프로필
- 운영자가 사진별 패널티 강도를 직접 입력하는 기능
