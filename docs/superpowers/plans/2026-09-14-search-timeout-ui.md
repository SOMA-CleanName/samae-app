# Search Timeout UI Implementation Plan

**Goal:** 승인된 시안대로 사진 영역에 검색 지연 안내와 재시도 버튼을 표시한다.

**Design:** 검색창은 먼저 보여주고 사진 영역을 Suspense로 분리한다. 검색 실패와 정상 0건을 구분한다. 모델 요청 4초 제한을 유지하고, 사진 조회·인증·관심사진 조회를 포함한 검색 결과 준비는 8초까지 기다린다. 검색 로깅은 응답 이후 수행한다. 재시도는 기존 검색어로 새 GET 요청을 보내 라우터의 같은 URL 캐시를 재사용하지 않는다.

브라우저 타이머는 Suspense 바깥에서 초기화하고 결과가 준비되면 해제한다. 공통 셸의 세션·채팅 배지는 별도 Suspense로 분리하며, 공개 검색의 사전 세션 갱신은 별도로 3초까지 기다린다. 재시도는 해당 검색어의 갤러리·스크롤·앵커 캐시도 지운다.

**Scope:** dev2의 기존 백필 변경을 보존한다. 운영 DB 설정·모델·검색 순위·홈 피드 정책은 유지한다.

- [x] 검색 결과 상태·기한 테스트를 먼저 작성하고 실패를 확인한다. 정상 0건, 정상 결과, null/예외, 무응답, 늦은 응답, 취소를 검증한다.
- [x] 검색 결과 준비에 기한과 취소 신호를 추가하고 서버의 실패를 숨기지 않도록 전달한다.
- [x] 사진+시계 아이콘, 승인된 문구, 브랜드 버튼을 구현한다. 검색창과 정상 갤러리를 보존하고 검색 결과만 스트리밍한다.
- [x] 정상·실패·8초 지연·재시도 경로를 검증한다. 문서에 새 UI 및 시간 기준을 반영한다.
- [x] 관련 테스트, TypeScript, 변경 파일 ESLint, 빌드, 독립 코드 리뷰를 완료한다.

Browser 연결을 시도했으나 `No browser is available` 및 빈 브라우저 목록을 확인했다. HTTP 스트리밍 응답·React 서버 렌더링·폼 제출 URL을 검증했다. 실제 브라우저 클릭·스크린샷·hydration 후 타이머 동작은 미검증이다.

**검증 결과 (2026-09-14):** 전체 TypeScript 테스트 271개, TypeScript 검사, 변경 파일 ESLint, 프로덕션 빌드 통과. 별도 3001 프로덕션 서버에 임시 fetch 대역을 주입하여 정상 결과·HTTP 503·잘못된 모델·임베딩 무응답·DB 무응답·DB 오류·정상 0건·같은 검색어 재시도 총 8경로를 확인했다. 지연 중 첫 HTML은 15~16ms에 도착했고 안내 문구는 각각 4,018ms·8,018ms에 렌더링됐다. 재시도는 실제 오류 폼의 숨김 검색어를 읽어 요청했으며 사진 복원을 확인했다. 테스트 대역은 저장소 밖 임시 파일에 두고 운영 DB에 테스트 로그를 쓰지 않았다.

기존 3000 개발 서버의 실제 모델·DB 검색과 홈은 각각 HTTP 200·사진 링크 48개를 반환했다. 독립 리뷰의 타이머 초기화·공통 셸 대기·재시도 캐시·너비 상한 지적을 반영하고 재검토를 마쳤다. 원격 배포는 수행하지 않았다.
