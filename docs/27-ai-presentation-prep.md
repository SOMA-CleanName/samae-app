# 27. AI 파트 발표·질의 대비 (2026-08-17)

> 문서 상태: **작성 중.** 발표 준비를 진행하며 채운다.
>
> 이 문서는 발표자가 보는 **작업용 문서**다. 설계 근거는 [22 시각 유사도](22-visual-similarity.md), 화면 동작은 [26 관심사진 유사 추천](26-interest-similar-recommendations.md) 에 있고 여기 옮겨 적지 않는다. 여기 있는 것은 **무엇을 말할지와 무엇을 답할지** 뿐이다.

## 1. 지금 진짜 동작하는 것

AI 관련 문서가 22~26 다섯 개로 흩어져 있다. **발표자는 이 표만 외우면 된다.**

| 사용자에게 동작 중 | 만들었지만 미연결 | 알려진 결함 |
|---|---|---|
| 사진 상세 유사 추천 (벡터) | 무드 태그 (`auto_mood_tags`) | 취향 '목적' 축 오배선 ([23](23-taste-purpose-mapping.md)) |
| 관심사진 앵커별 추천 ([26](26-interest-similar-recommendations.md)) | 톤 디스크립터 (검토 후 미도입) | 근접중복 3쌍 ([22](22-visual-similarity.md) §7.3) |
| 홈 피드 개인화·노출 낮춤 ([24](24-feed-personalization-demotion.md)) | | |

**8단계 중 0~5단계가 배포됐고 6~8단계는 보류다.** 보류 이유는 셋 다 같다 — **처방할 증상이 실측되지 않았다.**

### 이 표를 말하는 법

"못 했다" 로 들리면 감점이고 "판단했다" 로 들리면 강점이다. 문장을 미리 고정해 둔다.

> 8단계까지 설계했고 태그 생성까지 만들었습니다. 다만 **붙일 근거가 될 증상을 측정하지 못해 연결하지 않았습니다.** 재계산은 91초면 끝나므로, 증상이 관측되면 그때 붙입니다.

## 2. 헤드라인 숫자 하나

여러 숫자 중 **이것만 기억시킨다.**

> ### 추천 8장 중 같은 작가 사진이 **6.6장 → 3.2장**
> (82.2% → 39.9% · top-8 등장 작가 1.5명 → 3.3명)

왜 이 숫자인가 — "AI 를 왜 썼나" 의 답이면서 **마켓플레이스 지표로 바로 번역**된다. 사용자가 한 작가에 갇히지 않는다 = 매칭 기회가 넓어진다.

**왜 그런 일이 벌어졌나(원인 설명이 강점이다)**: 기존 추천은 `mood_tags` 겹침으로 정렬했는데, 태그는 **작가가 직접 입력**한다. 작가마다 어휘가 굳어 있어서 "태그가 겹친다 = 같은 사람이 달았다" 에 가까웠다. 유사도를 재는 대신 **작성자를 재고 있었다.**

### 보조 숫자 (물으면 꺼낸다)

| | 값 |
|---|---|
| 모델 비용 | **0원** (오픈 웨이트 · 조회 시점 추론 없음) |
| 색인 규모 | 공개 사진 1,582장 · 1152차원 · `halfvec` 3.5MB |
| 백필 1회 | 로컬 맥 11분 |
| 추천 응답 | RPC 왕복 89ms · 관심사진 추천 서버 처리 225~298ms |
| 기존 방식과의 결과 겹침 | **12.8%** (벡터가 태그가 못 찾던 것을 뽑는다) |

## 3. 서사 (초안 — 채울 것)

- [ ] 3분 버전
- [ ] 8분 버전

권장 뼈대:

1. **문제** — 추천 8장 중 6.6장이 같은 작가였다. 태그가 유사도가 아니라 작성자를 재고 있었다.
2. **선택** — SigLIP 2 임베딩 + pgvector. 조회 시점 추론이 없어 **비용과 지연이 늘지 않는 구조**.
3. **결과** — 같은 작가 39.9%, 작가 3.3명. 태그 없는 사진도 후보가 된다.
4. **판단** — 7·8단계는 만들었지만 붙이지 않았다. 근거가 없어서.

## 4. 예상 질문과 답

날아올 가능성이 높은 순서다. **★ 는 준비가 덜 된 것.**

### ★ Q. 정확도를 어떻게 측정했나

가장 아픈 질문이다. **정답 라벨이 없다.** "눈으로 봤다" 로 답하면 무너진다. 대리 지표 3종을 표로 준비한다.

| 지표 | 의미 | 결과 |
|---|---|---|
| 같은 작가 비율 | 낮을수록 무드로 묶임 | 82.2% → 39.9% |
| 시드와 톤 차이(명도·채도) | 낮을수록 톤 일관 | 0.1489 / 0.1307 |
| 변별폭 (top1 − 전체평균) | 클수록 구분력 | 0.214 |

- [ ] 위 표를 슬라이드 1장으로

### Q. 왜 파인튜닝을 안 했나

학습 데이터가 1,582장뿐이고, **제로샷으로 이미 기존 방식을 이겼다.** 파인튜닝은 개선폭을 잴 기준선이 생긴 다음 일이다.

### Q. 왜 SigLIP 2 인가 / 왜 CLIP 이 아닌가

- 공개 사진의 **80.6% 가 세로**, 18.4% 가 가로다. 고정 정사각 입력은 어느 쪽을 맞춰도 반대쪽 구도가 뭉개진다 → **원본 비율을 유지하는 NaFlex** 변형을 골랐다.
- 오픈 웨이트라 호출 과금이 없다.

### Q. 사진이 10만 장이 되면

현재 플래너가 `Seq Scan` 을 고르는 것은 1,582장에서 비용이 거의 같기 때문이다(282 vs 291). **데이터가 늘면 자동으로 HNSW 로 넘어간다.** 인덱스가 사용 가능한 상태인 것은 `enable_seqscan=off` 로 검증했다(읽은 버퍼 9,712 → 735).

### Q. 운영은 어떻게 하나 (신규 사진)

**주 1회 수동 배치**다. 자동화(6단계)는 의도적으로 보류했고 전환 조건까지 정해 뒀다 — "임베딩 대기가 두 주 연속 100장을 넘으면 착수". ([22](22-visual-similarity.md) §12.1)

> 먼저 꺼내지 않는다. 물으면 답한다.

### ★ Q. 개인화는 어떻게 되나

[24](24-feed-personalization-demotion.md) 내용이다. 발표자가 이 문서를 아직 안 읽었다면 읽어야 한다.

- [ ] 24 문서 정독

### Q. 비용은

**모델 0원.** 클릭된 사진이 이미 자기 벡터를 갖고 있어 **조회 시점에 추론이 없다.** 트래픽이 늘어도 추론 비용이 늘지 않는다.
