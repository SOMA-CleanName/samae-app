# 홈·상세 개인화 추천과 사진 노출 낮춤

> 최종 구현 기준: 2026-08-13 · `dev` 브랜치
>
> 기존 Superpowers 설계·구현 계획과 실제 코드를 대조해 하나로 통합한 현재 동작·운영 인수인계 문서다. 통합이 끝난 원본 `plans`·`specs` 파일은 2026-08-13에 삭제했다.

---

## 1. 목적과 결론

기존 `feed_hidden=true` 사진은 홈과 유사 추천에서 완전히 제외됐다. 현재는 이 값을 **노출 낮춤(soft demotion)** 신호로 사용한다.

- 기본 홈에서는 일반 사진을 먼저 보여주고, 일반 사진이 모두 소진된 뒤 노출 낮춤 사진을 보여준다.
- 사용자가 사진을 누르면 다음 홈 로딩 48장 일부를 해당 사진과 유사한 사진으로 교체한다.
- 최근에 같은 스타일을 반복해서 누를수록 개인화 추천량이 늘고, 유사한 노출 낮춤 사진의 순위 패널티도 단계적으로 줄어든다.
- 사진 상세 추천도 같은 클릭 이력을 사용한다.
- 모든 사진을 한 번 소진하면 새 시드로 다시 순환하므로 홈 무한 스크롤이 끝나지 않는다.

`photos.feed_hidden` 컬럼과 기존 선택 데이터는 그대로 보존한다. DB 컬럼명은 호환성을 위해 바꾸지 않았지만, 어드민과 제품 의미는 `숨김`이 아니라 `노출 낮춤`이다.

## 2. 적용 범위

### 적용됨

- 기본 홈 무한 피드
- 기본 홈의 클릭 기반 개인화 추천
- 사진 상세 하단 유사 추천
- `/admin/photos`의 개별·앨범 단위 노출 낮춤 관리

### 적용하지 않음

- 검색 결과
- 편집형 Explore 및 카테고리 큐레이션
- 계정에 영구 저장되는 장기 취향 프로필
- 사진별 패널티 강도 수동 입력

검색·편집형 화면은 기존 정책대로 `feed_hidden=true` 사진을 제외한다.

## 3. 공용 클릭 이력

홈과 상세 추천은 `sessionStorage`의 같은 키를 사용한다.

```text
samae:feed-click-history:v1
```

동작 규칙:

- 최근 고유 사진 ID를 최대 8장 저장한다.
- 같은 사진을 여러 번 눌러도 한 번만 기록한다.
- 8장을 넘으면 오래된 ID부터 제거한다.
- 홈 카드와 상세 추천 카드는 페이지 이동 직전에 동기적으로 기록한다.
- 서버 추천은 이 중 최근 최대 4장을 실제 앵커로 사용한다.
- 노출 낮춤 사진을 눌러도 일반 사진과 동일한 취향 앵커가 된다.
- 세션 저장소를 사용할 수 없으면 개인화 신호만 약해지고 기본 피드와 상세 추천은 계속 동작한다.

관련 코드:

- `src/lib/feed-click-history.ts`
- `src/components/user/ExploreGallery.tsx`
- `src/app/(user)/photos/[id]/PhotoExplore.tsx`

## 4. 홈 피드 데이터 흐름

홈의 서버 페이지 크기는 48장이다.

1. 첫 진입은 일반 홈 page 0의 48장으로 시작한다.
2. 사용자가 사진을 누르면 공용 클릭 이력에 ID를 기록한다.
3. 다음 48장을 요청할 때 일반 피드 48장과 최근 클릭 ID를 서버에 전달한다.
4. 서버는 클릭 앵커별 유사 후보를 최대 120장씩 조회한다.
5. 추천 장수와 노출 낮춤 승격 단계를 계산한다.
6. 현재 48장, 현재 사이클에서 이미 본 ID, 클릭 앵커를 제외한다.
7. 일반 사진 일부를 개인화 추천 6~36장으로 교체한다.
8. 교체 위치는 페이지 시드로 셔플해 한 구간에 규칙적으로 몰리지 않게 한다.

홈에서 추천되는 장수는 고정 12장이 아니라 클릭 수와 스타일 일관성에 따라 바뀐다.

| 조건 | 기본/강화 추천량 |
|---|---:|
| 클릭 1장 | 12장 |
| 클릭 2장 | 16장 |
| 클릭 3장 이상 | 20장 |
| 스타일 일관성 `>= 0.12` | 최소 20장 |
| 스타일 일관성 `>= 0.25` | 24장 |
| 스타일 일관성 `>= 0.40` | 30장 |
| 스타일 일관성 `>= 0.55` | 36장 |

최대치는 36장이다. 클릭 수가 많아도 서로 다른 스타일이면 일관성이 낮게 계산되어 추천량과 노출 낮춤 승격이 과도하게 올라가지 않는다.

관련 코드:

- `src/lib/discovery.ts`
  - `fetchPersonalizedHomeFeedPage`
  - `fetchPersonalizedRecommendations`
- `src/app/(user)/feed-actions.ts`
  - `loadMorePhotos`
  - `loadPersonalizedPhotos`

## 5. 스타일 일관성 계산

최근 최대 4개 앵커 각각에 대해 유사 사진 목록을 만들고, 각 목록의 상위 60개 ID가 서로 얼마나 겹치는지 계산한다.

- 두 목록의 교집합 크기를 더 작은 목록 크기로 나눈다.
- 앵커 쌍이 여러 개면 모든 쌍의 값을 평균낸다.
- 임베딩 결과가 없으면 태그 유사도 폴백 목록으로 같은 계산을 한다.

따라서 단순히 클릭 횟수만 늘리는 것으로는 강한 승격이 일어나지 않는다. 비슷한 스타일을 반복해서 선택해 유사 이웃이 실제로 겹쳐야 한다.

## 6. 노출 낮춤 승격 정책

유사도 조회 결과는 `feed_hidden`을 앱 경계에서 `demoted`로 변환하고, 원래 유사도 순서를 `naturalRank`로 보존한다.

| 단계 | 조건 | 노출 낮춤 유사 사진 위치 |
|---|---|---|
| 1단계 | 기본값, 또는 일관성 부족 | 일반 유사 사진 뒤 |
| 2단계 | 앵커 2장 이상 + 일관성 `>= 0.12` | 일반 유사 구간의 약 75% 지점 |
| 3단계 | 앵커 3장 이상 + 일관성 `>= 0.18` | 일반 유사 구간의 약 50% 지점 |
| 4단계 | 앵커 4장 이상 + 일관성 `>= 0.25` | 원래 자연 유사도 순위에 가깝게 복원 |

4단계에서도 `feed_hidden` 값을 지우는 것은 아니다. 해당 요청의 순위 패널티만 사실상 해제한다. 다른 사용자나 다른 세션의 기본 피드에서는 계속 노출 낮춤 정책을 적용한다.

핵심 순수 함수는 `src/lib/feed-demotion.ts`에 있다.

- `promotionStage`
- `mergeDemotedSimilar`
- `uniqueWithinCycle`
- `mapSimilarityRows`
- `nextFeedPhase`
- `composeDetailRecommendations`

## 7. 홈 전체 순환과 무한 스크롤

홈은 다음 상태 순서로 동작한다.

```text
일반 사진 페이지들
  → 일반 사진 소진
  → 노출 낮춤 사진 페이지들
  → 노출 낮춤 사진 소진
  → 새 시드의 다음 일반 사이클
  → 반복
```

세션에는 다음 상태를 저장하고 상세 화면에서 돌아올 때 복원한다.

- 현재 seed
- 마지막 page
- 현재 노출 장수
- `normal | demoted` 단계
- 반복 cycle 번호
- 현재 cycle에서 본 사진 ID
- 공용 클릭 이력 사본

중복 제거 범위는 **현재 48장 묶음과 현재 반복 사이클**이다. 새 사이클이 시작되면 이전 사이클에서 본 사진은 새 순서로 다시 나타날 수 있다. 이 정책이 사진 전체 소진 뒤에도 무한 스크롤을 계속 가능하게 한다.

노출 낮춤 전용 꼬리는 `fetchDemotedHomeFeedPage`가 `feed_hidden=true`, 공개 사진, 승인 작가 조건으로 조회한다.

## 8. 사진 상세 추천

상세 최초 진입은 현재 사진 한 장을 기준으로 즉시 서버 렌더링한다. 클라이언트가 마운트되면 공용 클릭 이력의 최근 ID를 읽어 한 번 재정렬한다.

기본 순서:

```text
일반 유사 사진
  → 노출 낮춤 유사 사진
  → 연관없는 일반 시드 사진
```

같은 스타일을 반복해서 누른 세션에서는 2~4단계 정책에 따라 노출 낮춤 유사 사진이 유사 구간 안에서 점차 올라온다. 연관없는 사진보다 뒤로 밀리지는 않는다.

추천 카드에서 다른 사진을 누르면 그 사진도 공용 클릭 이력에 기록되어 다음 상세 재정렬과 홈 개인화에 함께 사용된다.

관련 코드:

- `src/lib/discovery.ts`의 `fetchRankedDetailRecommendations`
- `src/app/(user)/feed-actions.ts`의 `loadRankedDetailPhotos`
- `src/app/(user)/photos/[id]/page.tsx`
- `src/app/(user)/photos/[id]/PhotoExplore.tsx`

## 9. 유사도 조회와 DB 변경

마이그레이션 `supabase/migrations/0076_photo_feed_demotion.sql`이 `similar_photos_by_embedding(uuid, integer)`을 갱신한다.

변경점:

- 후보 풀의 `not feed_hidden` 완전 제외 조건을 제거했다.
- 결과에 `feed_hidden boolean`을 추가했다.
- 공개 사진, 승인 작가, 현재 사진 제외, 같은 앨범 제외 조건은 유지했다.
- HNSW 검색 결과의 거리순을 유지한다.
- 최대 RPC limit은 300이다.

임베딩이 없거나 RPC가 실패하면 기존 `mood_tags` 기반 유사도 방식으로 폴백한다. 태그 폴백도 `feed_hidden` 상태를 함께 읽어 동일한 승격 정책을 적용한다.

`docs/22-visual-similarity.md`의 현재 RPC 기준도 `0076_photo_feed_demotion`으로 갱신되어 있다.

## 10. 어드민 동작

`/admin/photos`의 사용자 노출 문구는 다음처럼 변경했다.

- 사진 숨김 → 사진 노출 낮춤
- 숨김 → 노출 낮춤
- 숨김 해제 → 노출 복구
- 필터와 배지, 버튼, 접근성 라벨도 같은 용어 사용

개별 사진과 앨범 단위 토글, 서버 액션, 권한 검증, DB 컬럼은 기존 구조를 유지한다.

## 11. 실패 처리

- 임베딩 RPC 실패 또는 임베딩 없음: 태그 유사도 폴백
- 개인화 추천 실패: 준비된 일반 홈 사진 유지
- 노출 낮춤 후보 없음: 일반 추천만 표시
- 세션 저장소 접근 실패: 현재 화면은 유지하고 세션 개인화만 약화
- 일반 사진 페이지가 비면: 노출 낮춤 단계로 전환
- 네트워크 일시 오류: 피드 소진으로 확정하지 않고 잠시 뒤 같은 페이지 재시도

## 12. 테스트와 검증

현재 유지되는 자동 테스트는 다음 25개다.

### 노출 낮춤 순위 9개

- 클릭 1장: 일반 유사 사진 뒤 배치
- 일관된 클릭 2장: 하위 25% 부근 승격
- 일관된 클릭 3장: 중간 부근 승격
- 일관된 클릭 4장: 자연 순위 복원
- 불일치 클릭: 기본 패널티 유지
- 현재 사이클 중복·클릭·이미 본 ID 제거
- RPC `feed_hidden` → 앱 `demoted` 매핑
- 홈 `normal → demoted → 다음 cycle normal` 상태 전환
- 상세 `일반 유사 → 노출 낮춤 유사 → 무관 사진` 구성

### 클릭 이력 3개

- 고유 ID 순서 유지
- 최근 8장 제한
- 사용자 지정 제한의 결정성

### 추천 방향 보정 5개

- 극단적으로 유사한 후보의 상단 포함과 방향 분산
- 보호 가로 후보 군집의 첫 화면 분산
- 세로·기타 후보 안의 기존 순서 유지
- 세로 후보 부족 시 전체 후보 보존
- 일반·노출 낮춤 그룹이 공용 최상위 거리를 사용하는지 확인

### 클릭·관심 개인화 8개

- 관심 이력 저장값 검증과 중복 제거
- 최초 담기 시각 유지와 재담기 중복 방지
- 29,999ms 해제 시 관심 신호 취소
- 30,000ms 해제 시 학습된 관심 신호 유지
- 기존 장바구니 사진의 성숙한 관심 이력 이관
- 클릭 1·관심 2 가중치의 `6, 9, 12...` 추천량
- 신호별 ID 중복 제거와 최대 36장 제한
- 최근 관심 우선·클릭 중복 제거 기준 사진 선택

검증 명령:

## 16. 추천 방향 편향 보정 (2026-08-13)

### 측정 결과

공개·승인·임베딩 완료 1,763장을 대상으로 방향별 기준 사진을 분산 표집해 top-30을 측정했다.

| 기준 | 카탈로그 기본 비중 | top-30 같은 방향 | 기본 비중 대비 |
|---|---:|---:|---:|
| 가로 | 21.9% | 96.8% | 4.42배 |
| 세로 | 77.1% | 97.3% | 1.26배 |
| 정사각 | 1.0% | 20.7% | 20.24배 |

가로 기준에서 같은 작가 후보를 제외해도 가로 비율은 98.2%였다. 따라서 작가나 앨범 쏠림보다 SigLIP 2 NaFlex 임베딩이 원본 종횡비를 강하게 반영하는 것이 주원인이다.

### 정책

- 임베딩 후보 중 최상위 거리에서 `+0.015` 이내인 후보는 방향과 관계없이 상단 포함을 보호한다.
- 최유사 1장은 1순위를 유지하고, 나머지 보호 후보는 같은 방향 사진이 첫 화면에 뭉치지 않도록 방향 슬롯에 분산한다.
- 보호 후보를 포함한 최종 후보의 세로 사진 비율 75%를 목표로 재배치한다.
- 세로 후보가 부족하면 유사도가 낮은 사진을 새로 만들거나 강제로 채우지 않고 남은 원래 후보를 사용한다.
- 일반 후보와 노출 낮춤 후보를 각각 보정한 뒤 기존 1~4단계 노출 낮춤 승격 정책으로 병합한다.
- 태그 폴백은 연속 거리 값이 없으므로 보호 구간 없이 세로 75% 목표만 적용한다.
- 홈 개인화와 사진 상세 추천에 같은 정책을 적용한다.
- 임베딩 RPC 후보 풀은 120장에서 최대 300장으로 넓히되, 상세 반환 120장과 홈 삽입 6~36장 한도는 유지한다.

`+0.015` 근거는 가로 기준 20장의 top-120 거리 분포다. 기준 사진당 보호 후보는 평균 2.6장이었다. `+0.030`은 7.2장, `+0.050`은 19.9장을 보호해 방향 편향 완화 효과가 지나치게 약해진다.

top-120 후보만 재정렬하면 가로 기준 top-30의 세로 비율은 24.5%에 그쳤다. top-300으로 후보를 넓힌 뒤 같은 보정을 적용하면 세로 비율이 정확히 75%가 됐다. 이때 top-30 마지막 후보의 코사인 거리는 기존 top-30 마지막 후보보다 평균 `0.0632` 증가했다.

### 구현 계획

1. `SimilarPhoto`에 임베딩 코사인 `distance`를 선택 값으로 끝까지 보존한다. ✅
2. 순수 함수 `rebalancePortraitShare`를 추가하고 보호 구간, 75% 목표, 후보 부족, 순서 안정성을 테스트한다. ✅
3. 일반·노출 낮춤 유사 후보 각각을 방향 보정한 뒤 기존 `mergeDemotedSimilar`에 전달한다. ✅
4. RPC 내부 재정렬 후보를 300장으로 넓히고 호출부의 기존 반환 한도를 유지한다. ✅
5. 홈 개인화와 상세 추천 회귀 테스트, 타입 검사, 배포 검증을 실행한다. ✅

## 17. 클릭·관심 신호 분리와 추천량 계산 설계 (2026-08-13)

### 목표

홈 피드의 다음 48장에 섞이는 유사 사진 수를 사용자의 명시적인 행동 강도에 따라 결정한다. 사진 열람 클릭, 현재 장바구니, 추천용 관심 이력을 서로 분리한다. 관심 해제는 부정 취향이 아니라 장바구니 정리일 수 있으므로 감점 신호로 사용하지 않는다.

사진 상세 하단 추천은 현재처럼 클릭 이력만 사용한다. 이번 변경 범위는 홈 피드 개인화다.

### 신호와 저장소

| 신호 | 저장소 | 가중치 | 해제 동작 |
|---|---|---:|---|
| 사진 열람 클릭 | `sessionStorage`의 `samae:feed-click-history:v1` | 1 | 세션이 끝날 때까지 유지 |
| 추천용 관심 이력 | `localStorage`의 `samae:feed-interest-history:v1` | 2 | 담은 뒤 30초 미만에 해제한 경우만 제거 |

같은 사진이 클릭 이력과 관심 목록에 모두 있으면 가중치를 합산한다. 예를 들어 사진 한 장을 열고 관심에 담으면 `1 + 2 = 3`이다. 다만 유사도 기준 사진 ID는 중복 없이 한 번만 사용한다.

관심 담기 시각을 함께 저장한다. 담은 지 30초 미만에 해제하면 실수 취소로 보고 추천용 관심 이력에서도 제거한다. 30초 이상 지난 뒤 해제하면 장바구니에서만 제거하고 추천용 관심 이력은 유지한다. 이 해제는 유사 사진에 감점을 만들지 않는다. 이미 학습된 사진을 다시 담아도 가중치를 중복 추가하거나 최초 담기 시각을 갱신하지 않는다.

### 추천량 계산

고유 클릭 사진 수를 `C`, 고유 관심 사진 수를 `I`라고 할 때 유효 신호 수 `S`와 다음 48장에 삽입할 유사 사진 수 `R`은 다음과 같다.

```text
S = C + 2I
S = 0이면 R = 0
S > 0이면 R = min(36, 3 × (S + 1))
```

예시:

| 행동 | 유효 신호 `S` | 유사 사진 `R` |
|---|---:|---:|
| 클릭 1장 | 1 | 6장 |
| 클릭 2장 | 2 | 9장 |
| 클릭 3장 | 3 | 12장 |
| 관심 이력만 1장 | 2 | 9장 |
| 클릭 1장 + 같은 사진 관심 | 3 | 12장 |
| 클릭 2장 + 그중 1장 관심 | 4 | 15장 |
| 유효 신호 11 이상 | 11+ | 최대 36장 |

기존의 스타일 일치도 임계값에 따른 `20/24/30/36장` 추천량 증폭은 제거한다. 스타일 일치도는 노출 낮춤 사진의 1~4단계 승격 판단에만 유지한다.

### 홈 피드 데이터 흐름

1. `CartProvider`는 장바구니와 추천용 관심 이력을 각각 복원하고, 관심 이력 ID와 복원 완료 상태를 제공한다.
2. 기존 장바구니에 있지만 추천용 이력이 없는 사진은 이전 버전에서 충분히 오래 담겨 있던 사진으로 간주해 `addedAt: 0`으로 한 번 이관한다.
3. 관심 추가 시 고유한 `{ id, addedAt }` 이력을 만든다. 이미 이력이 있으면 기존 값을 유지한다.
4. 개별 해제와 전체 비우기는 각각의 담기 경과 시간을 확인한다. 30초 미만인 항목만 추천용 이력에서 제거한다.
5. `ExploreGallery`는 공용 클릭 이력과 추천용 관심 이력 ID를 별도 신호로 사용한다.
6. 홈의 다음 페이지를 요청할 때 `clickedPhotoIds`, `interestedPhotoIds`, `seenPhotoIds`를 구분해 서버 액션에 전달한다.
7. 서버는 클릭과 관심 ID의 합집합에서 중복을 제거해 유사도 기준 사진을 만든다.
8. 홈 추천 기준 사진은 관심 신호를 우선하되 최대 최근 4개의 고유 ID만 사용한다. 관심 사진 사이와 클릭 사진 사이의 기존 순서는 보존한다.
9. 여러 기준 사진의 추천 후보는 지금처럼 한 장씩 번갈아 선택한다. 관심 가중치 2는 추천량에만 적용하고 한 관심 사진의 후보를 두 번씩 뽑지는 않는다.
10. 관심 추가·해제 중 이미 시작된 요청은 요청 시점의 스냅샷을 사용하고, 다음 48장 요청부터 최신 관심 이력을 적용한다.

초기 48장은 현재 정책대로 일반 홈 피드를 유지한다. 클릭이나 관심 신호로 계산한 유사 사진은 다음 48장 로딩부터 섞인다.

### 실패 처리

- 장바구니와 추천용 관심 이력의 `localStorage` 복원이 끝나기 전에는 관심 목록을 빈 값으로 확정해 개인화 요청하지 않는다.
- 저장소 접근이 불가능하면 관심 신호만 비활성화하고 클릭 기반 개인화는 유지한다.
- 관심 사진이 삭제·비공개·미승인 상태라 유사 후보를 가져올 수 없으면 해당 ID만 기준 사진에서 제외한다.
- 추천 후보가 계산된 목표 수보다 적으면 가능한 후보만 섞고 일반 사진으로 나머지 48장을 채운다.

## 18. 관심 사진 상세 세로 순환 탐색 설계 (2026-08-14)

### 목표와 범위

관심 사진 도크의 펼침 그리드에서 사진을 탭해 상세보기에 들어간 뒤, 세로 스와이프만으로 다른 관심 사진을 연속 탐색한다. 가로 스와이프는 탐색 동작으로 사용하지 않는다.

- 손가락을 위로 밀면 그리드 표시 순서의 다음 관심 사진으로 이동한다.
- 손가락을 아래로 끌면 이전 관심 사진으로 이동한다.
- 마지막 사진의 다음은 첫 사진이고, 첫 사진의 이전은 마지막 사진이다.
- 관심 사진이 한 장뿐이면 순환 탐색과 제스처 안내를 비활성화한다.
- 닫기, 공유, 게시물 보기, 무료 견적 받기와 기존 브라우저 뒤로가기 동작은 유지한다.

그리드는 최신 관심 사진부터 표시하므로 상세 탐색 순서도 같은 최신순을 사용한다. 사용자가 그리드 중간 사진에서 진입하면 그 위치를 기준으로 앞뒤가 이어진다.

### 제스처 판정과 전환

- 포인터 시작점과 끝점의 세로 거리가 56px 이상이고 세로 이동이 가로 이동보다 클 때만 탐색으로 판정한다.
- 위 방향은 `next`, 아래 방향은 `previous`로 해석한다.
- 임계값 미만 이동과 가로 위주 이동은 사진 전환을 만들지 않는다.
- 한 번 전환을 시작하면 약 320ms 동안 중복 입력을 잠근다.
- 현재 사진은 제스처 방향으로 빠져나가고 새 사진은 반대쪽에서 들어오는 세로 전환을 사용한다.
- 전환이 시작된 포인터 업 뒤에 발생하는 합성 클릭은 무시해 상세보기가 그리드로 닫히지 않게 한다.
- 데스크톱 확인을 위해 세로 휠·트랙패드 입력도 같은 순환 인덱스를 사용하되 한 번의 관성 스크롤에서 한 장만 이동하도록 잠근다.
- `prefers-reduced-motion` 환경에서는 큰 이동 애니메이션 없이 짧은 교차 페이드로 바꾼다.

순환 인덱스 계산과 제스처 방향 판정은 React 컴포넌트 밖의 순수 함수로 분리해 경계 조건을 자동 테스트한다.

### 최초 사용 안내

관심 사진이 두 장 이상이고 이 브라우저에서 안내를 본 적이 없을 때만 상세 진입 약 0.5초 후 안내를 한 번 표시한다.

```text
위로 밀면 다음 관심사진이 보입니다
```

- 회색 반투명 배경과 흰색 글씨를 사용한다.
- 문구 위의 하얀 화살표 세 개가 짧은 간격으로 위로 이동하며 사라진다.
- 안내 전체는 약 2초 안에 페이드아웃하고 포인터 입력을 가로채지 않는다.
- 사용자가 안내 도중 실제 스와이프를 시작하면 즉시 사라진다.
- 노출 여부는 버전이 포함된 `localStorage` 키로 저장한다. 문구나 동작을 크게 바꿀 때 새 버전으로 다시 안내할 수 있다.
- 저장소에 접근할 수 없으면 현재 상세 세션에서 한 번만 보여주고 탐색 자체는 정상 동작한다.

### 상태와 데이터 흐름

1. `FloatingCart`는 `items`를 그리드 표시 순서와 같은 최신순 탐색 배열로 만든다.
2. 상세 진입 시 `focused` ID의 탐색 인덱스를 찾는다.
3. 스와이프 방향과 현재 인덱스로 순환 목적지 인덱스를 계산한다.
4. 전환 중에는 출발·도착 ID와 방향을 보관하고 두 카드만 표시한다.
5. 전환이 끝나면 `focused`를 목적지 ID로 확정하고 기존 메타 조회가 새 사진 ID 기준으로 실행된다.
6. 관심 목록이 외부에서 바뀌어 현재 ID가 사라지면 남은 첫 사진으로 이동하고, 목록이 비면 기존 동작대로 도크를 닫는다.

### 실패 처리와 접근성

- 이미지나 메타 조회가 늦어도 사진 전환 상태는 멈추지 않는다. 기존 메타의 `photoId` 검증으로 다른 사진 정보가 노출되지 않게 한다.
- 전환 중 닫기나 브라우저 뒤로가기가 발생하면 타이머를 정리하고 그리드로 복귀한다.
- 안내는 `aria-hidden`으로 처리해 화면 낭독기가 일회성 장식 문구를 반복해서 읽지 않게 한다.
- 상세 카드 컨테이너의 접근성 라벨에는 세로 탐색 가능 여부를 포함한다.

### 테스트와 승인 기준

1. 중간 사진에서 `next`와 `previous`가 각각 인접 사진을 반환한다.
2. 마지막의 `next`가 첫 사진, 첫 사진의 `previous`가 마지막 사진을 반환한다.
3. 빈 목록과 한 장 목록에서 안전하게 동작한다.
4. 56px 미만, 가로 위주 이동은 무시하고 유효한 위·아래 이동만 방향을 반환한다.
5. 스와이프 뒤 합성 클릭으로 상세가 닫히지 않는다.
6. 빠른 연속 입력과 휠 관성이 한 번의 전환에서 여러 장을 건너뛰지 않는다.
7. 최초 안내는 두 장 이상일 때 한 번만 나타나며 약 2초 안에 사라진다.
8. 실제 스와이프 시 안내가 즉시 사라진다.
9. 마지막과 처음 사이를 여러 번 왕복해도 공유·메타·CTA가 현재 사진 ID를 사용한다.
