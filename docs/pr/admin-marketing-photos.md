# 마케팅 사용 가능 사진 — 동의 여부로 걸러 보는 지면

`/admin/marketing` (내비 「지면」 → 「마케팅 사용」)

## 왜

광고·SNS 에 쓸 사진을 고를 때 **"이 작가 사진 중 뭘 써도 되냐"** 를 물을 자리가 없었다.

동의는 **앨범(포트폴리오) 단위**인데 기존 화면은 전부 사진 그리드다.

- 「사진 내리기」 — 1,856장을 필터 없이 쏟아낸다. 동의 여부는 안 보인다
- 「타겟 카테고리」 — 동의를 보여주지만 그 카테고리 안에서만

그래서 쓸 때마다 앨범을 하나씩 열어 확인해야 했다.

## 무엇

| 축 | 값 |
|---|---|
| 동의 | 전체 / 사용 가능 / 사용 불가 |
| 작가 | 드롭다운 — 이름 옆에 `가능 559 / 불가 44` |
| 용도 | 개인·커플·웨딩·우정·행사·상업 |
| 무드 | 자동 분류 어휘 상위 24개 칩 |
| 검색 | 앨범·작가·무드 |
| 토글 | 내린 사진 포함 |

조건은 AND 로 묶고, 같은 종류의 여러 값은 OR 로 본다. 격자는 가능=초록 / 불가=빨강+라벨이고, 누르면 **왜 못 쓰는지**와 어느 앨범인지가 뜬다 — 그래야 작가에게 뭘 요청할지 알 수 있다.

작가 드롭다운에 가능/불가 수를 적은 게 이 화면의 핵심이다. "누구에게 동의를 더 받아야 하는가" 가 곧 운영의 다음 할 일이다.

판정 규칙은 `lib/marketing-photos` 한 곳에 둔다. 화면마다 다르게 판단하면 그 어긋남이 실제로 밖에 나가는 사진을 고른다.

## 판정에서 뺀 것

**`photographers.promo_consent`** — 컬럼은 있지만 **어디서도 쓰지 않는다.** 입점 동의 화면이 홍보 동의를 일부러 안 받는다(`AgreeGate.tsx`: "사진 속 인물의 초상권은 사진마다 사정이 달라서, 한 번에 묶는 것 자체가 위험하다"). 21명 전원 false 라, 게이트에 넣으면 **모든 사진이 사용 불가**가 된다.

**`feed_hidden`** (177장) — 운영이 피드에서 내린 것과 동의는 별개 사안이다. 표시만 하고 거르기는 운영이 고르게 둔다.

## 못 보는 것 (지면에 적어 둠)

피사체(회원)의 초상 사용 거부 `bookings.portrait_optout_at` 은 **예약 단위**인데 사진·앨범이 예약을 참조하지 않아 이어 붙일 수가 없다(현재 거부 0건). 없는 보증을 있는 것처럼 보이면 그게 더 위험해서 화면에 한계를 적었다. 제대로 잇는 건 스키마 작업이라 따로 잡아야 한다.
