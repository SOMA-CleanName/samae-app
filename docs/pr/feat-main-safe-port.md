## 왜 이 PR 이 있나

`dev` 가 `main` 보다 **149 커밋** 앞서 있는데, 그 대부분은 리드 판매를 폐지하고 채팅 상주·
에스크로로 갈아엎는 작업이라 **PG 계약 전에는 배포할 수 없다.** 배포하는 순간 작가가
연락처를 사는 현재의 수익 경로가 사라진다.

그런데 그 안에 두 가지가 섞여 있었다.

1. **결제·문의와 무관한 지면 자산** — 아티클·가이드 33편·촬영 장소 18곳·SEO·홈/탐색 재단장.
   순수 획득 자산이고 SEO 는 색인에 시간이 걸리므로 PG 를 기다리면 4주를 통째로 버린다.
2. **PG 심사에 필요한 법무 정비** — 사업자정보 표시·약관·개인정보 처리방침.
   **심사관은 samae.ai(=main)를 본다. dev 는 보지 않는다.** 4주 뒤로 미룰 수 없다.

이 PR 은 그 둘을 담는다. **문의·스튜디오·채팅은 한 파일도 건드리지 않았다.**

## 1. 법무 — PG 심사 요건

### 1-1. 사업자정보 표시

전자상거래법 제10조 + KG이니시스 요건(*"사이트 하단 사업자정보 확인 가능한 단계까지 구축"*).

```
상호 사매 · 대표 김정훈 · 사업자등록번호 827-70-00636
주소 인천광역시 연수구 인천타워대로 323, A동 31층 3101호 CS119호
이메일 samaephoto@gmail.com
```

값은 `lib/business-info` 한 곳. **비면 그 줄이 안 그려진다** — 전화번호(유심 대기)와
통신판매업 신고번호(PG 후)는 지금 빠져 있다.

푸터는 끝이 있는 지면에만 닿으므로 **홈·카테고리는 무한 피드 직전**에 따로 뒀다.
심사관이 유입 1위 지면에서 못 찾으면 거기서 걸린다.

> ⚠️ 검토 중 **주소에 호실(CS119호)이 빠져 있던 것**을 잡았다. 심사는 등록증과 대조하고,
> 한 칸이라도 다르면 반려된다.

### 1-2. 서비스 이용약관 — 신규 (18개 조)

**`/terms` 가 목차만 있는 껍데기인데 이미 돈을 받고 있었다.** 더 나쁜 것은,
가입 화면이 *"가입하면 서비스 이용약관에 동의하게 됩니다"* 라며 **존재하지 않는 약관에
동의시키고 있었다는 점이다.** 분쟁 시 회원이 무엇에 동의했는지 특정할 수 없다.

조문은 지어낸 것이 아니라 **코드가 실제로 하는 것을 옮긴 것**이다. 근거는
`docs/35-terms-draft.md` 의 `↳` 주석에 조별로 달았다. 핵심은 제4조 —

> 회사는 통신판매중개자이며 촬영 계약의 당사자가 아닙니다.
> **회사는 촬영비를 수령하거나 보관하지 않습니다.**

이게 사실인 근거: `settlements`(*"촬영비는 오프플랫폼이라 플랫폼이 보관/정산하지 않는다"*) ·
`bookings`(*"작가 계좌로 직접 송금"*) · `refund`(*"환불 금액도 작가가 직접 송금"*).
**지금 모델은 돈이 사매를 거치지 않는다.** 통신판매중개자 지위의 가장 강한 근거다.

무효가 될 조항을 미리 피했다 —
- 제16조 3항(고의·중과실 책임)을 남겼다. 사업자 책임을 전부 배제하면 약관규제법 제7조로
  무효고, 그러면 앞의 면책 조항까지 같이 흔들린다
- 제18조에 "회사 소재지 전속관할"을 쓰지 않았다. 소비자에게는 주소지 관할이 보장된다

시행일은 **게시일 + 7일**(2026-09-11). 부칙이 기존 회원에게 7일 사전 공지를 약속하고
이 지면 자체가 그 공지다. **머지가 9/4 보다 밀리면 두 날짜도 같이 밀어야 한다**(파일 상단 주석).

### 1-3. 개인정보 처리방침 — 8개 절 → 13개 절

법정 필수 항목이 여러 개 빠져 있었다. 가장 큰 것이 **개인정보 보호책임자**(제31조) —
성명·직책·연락처를 반드시 표시해야 하는데 문의처가 *"서비스 내 채팅 또는 운영 채널"* 뿐이었다.

새로 들어온 것: 보호책임자 · 국외 이전 · 파기 절차 · 권리 행사 방법 · 안전성 확보 조치 ·
권익침해 구제기관 · 수집 항목을 시점별로 분해 · 보유 기간을 항목별로.

**항목은 전부 실물에서 확인했다** — `profiles`·`inquiries`·`analytics_events`·
`persona_results` 컬럼을 직접 조회했고, 수탁자는 실제 import 를, 파기는 `soft-delete` 와
`deleteAccount` 를 근거로 썼다.

> 🔴 **초안에서 두 줄을 지웠다.** "접속 로그 1년 보관" 과 "페르소나 72시간 후 자동 만료" —
> 둘 다 그렇게 지우는 코드가 없다(전자는 어드민 수동 초기화만, 후자는 조회에서 빠질 뿐
> 행은 남는다). **지키지 않는 기간을 적으면 그 자체가 거짓 고지**고, 규제기관이 보는 건
> 방침이 아니라 실제 처리 실태다.

### 1-4. 가입 동의를 구분 동의로

문구 한 줄(묵시적 동의)에서 **필수 체크박스 2개**로. 카카오·이메일 **두 경로 모두** 가드를
걸었다 — 카카오가 주 경로라 한쪽만 막으면 의미가 없다.

`our-vibe`·`vintage-memories`·`natural-look` 등이 **지금 빈 페이지다.** 100개씩 끊어 조회한다.

## 3. 무엇을 뺐고, 왜

| | 이유 |
|---|---|
| 채팅·챗봇·에스크로·환불 v2 | 리드 판매 경로를 파괴한다 |
| 사진 상세의 **상담 트랙** | `/chat/start` 가 이 브랜치에 없다. [촬영 문의하기] 한 줄만 남겼다 |
| OTP 가입 마무리 · 알림 큐 | 리드 모델에선 문의 폼이 이미 연락처를 받아 중복. 발신번호도 없다 |
| **`/trust` 지면** | 에스크로·연락처 비공개(새 모델)를 설명 — 지금 운영과 어긋난다 |

### 🔴 지면이 거짓말을 할 뻔한 것 — 링크 6곳 + 문구 3곳

가져온 파일들이 `/trust` 를 걸고 있었고(SiteFooter·SiteLinksRow·ProfileSheet·탐색 판권면·
`/terms`·llms.txt), 더 나쁜 건 **새 모델의 약속을 그대로 적고 있었다는 것**이다.

```
SiteFooter · PartnerBadge   "결제는 사매 계좌로 받고, 연락처는 채팅 밖으로 나가지 않아요"
PartnerBadge                "직접 인터뷰하고 심사해 선별한 작가입니다"
/terms                      "촬영·결제·환불은 모두 그 기준으로 처리됩니다"  ← 가리킬 문서가 없어짐
```

전부 제거하거나 사실 범위로 낮췄다. 파트너 뱃지는 `approved_at` 이 보증하는 만큼만
남겼다(*"심사해 승인한"*) — 인터뷰 여부는 작가마다 다르고 기록에 없다.

> 뱃지 **조건은 건드리지 않았다.** 호출부가 `!isOwner` 만 보길래 모든 작가에게 붙는 줄
> 알았는데, 지면 노출 쿼리가 전부 `photographer.status='approved'` 필터를 거친다.
> 사진 상세에 도달했다는 것 자체가 승인된 작가라는 뜻이다. 그 불변식을 주석에 못박았다.

## 4. 검증

- `npx tsc --noEmit` · eslint · `npx next build` 통과 (76 페이지 프리렌더)
- 라우트 15개 스모크 **전부 200** — `/inquiry` 포함. 내부 링크 27개 전부 도달 가능
- 사이트맵 1,079 URL · `/trust` 없음 확인
- DB — 마이그레이션 0084~0108 이 프로덕션에 적용된 상태임을 직접 조회로 검증
- **[claude-for-legal](https://github.com/anthropics/claude-for-legal)(Anthropic 공식)의
  `product-legal/launch-review` 8카테고리로 정책 감사** → `docs/36-launch-legal-review.md`

### main 의 결정을 덮지 않은 것

**검색 UI 숨김을 유지한다.** dev 는 `home/results: true` 로 다시 켜 뒀지만, main 에는
dev 가 갈라진 뒤 들어온 `chore: 검색 UI 임시 숨김`(#301)이 있다. 그쪽이 더 최신이고
의도된 프로덕션 결정이라 main 판을 남겼다(테스트도 함께).

### 알려진 것

`editorial/Reveal.tsx`·`ProfileSheet.tsx`·`DetailHookCta.tsx` 의 react-hooks 경고는
**dev 에도 있는 것**이라 그대로 뒀다. 여기서 고치면 나중에 dev 를 머지할 때 충돌한다.
