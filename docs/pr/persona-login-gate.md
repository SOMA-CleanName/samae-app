# /event/persona — 분석 전에 로그인 · 하루 상한 · 한도 시 업로드 전환

## 왜

인스타에서 이벤트가 터지면서 **분석만 하고 나가는 사람**에게 비용이 그대로 나갔다.

```
10/5 22시 ~ 10/6 04시 (6시간) · 335건 (인스타 253 · 업로드 82)
시간당 최대 88건 · Anthropic $1.98/일 (건당 ~$0.006) · Apify 별도
```

비용을 가입자로 바꾼다 — **결과를 보려면 로그인.**

## 1. 로그인 게이트

- 검사를 **캐시 히트보다 앞에** 둔다. 뒤에 두면 "이미 분석된 아이디" 가 공짜 경로로 남고, 인기 아이디일수록 그대로 빠져나간다
- **업로드 경로도 같은 문지기.** 여기만 열면 "비공개 계정이라 사진을 올려보세요" 안내를 타고 그대로 우회된다
- 화면은 **누르기 전에** 알린다 — "카카오로 3초 로그인하면 바로 분석해드려요". 누른 뒤 막으면 분석되는 줄 알았다가 거절당한 것처럼 읽힌다
- 로그인하고 돌아오면 그 아이디로 **바로 이어서** 분석한다 (`?u=…&auto=1`, `safeNext` 로 오픈 리다이렉트 차단)
- 화면 검사는 헛걸음을 줄이는 것이고 **막는 건 서버 액션**이다. 분석을 부르는 네 곳 전부 게이트 뒤에 있다 — 제출 · 확인카드 탭 · 열화모드 · 업로드

**공유 링크(`/r/[id]`)는 공개로 둔다.** 저장된 결과를 꺼내 보는 것이라 비용이 0 이고, 그 링크가 이벤트의 유입 경로다. 잠그면 이벤트가 멈춘다.

## 2. 하루 상한 · 끄기 스위치

```bash
PERSONA_DAILY_CAP=300    # 비우거나 0 이면 무제한
PERSONA_ANALYSIS_OFF=1   # 새 분석만 멈춤. 캐시·공유 링크는 계속 열림
```

IP 레이트리밋(시간당 5)은 **한 사람**이 몰아치는 걸 막는다. 서로 다른 300명이 한 번씩 돌려도 비용은 똑같이 나가므로 **전체 합계**를 보는 상한이 따로 필요하다.

둘 다 **캐시 히트에는 적용하지 않는다** — 이미 분석된 결과를 꺼내 보는 건 비용이 0 이다.

고려한 것:
- 경계는 **한국 자정**. 서버 UTC 로 끊으면 상한이 한국 시간 오전 9시에 풀린다
- 설정 읽기는 느슨하게 — 숫자가 아니면 무제한. 오타 하나로 서비스가 통째로 막히는 쪽이 더 나쁘다
- 끄기 스위치는 **정확히 `1`** 일 때만. `true` 를 넣고 껐다고 믿는 게 제일 위험하다

## 3. Apify 한도 → 업로드 분석으로

무료 플랜이 거의 찼다(이번 주기 $4.11/$5). 소진되면 `run-sync` 가 402/403 을 뱉는데 지금은 일반 에러로 흘러 **"분석에 실패했어요"** 가 뜬다 — 로그인까지 한 사람에게 그 문구가 뜨는 게 최악이다.

402 · 403 · 429 를 `PersonaScrapeError("quota")` 로 던진다. 비공개 · 게시물없음과 **출구가 같다**(사진 직접 업로드), 그래서 실패가 아니라 다른 길로 보여준다:

> 지금 인스타 읽기가 잠시 막혔어요. 사진 3~5장 올리면 바로 분석해드릴게요.

업로드 fallback 버튼도 이 경우에 함께 뜬다.

## 4. 퍼널

이 repo 에 `/api/track` 은 없다 — Mixpanel(`mpTrack`)이다. 네 칸을 새로 남겼다.

| 이벤트 | 시점 | 속성 |
|---|---|---|
| `View Persona Page` | 지면 방문 | `signed_in`, `prefilled` |
| `Show Persona Login Gate` | 비로그인에게 안내 노출 | — |
| `Click Persona Login Gate` | 분석 누르고 로그인으로 | `method` |
| `Return From Persona Login` | 로그인하고 돌아와 자동 분석 | `method` |
| `Complete Persona Analysis` | 분석 완료 **(기존)** | `method`, `duration_ms`, `purpose_key`, … |

방문·노출은 ref 가드로 **한 번만** 쏜다. 리렌더마다 쏘면 분모가 부풀어 전환율이 거짓이 된다.

## 5. 분석 결과에 주인 (0143 · 원격 적용 완료)

로그인해야 분석되게 바뀌면서 비로소 **"누가 어떤 페르소나로 나왔는지"** 를 알 수 있게 됐다. 그 전에는 `username_hash` 뿐이라 역추적이 불가능했고, 분석만 하고 사라진 사람과 가입한 사람을 구분할 수 없었다.

`persona_results.profile_id` (nullable, `on delete set null`). 작가 추천·리타게팅과 "분석 → 문의" 전환을 사람 단위로 보는 데 쓴다.

**인스타 아이디 원본은 여전히 저장하지 않는다** — `username_hash` 는 그대로 해시고, 새로 들어가는 건 우리 서비스의 회원 id 뿐이다. 게이트 배포 이전 결과는 전부 null.

## 6. 늘 뜨던 장애 문구

```
전 · 지금 계정 미리보기가 원활하지 않아요. 아이디가 정확하다면 바로 분석할 수 있어요.
후 · 입력하신 아이디로 바로 분석할게요. 공개 계정인지 한 번만 확인해주세요.
```

계정 미리보기는 **프로덕션에서 거의 항상 꺼져 있다** — 인스타가 데이터센터 IP 를 막는다(`lookup.ts` 주석에 이미 적혀 있던 사실이고, 조회 캐시에 쌓인 아이디가 2건뿐인 것으로 확인했다). 평상시 상태를 장애처럼 말하고 있었고, 이벤트로 처음 온 사람에게는 서비스가 고장난 것처럼 보였다.
