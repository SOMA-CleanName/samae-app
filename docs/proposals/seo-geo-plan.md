목표: **"스냅 어디서 찍지" 를 검색하는 사람이 사매를 만나게 한다**

---

> ## 🔴 2026-09-17 점검 — **깔아 둔 게 하나도 동작하지 않고 있었다**
>
> 아래 P0~P3 는 거의 다 구현돼 있었다. 그런데 **운영 사이트가 통째로 크롤 차단**이라
> 그 전부가 아무에게도 안 읽히고 있었다. 실측:
>
> ```
> https://www.samae.ai/robots.txt
>   User-Agent: *
>   Disallow: /            ← 전체 차단. Sitemap 줄도 없음
> ```
>
> | 무엇 | 왜 | 어떻게 고쳤나 |
> |---|---|---|
> | **운영 robots.txt 가 전체 차단** | `robots.ts` 가 `if (!isProd) 전부 막기` 였고, 판정이 `VERCEL_ENV` 하나에 걸려 있었다. Vercel 의 시스템 환경변수 자동 주입이 꺼져 있으면 그 값이 안 들어오고 `APP_ENV` 가 "development" 로 떨어진다. **에러 없이 조용히** 사이트가 사라진다 | 기본값을 뒤집었다 — **비프로덕션이라고 확신할 때만** 막는다. 판정에 `NODE_ENV` 를 함께 본다(`next build` 는 Vercel 변수와 무관하게 항상 production). 프리뷰는 Vercel 이 배포 보호 + `X-Robots-Tag: noindex` 로 이미 막는다 |
> | **sitemap 1078개 URL 이 전부 리다이렉트** | `SITE_URL` 이 apex(`samae.ai`)인데 사이트는 `www` 로 서빙된다(apex → 308 → www). canonical·OG·robots host 까지 전부 apex 를 가리켰다 | `SITE_URL` 을 `https://www.samae.ai` 로. www 를 정본으로 둔 이유는 카카오 간편가입 약관 URL 이 이미 www 로 심사를 통과했기 때문 |
> | **공개 사진의 44% 가 sitemap 에서 누락** | `.limit(5000)` 이 안 먹는다. PostgREST 가 요청당 1000행으로 자르고 그 상한이 우선한다. 공개 사진 1779장 중 **정확히 1000장만** 실려 있었다. 잘린 티가 안 나서 몇 달을 몰랐다 | `range()` 페이지네이션. 작가 페이지도 사진 목록에서 역산하던 걸 작가 표에서 직접 뽑게 바꿨다(17명 중 11명만 실려 있었다) |
>
> 결과: sitemap **1078 → 1859 URL**, 사진 1000 → 1779, 작가 11 → 13(공개 사진이 있는 작가).
>
> ### 그 뒤 — 검색등록과 2차 점검 (같은 날)
>
> **구글 완료.** 서치콘솔 **도메인 속성** `samae.ai` 로 등록(apex·www·http·https 를 한 번에
> 덮는다). 소유확인은 Cloudflare Domain Connect 일회성 승인 — TXT 한 줄만 추가되고 지속
> 권한은 주지 않는다(기존 Zoho 인증·SPF 무사). sitemap 제출 → **상태 "성공" · 발견된 페이지 1,859.**
>
> > 제출 직후엔 "가져올 수 없음" 이었다. URL 검사가 원인을 보여줬다 —
> > **"색인이 생성되었으나 robots.txt에 의해 차단됨"**. 구글이 옛 `Disallow: /` 를 들고 있어
> > 홈이 *내용 없이 URL 만* 색인된 상태였다. 색인 생성 요청이 robots 재수집을 같이 당겨
> > 몇 분 만에 풀렸다. (서치콘솔의 robots.txt 리포트는 새 속성이라 아직 비어 있어서
> > **"robots.txt 파일 없음" 으로 보였다 — 그 화면만 보고 판단하면 안 된다.**)
>
> **네이버**는 소유확인까지 완료(메타 태그 · `NEXT_PUBLIC_NAVER_SITE_VERIFICATION`).
> ⬜ **사이트맵 제출은 남아 있다** — 네이버는 구글과 달리 robots.txt 의 `Sitemap:` 줄만
> 보고 긁지 않는다. 등록·제출을 해야 한다.
>
> ### 2차 점검에서 더 나온 것
>
> | 무엇 | 왜 |
> |---|---|
> | **`/guide/{slug}` 14개가 전부 404** | `generateStaticParams` 가 슬러그를 미리 `encodeURIComponent` 해서 넘겼다. 거기 돌려주는 값은 원본이어야 하고 인코딩은 Next 가 한다. 이중 인코딩된 경로로 프리렌더되면서 **`notFound()` 가 404 페이지로 구워졌다.** 허브가 거는 링크 14개가 전부 죽어 있었고, sitemap 에도 실려 구글이 그대로 긁어갔고, llms.txt 는 AI 에게 `/guide/{slug}` 를 **가장 먼저** 읽으라고 안내하고 있었다 |
> | **og:image 가 4개 지면에서 누락** | `app/opengraph-image.png` 는 하위로 내려가지만 페이지가 `openGraph` 를 직접 정의하면 끊긴다. 제목·설명은 잘 나가고 이미지만 빠져 화면으로는 티가 안 난다. 하필 밖에 뿌리는 지면 넷(`guide`·`spots`·`explore`·`c`)이 그랬다 |
> | **`/c/{slug}` 구조화 데이터 0** | 성격이 같은 `/explore/{slug}` 는 CollectionPage 를 심는데 이쪽만 비어 있었다 |
> | llms.txt 의 `사이트:` 가 apex | AI 가 인용할 때 리다이렉트 주소를 남기게 된다 |
> | robots 에 네이버 **Yeti** 미명시 | `*` 로 허용되지만 조이는 순간 조용히 빠진다 (AI 크롤러를 명시한 것과 같은 이유) |
>
> **공통점 — 셋 다 빌드도 통과하고 에러도 안 난다.** 404 가 조용히 구워지고, 메타 한 줄이
> 조용히 빠진다. 그래서 `decodeSlug` 에 회귀 테스트를 붙였다(6건).
>
> ### 2차 점검에서 **이상 없던 것**
>
> - sitemap 1,859개 — 유형별 표본 전부 200 (guide 는 14개 전수 200)

>   고 꼽은 항목이 실제로 나가고 있다
> - JSON-LD 8개 지면 전부: `Organization`·`WebSite`·`FAQPage`·`Article`·`Place`·
>   `CollectionPage`·`ItemList`·`ImageObject`·`BreadcrumbList`
> - canonical·description·og:title 전 지면 완비
> - AI 크롤러 6종 robots 허용 살아 있음, `llms.txt` 정상 서빙
> - `AggregateRating` 은 **일부러 없다** — 후기가 0건이라 넣으면 스팸 판정이다(§P1 주석)
>
> ### 아직 남은 것
>
> - ⬜ **네이버 사이트맵 제출** (위)
> - ⬜ `feed_hidden` 사진(운영이 피드에서 내린 18장)이 sitemap 에 그대로 있다. 피드에서만
>   내린 것이라 `/photos/{id}` 는 공개지만, **이제 구글이 실제로 긁어가므로** 검색에도 뜬다.
>   뺄지 말지는 운영 판단
> - ⬜ 로컬 `.env.local` 에 `NEXT_PUBLIC_SUPABASE_ANON_KEY` 누락 — `createPublicClient()` 가

>   이번 404 를 로컬에서 재현하지 못한 이유이기도 하다
> - ⬜ Vercel 시스템 환경변수 자동 주입이 꺼져 있는 이유 미확인. robots 는 더 이상 거기
>   의존하지 않지만, `VERCEL_ENV` 를 쓰는 코드가 생기면 같은 사고가 난다
>

### 인프라는 이미 있다

```
**기본기가 없어서 안 뜨는 게 아니다.** 아래 두 가지가 문제다.

### ① 검색 결과에 사매가 없다
`samae.ai 사매 사진작가 매칭` 으로 검색하면 SAM(Segment Anything Model) 같은 무관한 결과만 나온다.
`.ai` 도메인이라 AI 관련 결과에 묻힌다.

### ② ⭐ 그런데 진짜 발견은 이것이다 — **경쟁 상대가 플랫폼이 아니다**

`스냅사진 촬영 장소 추천 서울 작가 예약` 검색 시 AI 답변이 인용한 출처:
```
블로그(thelife.marketing) · 마이리얼트립 상품페이지 · 아워플레이스 · 순위닷
```
**스냅퍼·필름커넥트·올스냅 — 매칭 플랫폼이 하나도 없다.**

즉 **"어디서 찍지" 질문은 플랫폼이 아니라 콘텐츠가 먹는다.**
여기서 우리 경쟁 상대는 스냅퍼가 아니라 블로그다. 그리고 이건 **이길 수 있는 싸움**이다:

> 블로그는 "경복궁 예뻐요"라고 쓴다.
> 사매는 **그 장소에서 실제로 찍힌 사진 + 찍은 작가 + 실제 패키지 가격**을 붙일 수 있다.
> AI 입장에서 인용하기 더 좋은 페이지다.

**전략: 헤드 키워드("스냅사진") 정면 승부를 피하고, 장소·상황 롱테일로 들어간다.**
올스냅은 2016년부터 쌓았다. 정면 승부는 시간 싸움이고 우리가 진다.

## 2. 작업 목록

### P0 — 색인·크롤 기반 (1~2일 · 효과 즉시)

#### 2-1. `/explore/[slug]` 26개가 sitemap 에서 빠져 있다 🚨
현재 sitemap 수록 대상:
```
정적 2개 · /c/[slug] (타겟 카테고리 4개) · /photographers/[id] · /photos/[id]
```
**`explore_categories` 26개(무드 5 + 기타 21)가 통째로 빠졌다.**
무드·장면별 큐레이션이라 **SEO 가치가 가장 높은 페이지인데 색인 대상이 아니다.**

- [ ] `sitemap.ts` 에 `/explore/[slug]` 추가 (`published = true` 만)
- [ ] `changeFrequency: "weekly"`, `priority: 0.8` — `/c/` 보다 높게

#### 2-2. AI 크롤러 명시 허용
현재 `userAgent: "*"` 라 막히진 않았으나, 명시해두면 정책이 문서로 남고 오설정 사고를 막는다.

- [ ] `robots.ts` 에 `GPTBot` · `PerplexityBot` · `ClaudeBot` · `Google-Extended` · `CCBot` 규칙 명시
- [ ] 차단 경로는 `*` 와 동일하게 유지 (거래·관리 경로는 AI 에게도 안 보여준다)

#### 2-3. `llms.txt` 추가
AI 크롤러용 요약 파일. 사이트가 무엇이고 어떤 페이지가 인용할 만한지 알려준다.

- [ ] `/public/llms.txt` — 서비스 한 줄 정의 · 주요 섹션 · 인용 시 표기 요청
- [ ] 작가 실명·연락처는 넣지 않는다 (익명 정책)

#### 2-4. Search Console · 네이버 서치어드바이저 등록
- [ ] 사이트 소유 확인 + sitemap 제출
- [ ] 색인 요청 (주요 20~30 URL)
- [ ] **네이버를 빼지 말 것** — 한국 스냅 검색은 네이버 비중이 크다

### P3 — FAQ 허브 (3~5일 · GEO 가성비 최고)

AI 답변은 **질문-답 쌍**을 가장 잘 인용한다. 그리고 우리에겐 이미 재료가 있다:
```
src/lib/bot-kb-data.ts    챗봇 지식베이스
스레드 재고 59편           전부 "질문형 제목 + 답" 구조다
```
스레드 원고 제목이 그대로 FAQ 질문이다 — `채도를 낮추면 왜 고급스럽다고 느끼나?`,
`촬영 시간이 대부분 1시간 30분 언저리인 이유`, `레퍼런스는 몇 장 보내야 하나?`

- [ ] `/guide/[slug]` 또는 `/faq` — 카테고리별 질문 묶음
- [ ] `FAQPage` JSON-LD
- [ ] **스레드 통과분을 웹 콘텐츠로 재활용** — 이미 QC(사실 검증·화자)를 통과한 글이다
- [ ] ⚠️ 스레드 원고는 화자가 "플랫폼 관찰자" 존댓말이다. 웹은 톤을 맞춰 다듬을 것

## 3. 무엇을 성공으로 볼 것인가

**순위를 목표로 잡지 않는다.** 신규 도메인은 순위가 늦게 움직여서 판단이 흐려진다.

| 시점 | 확인할 것 | 기준 |
|---|---|---|
| 1주 | Search Console 색인 페이지 수 | **0 → 100+** |
| 2~4주 | AI 검색에서 사매 인용 여부 | ChatGPT·Perplexity·구글 AI에 `성수 스냅 촬영 장소` 등 직접 질의 |
| 4~8주 | 검색 유입 세션 | Mixpanel `utm_source=organic` 또는 referrer 기준 |
| 8주+ | 롱테일 순위 | `[장소]+스냅` 조합 10개 표본 |

⚠️ **2번을 사람이 직접 질의해서 확인해야 한다.** AI 인용은 Search Console 에 안 잡힌다.

| 항목 | 내용 | 결정권 |

## 5. 실행 순서

```
P0 색인 기반      1~2일   ← 여기 없으면 나머지가 무의미
P1 구조화 데이터   3~5일
P3 FAQ 허브       3~5일   ← 스레드 재고 재활용이라 원고 비용 0
P2 장소 페이지     1~2주   ← 이 기획의 본체. 앞의 셋이 깔린 뒤에
```

**P0 → P1 → P3 → P2 순을 권한다.** P2 가 본체지만 색인·구조화가 없으면 만들어도 안 읽힌다.
P3 를 P2 앞에 두는 건 **원고가 이미 있어서 가장 싸기 때문**이다.
