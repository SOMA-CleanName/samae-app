# SEO · GEO 기획서 — 검색과 AI 답변에 사매를 올리기

작성 2026-08-31 · 대상: `samae.ai` 공개 영역
목표: **"스냅 어디서 찍지" 를 검색하는 사람이 사매를 만나게 한다**

---

## 0. 먼저 — 지금 어디에 서 있나

### 인프라는 이미 있다
```
src/app/robots.ts        운영만 허용 · 거래·관리 경로 차단        ✅
src/app/sitemap.ts       DB 기반 자동 생성 (하루 1회)             ✅
src/lib/seo.ts           페이지별 동적 메타데이터 + JSON-LD 빌더    ✅
src/components/JsonLd.tsx                                        ✅
```
**기본기가 없어서 안 뜨는 게 아니다.** 아래 두 가지가 문제다.

### ① 검색 결과에 사매가 없다
`samae.ai 사매 사진작가 매칭` 으로 검색하면 SAM(Segment Anything Model) 같은 무관한 결과만 나온다.
`.ai` 도메인이라 AI 관련 결과에 묻힌다.

### ② ⭐ 그런데 진짜 발견은 이것이다 — **경쟁 상대가 플랫폼이 아니다**

`스냅사진 촬영 장소 추천 서울 작가 예약` 검색 시 AI 답변이 인용한 출처:
```
블로그(thelife.marketing) · 마이리얼트립 상품페이지 · 아워플레이스 · 순위닷
```
**스냅퍼·필름커넥트·올스냅 — 매칭 플랫폼이 하나도 없다.**

즉 **"어디서 찍지" 질문은 플랫폼이 아니라 콘텐츠가 먹는다.**
여기서 우리 경쟁 상대는 스냅퍼가 아니라 블로그다. 그리고 이건 **이길 수 있는 싸움**이다:

> 블로그는 "경복궁 예뻐요"라고 쓴다.
> 사매는 **그 장소에서 실제로 찍힌 사진 + 찍은 작가 + 실제 패키지 가격**을 붙일 수 있다.
> AI 입장에서 인용하기 더 좋은 페이지다.

**전략: 헤드 키워드("스냅사진") 정면 승부를 피하고, 장소·상황 롱테일로 들어간다.**
올스냅은 2016년부터 쌓았다. 정면 승부는 시간 싸움이고 우리가 진다.

## 1. 시간 — 즉각 효과는 없다. 갈래가 다르다

| 갈래 | 체감까지 | 이유 |
|---|---|---|
| **GEO** (AI 답변 인용) | **2~6주** | 백링크 권위보다 **구조화된 사실 텍스트**를 본다. 도메인 나이 영향이 작다 |
| **롱테일 SEO** (장소·상황) | 1~3개월 | 경쟁이 블로그 수준이라 진입 가능 |
| **헤드 SEO** ("스냅사진") | 6개월~1년+ | 지금 하면 시간만 태운다. ①②의 결과로 따라온다 |

**모든 갈래의 전제는 색인이다.** 색인이 안 되면 AI도 인용할 수 없다 → §2가 0순위인 이유.

## 2. 작업 목록

### P0 — 색인·크롤 기반 (1~2일 · 효과 즉시)

#### 2-1. `/explore/[slug]` 26개가 sitemap 에서 빠져 있다 🚨
현재 sitemap 수록 대상:
```
정적 2개 · /c/[slug] (타겟 카테고리 4개) · /photographers/[id] · /photos/[id]
```
**`explore_categories` 26개(무드 5 + 기타 21)가 통째로 빠졌다.**
무드·장면별 큐레이션이라 **SEO 가치가 가장 높은 페이지인데 색인 대상이 아니다.**

- [ ] `sitemap.ts` 에 `/explore/[slug]` 추가 (`published = true` 만)
- [ ] `changeFrequency: "weekly"`, `priority: 0.8` — `/c/` 보다 높게

#### 2-2. AI 크롤러 명시 허용
현재 `userAgent: "*"` 라 막히진 않았으나, 명시해두면 정책이 문서로 남고 오설정 사고를 막는다.

- [ ] `robots.ts` 에 `GPTBot` · `PerplexityBot` · `ClaudeBot` · `Google-Extended` · `CCBot` 규칙 명시
- [ ] 차단 경로는 `*` 와 동일하게 유지 (거래·관리 경로는 AI 에게도 안 보여준다)

#### 2-3. `llms.txt` 추가
AI 크롤러용 요약 파일. 사이트가 무엇이고 어떤 페이지가 인용할 만한지 알려준다.

- [ ] `/public/llms.txt` — 서비스 한 줄 정의 · 주요 섹션 · 인용 시 표기 요청
- [ ] 작가 실명·연락처는 넣지 않는다 (익명 정책)

#### 2-4. Search Console · 네이버 서치어드바이저 등록
- [ ] 사이트 소유 확인 + sitemap 제출
- [ ] 색인 요청 (주요 20~30 URL)
- [ ] **네이버를 빼지 말 것** — 한국 스냅 검색은 네이버 비중이 크다

---

### P1 — 구조화 데이터 확대 (3~5일 · GEO 직결)

현재 JSON-LD 는 **3종뿐**이다: `Organization` · `WebSite` · `ImageObject`
`FAQPage`·`Product`·`Review` 가 없어서 **AI 가 인용할 사실 단위가 없다.**

| 페이지 | 추가할 타입 | 왜 |
|---|---|---|
| `/photographers/[id]` | `ProfilePage` + `Service` + `AggregateRating` | 후기·평점이 DB 에 있다(`reviews`). 안 쓰고 있다 |
| 패키지 | `Product` + `Offer`(가격·통화) | `packages` 에 가격이 있다. **가격은 AI 답변에 가장 잘 인용된다** |
| `/explore/[slug]`·`/c/[slug]` | `CollectionPage` + `ItemList` | 목록 페이지임을 알려야 개별 사진이 함께 노출된다 |
| **신규 FAQ** | `FAQPage` | **AI 인용률이 가장 높은 타입.** §3 참고 |
| 전 페이지 | `BreadcrumbList` | 사이트 구조를 이해시킨다 |
| `/photos/[id]` | `ImageObject` 에 `contentLocation`(Place) 추가 | 장소를 사실로 만든다 |

- [ ] `lib/seo.ts` 에 위 빌더 추가
- [ ] `AggregateRating` 은 **후기 3건 이상일 때만** 출력 (적으면 스팸 판정)

> ⚠️ **익명 정책과 충돌 지점.** 현재 `creator: { name: "사진작가" }` 로 실명을 가린다.
> 검색 신뢰도(E-E-A-T)에는 불리하다. 실명 대신 **작가 활동명**이라도 넣을 수 있는지 정책 판단이 필요하다.
> 판단 전까지는 현행 유지.

### P2 — ⭐ 장소 페이지 신설 (1~2주 · 이 기획의 핵심)

**`/spots/[slug]`** 를 만든다. 지금 사매에 없는 라우트다.

#### 재료가 이미 있다
```
공장/spots-data.mjs      을지로·경복궁·서울숲·성수 등 10곳
                         area · detail(주소·역 출구) · desc · tip · verified 플래그까지
photos.region            필터용 지역
photos.location_text     장소 텍스트
photographers.regions    작가 활동 지역
```
`spots-data.mjs` 를 인스타 카드뉴스에만 쓰고 **웹 페이지로 안 만들고 있는 게 낭비다.**

#### 페이지 구성 (블로그가 못 하는 것만 넣는다)
```
① 장소 소개        spots-data 의 desc · tip · 주소 · 가장 가까운 역
② 여기서 찍힌 사진   photos WHERE region/location_text 매칭 → 실물 결과
③ 여기서 찍는 작가   ②의 사진 작가 목록 → 프로필 링크
④ 대략의 비용       ③ 작가들의 패키지 최저가 범위
⑤ 촬영 팁          골든아워·입장료·주차 등 (spots-data.tip)
⑥ FAQ             "예약은 며칠 전에?" "우천 시?" "한복 대여는?"
```
**②③④가 블로그에 없는 것이다.** 이것 때문에 AI 가 우리를 인용한다.

- [ ] `/spots` 목록 + `/spots/[slug]` 상세
- [ ] `Place` + `FAQPage` + `ItemList` JSON-LD
- [ ] sitemap 등록
- [ ] `spots-data.mjs` → DB 또는 앱 내 상수로 이관 (공장과 앱이 같은 원본을 보게)

> ⚠️ `spots-data.mjs` 에 `verified: false` 항목이 있다(서울숲 등).
> **팩트체크 안 된 정보를 웹에 올리면 SEO 가 아니라 리스크다.** `verified: true` 만 먼저 낸다.

---

### P3 — FAQ 허브 (3~5일 · GEO 가성비 최고)

AI 답변은 **질문-답 쌍**을 가장 잘 인용한다. 그리고 우리에겐 이미 재료가 있다:
```
src/lib/bot-kb-data.ts    챗봇 지식베이스
스레드 재고 59편           전부 "질문형 제목 + 답" 구조다
```
스레드 원고 제목이 그대로 FAQ 질문이다 — `채도를 낮추면 왜 고급스럽다고 느끼나?`,
`촬영 시간이 대부분 1시간 30분 언저리인 이유`, `레퍼런스는 몇 장 보내야 하나?`

- [ ] `/guide/[slug]` 또는 `/faq` — 카테고리별 질문 묶음
- [ ] `FAQPage` JSON-LD
- [ ] **스레드 통과분을 웹 콘텐츠로 재활용** — 이미 QC(사실 검증·화자)를 통과한 글이다
- [ ] ⚠️ 스레드 원고는 화자가 "플랫폼 관찰자" 존댓말이다. 웹은 톤을 맞춰 다듬을 것

## 3. 무엇을 성공으로 볼 것인가

**순위를 목표로 잡지 않는다.** 신규 도메인은 순위가 늦게 움직여서 판단이 흐려진다.

| 시점 | 확인할 것 | 기준 |
|---|---|---|
| 1주 | Search Console 색인 페이지 수 | **0 → 100+** |
| 2~4주 | AI 검색에서 사매 인용 여부 | ChatGPT·Perplexity·구글 AI에 `성수 스냅 촬영 장소` 등 직접 질의 |
| 4~8주 | 검색 유입 세션 | Mixpanel `utm_source=organic` 또는 referrer 기준 |
| 8주+ | 롱테일 순위 | `[장소]+스냅` 조합 10개 표본 |

⚠️ **2번을 사람이 직접 질의해서 확인해야 한다.** AI 인용은 Search Console 에 안 잡힌다.

## 4. 리스크 · 판단 필요

| 항목 | 내용 | 결정권 |
|---|---|---|
| **작가 익명 정책** | 실명 없이는 E-E-A-T 가 약하다. 활동명이라도 노출할지 | 정훈 |
| **`verified:false` 장소** | 팩트체크 전 발행 금지. 누가 검증하나 | 정훈 |
| **사진 저작권** | 장소 페이지에 사진을 쓰려면 `ad_consent` 범위 확인 필요 | 정훈 |
| **`.ai` 도메인** | 검색에서 AI 관련 결과에 묻힌다. 브랜드 검색 개선이 어렵다 | 장기 과제 |
| 중복 콘텐츠 | `/c/[slug]` 와 `/explore/[slug]` 가 겹칠 수 있음 → canonical 정리 | 개발 |

## 5. 실행 순서

```
P0 색인 기반      1~2일   ← 여기 없으면 나머지가 무의미
P1 구조화 데이터   3~5일
P3 FAQ 허브       3~5일   ← 스레드 재고 재활용이라 원고 비용 0
P2 장소 페이지     1~2주   ← 이 기획의 본체. 앞의 셋이 깔린 뒤에
```

**P0 → P1 → P3 → P2 순을 권한다.** P2 가 본체지만 색인·구조화가 없으면 만들어도 안 읽힌다.
P3 를 P2 앞에 두는 건 **원고가 이미 있어서 가장 싸기 때문**이다.
