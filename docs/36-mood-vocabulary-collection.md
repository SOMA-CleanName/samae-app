## 0. 전체 깔때기 — 5,176개가 어디서 나왔나

사전 전체가 아니라 **좁혀 온 것**이다. 어디서 얼마나 떨어져 나갔는지 남겨 둔다.

| 단계 | 개수 | 어디서 |
|---|---:|---|
| 사전에서 수집한 후보 | **64,737** | `collection.json` — §2 |
| → 수식어도 무드 범주도 아니라 제외 | −39,847 | `build_mood_priority_pool.py` |
| → 뜻풀이가 없어 제외 | −12,812 | 〃 |
| → 파일럿 500개에서 이미 판단 | −500 | `classification-v2.json` — §6-3 |
| **우선 풀 — 전량 판정한 것** | **11,578** | `priority-pool.json` |
| ├ N (무드 아님) | 6,402 | |
| └ **Y (무드)** | **5,176** | `accepted-screen-priority.json` |

**걸러 낸 기준** (`build_mood_priority_pool.py`)

1. **이미 판단함** — 파일럿 500개. 이번 판정과 아직 합치지 않았다
2. **뜻풀이 없음** — 사전에 표제어만 있고 정의가 없는 항목. **무드가 아니라서 뺀 게 아니라 판단할 근거가 없어서 뺐다**
3. **수식어도 무드 범주도 아님** — 품사가 수식어(형용사·부사·관형사…)도 아니고 의미범주가 무드 범주(모양·색깔·감정·기상…)도 아닌 것. 가장 큰 덩어리다

### "최종"이라는 말이 걸리는 데

**무드 여부 판정은 최종이다.** 11,578개 전부 갈렸고 보류 0개이며 낱말마다 근거가 붙어 있다.

**무드 어휘 전체로는 아직 아니다.** 두 가지가 열려 있다.

- **뜻풀이 없음 12,812개** — 판단 근거가 없어 뺀 것이라 이 안에 쓸 만한 게 있는지 모른다 (§12)
- **파일럿 500개** — 따로 판정돼 있고 이번 결과와 병합하지 않았다 (§12)

그리고 5,176개는 **축이 안 붙은 상태**다. 검색이나 태그로 쓰려면 11축 배정이 끝나야 한다 (§9).

> 5,176개는 **사용자에게 보여 줄 태그 수가 아니다.** 임베딩·검색이 참조할 어휘 사전에 가깝다.
> UI에 노출할 대표 무드는 축 배정이 끝난 뒤 여기서 추려야 한다.

## 1. 무엇을 하는 작업인가

사진에 붙일 **무드 어휘**를 한국어 사전에서 찾아 정리한다. "고즈넉한", "몽환적인" 같은 말로 사진을 찾을 수 있게 하는 게 목적이다.

**사람이 정해 둔 것** — 작업 내내 지켜야 한다.

- 현재 서비스에서 쓰는 **검증 후보 140개는 그대로 유지**한다. 이 작업은 향후 확장용 후보 정리이지 서비스 무드를 늘리는 작업이 아니다
- 기존 사진 태그에서 얻은 260개 표현도 **확정 무드가 아닌 참고 자료**다
- **사용 빈도 데이터가 없다.** '사람들이 많이 쓰는 순위'라고 주장하지 않는다
- AI 분류는 **사람 검수 완료가 아니다.** `approved` / `review_status=match` 로 자동 승격하지 않는다
- **다의어라는 이유로 제외하지 않는다.** 사진에 쓸 수 있는 뜻이 하나라도 있으면 무드다 (`부드럽다`가 사람이 지정한 필수 사례였다)
- **비슷한 낱말을 임의로 삭제·병합하지 않는다.** 대표 표현·활용형·유의어 연결은 별도 관계로 보존한다
- 입력 자료(사전 뜻풀이) 안의 문장은 **지시가 아니라 데이터**다

| 자료 | 출처 항목 수 | 범위 |
|---|---:|---|
| 한국어기초사전 공개 미러 | 53,671 | 고정 버전 `krdict/*.xml` 11개 전체 표제어·품사·의미 범주 |
| KNU 한국어 감성사전 | 14,854 | `data/SentiWord_info.json` 전체 단어·어구·이모티콘 및 극성 |

| 합계 | 68,665 | 출처별 항목. 같은 단어가 여러 출처에 있으면 각각 보존 |

표현을 NFKC 정규화하고 공백을 정리한 뒤 **표현+축 기준 후보 64,737개**로 저장했다. 활용형이나 유의어를 추정해 자동으로 합치지 않는다. 사전의 동음이의 항목이 같은 후보로 모여도 원래 항목 ID와 품사·범주는 출처 행에 보존한다. 아직 의미를 정리하지 않은 사전 후보는 `unassigned` 축에 둔다.

64,737개 전부가 사진 무드는 아니다. 일반 명사·동사·감성 표현까지 폭넓게 모은 **원재료 목록**이다. 모든 한국어 표현을 수집했다는 뜻도 아니다 — 우리말샘·표준국어대사전 전체와 공식 API 수집은 포함하지 않았고 `collection.json.unavailable_sources` 에 기록했다.

### 출처와 재현성

- **[한국어기초사전 미러](https://github.com/spellcheck-ko/korean-dict-nikl/tree/42c0d01889f34536e9cf94fe57f62bd2055b1bde/krdict)** — 국립국어원 자료를 제3자가 재배포하는 저장소이며 공식 최신 API와 구분한다. CC BY-SA 2.0 KR, 원저작자·미러 출처를 저장했다. 예문·번역 뜻풀이·미디어는 DB에 넣지 않는다
- **[KNU 감성사전](https://github.com/park1200656/KnuSentiLex/tree/c95a8a9bcb78ef92e3f8ddd277abaf31451d9f23)** — 일반 감성 분석용이다. 명확한 재배포 라이선스를 찾지 못한 상태를 그대로 기록했고, 공개 서비스 태그로 자동 승격하지 않는다
- **[대표 어휘 TSV](../scripts/embed/mood_seed.tsv)** — 프로젝트 작성·AI 보조 초안. 공개 사용 빈도 근거는 없다

수집기는 저장소 버전을 고정하고 파일 SHA-256을 남긴다. 한국어기초사전은 Git blob SHA-1과 파일 크기도 확인한다. XML 번역 영역의 XML 1.0 금지 제어문자 7바이트는 **파싱할 때만** 제거했고 원본 캐시와 해시는 그대로다.

## 3. DB 구조와 저장 상태

[0119 마이그레이션](../supabase/migrations/0119_mood_vocabulary_research.sql)과 [0120](../supabase/migrations/0120_mood_lexical_classification.sql)이 실제 DB에 적용돼 있다.

| 테이블 | 역할 |
|---|---|
| `mood_sources` | 출처 URL·버전·이용 조건·원저작자·파일 해시 |
| `mood_candidates` | 표현·축·영어 프롬프트·선정 근거·검토 상태 |
| `mood_candidate_sources` | 원본 항목 ID와 후보 연결, 품사/범주/극성 등 출처 메타데이터 |
| `mood_candidate_classifications` | **후보당 1행.** `kind`, 단일 `axis`, `version`, `rule`, `evidence` |
| `mood_catalog` | 조회용 뷰. 편집 축이 있으면 우선하고 없을 때만 제안 축을 보여 준다 |
| `mood_validation_runs` / `_results` | 모델·사진 수·유사도 등 사진 검증 결과 |

일반 사용자·작가는 연구 테이블을 읽거나 수정할 수 없다. RLS를 켜고 서비스 역할에만 권한을 줬다. 기존 `photos.mood_tags`, `auto_mood_tags`, 목적·검수 컬럼은 변경하지 않는다. 연구 결과를 오전 6시 사진 태그 자동 부여에 연결하지 않았다.

재수집·재저장해도 키 충돌 시 중복을 추가하지 않고, 이미 승인/거절한 후보 상태를 초기화하지 않는다. 수집 결과와 검증 결과는 각각 한 트랜잭션으로 저장한다.

### ⚠ 이번 작업 결과는 DB에 넣지 않았다

`node scripts/store-mood-research.cjs classification --apply` 를 **실행하지 않았다.**

이 명령은 `mood_candidate_classifications` 를 후보 ID별로 덮어쓰며 **버전 역행을 막지 않는다.** v2를 그 경로로 넣으면 v1이 사라지고, 나중에 v1을 다시 넣으면 v2가 사라진다.

반영하려면 먼저 둘 중 하나가 필요하다.

1. **새 마이그레이션(0121)** — `mood_candidate_classifications` 에 `version` 을 포함한 복합키를 두거나 버전별 이력 테이블을 추가한다. **축이 11개가 된 것과 다축 허용도 여기서 함께 처리해야 한다** (현재 `axis` 는 단일 컬럼 + check 제약이고 축 10개만 들어 있다)
2. 또는 저장기에 **버전 역행 방지 가드**를 넣고 v2 전용 저장 경로를 만든다

`mood_catalog` 뷰는 원본 `axis != 'unassigned'` 를 우선하므로 **기존 편집 축 140개는 어느 쪽이든 영향받지 않는다.** 이 보호는 그대로 둔다.

## 4. 사진 검증 — 대표 140개

공개·호환 SigLIP2 임베딩 사진 **1,780장**으로 대표 140개를 비교했다. 검색 우선 상주 서버의 `/embed-text-backfill` 에 영어 프롬프트를 최대 8개씩 요청했고, 사진 벡터는 기존 DB 값을 재사용했다.

각 후보의 상위 6장을 뽑되 같은 포트폴리오는 최대 2장으로 제한해 **840개 후보-사진 결과**를 저장했다. 점수는 코사인 유사도이며 정확도나 확률이 아니다. **항상 상위 결과를 만드는 방식이므로 상위에 나왔다는 이유만으로 분류가 정확하다고 판단하지 않는다.**

16개 1위 결과를 표본으로 눈으로 확인했다. `몽환적인`·`다정한`·`청량한` 에는 의도에 맞는 사례가 있었지만, `눈부신` 1위는 눈부심을 보여 준다고 보기 어려웠다. `빈티지한` 과 `시크한` 은 같은 사진이 1위로 올라와 표현 간 구분도 확인이 필요하다. **이 관찰은 140개 전체의 정확도 평가가 아니다.** 모든 결과는 `review_status=pending`, 대표 후보는 `selection_status=shortlisted` 로 유지했다.

### 관리자 화면

`사진 목적&무드 → 무드`(`/admin/photo-purpose/mood`)에서 전체 후보·검증 후보·확정 무드·기존 사진 참고 어휘를 볼 수 있다. 단어 검색, 축 필터, 50개 단위 페이지 이동을 제공한다.

**기존 사진 참고 어휘**는 `visibility=published` 사진의 `mood_tags`·`auto_mood_tags` 에 있는 서로 다른 표현 수다. 종전 명칭 '실사용 무드'에서 이름을 바꿨다 — **확정 무드가 아니기 때문**이다. 수동·자동에 같은 태그가 있거나 한 배열에 중복돼도 한 사진은 한 번 센다.

## 5. v1 규칙 분류와 그 실패

전체 64,737개에 `mood-lexical-v1` 분류 제안을 저장해 뒀다. 사전 의미 범주와 명시적 표현 목록을 쓰는 **규칙 기반**이며, 뜻풀이를 읽은 결과가 아니다.

| 구분 | 개수 |
|---|---:|
| 무드 축으로 연결 (기존 140개 포함) | 2,032 |
| 일반 어휘 | 6,296 |
| 판단 보류 | 56,409 |
| 전체 | 64,737 |

**v1은 양쪽으로 틀렸다.**

- **뜻이 여러 개면 보류**해서 `부드럽다`·`따뜻하다`·`박명` 같은 핵심 표현을 놓쳤다 (보류율 87%)
- **사전 범주만 맞으면 무드로 넣어** `선배`·`의학계`·`속도전` 을 무드로 만들었다

그래서 **사전 뜻풀이를 직접 읽고 판단하는 방식(v2)** 으로 바꿨다. v1 결과(`classification.json`)는 비교용으로 그대로 보존한다.

## 6. v2 — 뜻풀이를 직접 읽는 방식으로 전환

### 6-1. 뜻풀이 확보

`extract_mood_dictionary.py` 에 `extract_senses()` 를 추가했다. 기존 `extract()` 는 그대로 둬서 `collection.json` 재현성을 보존한다. `Sense` 의 **직계** `feat[@att='definition']` 만 읽고 `SenseExample` 인용문·`Equivalent` 번역·미디어는 수집하지 않는다.

`build_mood_senses.py` 가 `collection.json` 에 기록된 sha256으로 캐시 XML 11개를 **먼저 검증한 뒤** 읽는다. 결과 `senses.json` (17.5MB):

| 항목 | 값 |
|---|---:|
| 파일 | 11 (sha256 전부 일치) |
| 사전 항목 | 56,555 |
| 뜻풀이 없는 항목 | **0** |
| sense(뜻) | 76,833 |

후보 64,737개 중 **51,909개(80.2%)** 가 뜻풀이와 연결된다. 나머지 12,828개는 KNU 전용 항목과 편집 시드 활용형(`포근한`, `몽환적인` 등)으로, **사전에 없으므로 뜻풀이를 만들어 내지 않았다.**

### 6-2. ⚠ 발견한 데이터 결함 — `entry_key` 중복 (미해결)

사전 XML은 **표제어와 그 관용구·속담에 같은 `LexicalEntry val` 을 재사용한다.**
예: `27500` = `가다` + `가도 오도 못하다` + `갈수록 태산` 등 8개 항목.

- `entry_key` **1,160개**가 둘 이상의 항목에 걸쳐 있고, 전체 56,555개 중 **2,884개가 충돌**한다
- 수집기는 `entries.set([source_id, entry_key])` 로 **마지막 항목만** 남겼다. `mood_candidate_sources` 의 기본키가 `(source_id, entry_key)` 라 DB에도 그대로 반영돼 있다
- 결과적으로 **후보 2,581개가 출처 행을 잃었다.** `가다`·`가난`·`가늠` 같은 기본 표제어가 포함된다

**우회한 방법:** `senses.json` 은 `entry_key → 항목 리스트` 로 보존하고, 후보와의 연결은 `(entry_key, 표제어)` 로 맞췄다. 저장된 출처 행이 있는 49,328건은 **전부 표제어가 일치**했고(불일치 0건), 행을 잃은 후보는 표제어로 복구해 `join: "label_recovered"` 로 표시했다.

**수집기·스키마 수정은 아직 안 했다.** §12에 남겨 둔다.

### 7-2. 어떻게 판단했나

파일럿과 같은 방식이다. **규칙 기반이 아니라 뜻풀이를 하나하나 읽고** 판단했다. 한 항목의 모든 sense를 보고, **그중 하나라도** 사진의 겉모습·분위기를 서술할 수 있으면 Y다.

**Y 기준** — 뜻풀이가 **사진에 찍혀 보이거나 사진에서 느껴지는 것**을 서술할 때

- 빛·색: `희끔하다`, `황금빛`, `어스름`, `광채`, `역광`
- 질감·형태: `보송보송하다`, `까끌까끌하다`, `울퉁불퉁`, `잘록하다`
- 날씨·계절·시간대: `소나기`, `늦가을`, `저녁노을`, `한여름`, `눈보라`
- 공간·지형: `들녘`, `골짜기`, `언덕길`, `막다른`
- 인물의 겉모습: `해쓱하다`, `우람하다`, `보조개`, `단아하다`
- 움직임의 모양: `하늘하늘`, `팔랑거리다`, `뉘엿뉘엿`
- **감정·정서·기분을 가리키는 낱말은 품사·태(態)를 가리지 않고 전부**: `근심`, `질투심`, `매료되다`, `화내다` — §7-5에서 바뀐 기준

**N 기준**

- 사물·기관·직업 등 **대상 명사** (`국화꽃`, `동창생`, `커뮤니티`) — 뜻풀이에 무드 낱말이 들어 있어도 N
- 문법 요소 (조사·수사·지시어·접속 부사·접사)
- **능력·인격·가치 판단** (`훌륭하다`, `정직하다`, `유능하다`)
- 순수 크기·비교 (`대등하다`, `비슷하다`, `최소한`)
- **몸속 감각** — 밖에서 안 보이는 것 (`메스껍다`, `시큰거리다`, `배고프다`)
- 사동·타동으로만 쓰이는 행위 동사 (`위축시키다`, `못질하다`)
- **소리** (`컹컹`, `따르릉`) — 단 `왁자지껄`, `웅성웅성`은 장면의 분위기를 서술하므로 Y
- ~~겉으로 드러나는 표현이 없는 내면 상태~~ — **이 기준은 폐기됐다.** §7-5

**일관성을 위해 고정한 판정 쌍**

| Y | N | 이유 |
|---|---|---|
| `씁쓰름하다` | `쌀쌀하다`, `찝찔하다` | 맛+감정 겹침은 Y, 몸 감각뿐이면 N |
| `왁자지껄하다` | `시끄럽다` | 전자는 장면 묘사, 후자는 소리 판단 |
| `고풍스럽다` | `오래되다`, `묵다` | 전자는 분위기, 후자는 경과 사실 |
| `휘황히`, `환히` | `후딱후딱` | 시각 상태 부사는 Y, 행동 속도 부사는 N |
| `빛나다` | `위축시키다` | 겉모습을 서술하지 않는 사동/타동은 N — 단 **감정 동사는 태를 가리지 않고 Y** |
| `검붉다` | `국화꽃`, `별` | 색 서술은 Y, 대상 명사는 N |
| `근심`, `질투심`, `화내다` | `아`, `어휴`, `-심` | 감정이면 Y, 감탄사·접사는 N |

### 7-5. 중간에 틀렸던 것 두 가지

**(1) 활용형 판정이 엇갈렸다**

전 구간을 마친 뒤 어간별로 묶어 훑어보니, **같은 어간의 활용형인데 Y/N을 다르게 준 그룹**이 나왔다. `오뚝`은 N인데 `오뚝하다`는 Y인 식이다. 11,578개를 78배치로 나눠 보다 보니 배치 사이에서 기준이 흔들린 것이다.

- 근거 문장까지 비슷한 **42개 그룹**을 `conflicts-42.txt` 로 뽑았고, 사람이 12개 그룹을 직접 지정하고 나머지는 추천을 따랐다 — **낱말 48개 변경**
- 이때 `집적` 그룹만 통일에서 뺐다. `집적`(集積)과 `집적거리다`(귀찮게 굴다)는 뜻이 다르다
- 남은 **209개 그룹(낱말 486개)** 은 `conflicts-209.txt` 로 다시 뽑아 **사람이 "전부 Y"로 결정** — **234개 변경**
- 결과적으로 **어간이 같은데 Y/N이 갈리는 그룹은 0개**다. 검사에 걸리는 `이상`/`넙적`/`지리` 세 쌍은 동형이의어라 정상이다

**(2) "속마음은 사진에 안 드러나니 N" 기준이 틀렸다**

처음에는 감정 낱말이라도 겉으로 드러나지 않으면 N으로 갈랐다. `설렘`·`씁쓸하다`는 Y, `이기심`·`복수심`·`호기심`은 N이었다.

(1)에서 사람이 지정한 12개 그룹이 **전부 감정 낱말이었고 전부 Y였다**. 그 결정이 기준 자체를 부정하는 것이라 판단해, 같은 성격의 N이 얼마나 되는지 세어(`인간 > 감정` N 840개) 보고했다. 답은 **"감정인건 예스여야 해서 840개 정도는 다시 보는 게 맞는 것 같다"** 였다.

840개 전량을 다시 읽었다 — **N → Y 767개, N 유지 73개.**

**바뀐 기준**: 뜻풀이가 감정·정서·기분을 가리키면 **품사도 태(態)도 가리지 않고 Y**. 피동(`매료되다`)·사동(`흥분시키다`)·행위 동사(`화내다`)도 포함한다.

**그래도 N으로 남긴 73개**

| 갈래 | 보기 |
|---|---|
| 감탄사 — 감정을 표현하지만 낱말이 아니라 소리 | `아`, `아이고`, `어휴`, `어머`, `앗`, `응`, `천만에` |
| 문법 요소 | `-심`, `-감`, `의`(조사), `그냥`, `설마`, `당연히`, `감히` |
| 양태·정도 부사 | `불현듯`, `부득불`, `불가불`, `의외로`, `만판`, `그런대로` |
| 감정이 아닌 인지·평가 | `육감`, `선입견`, `아이러니하다`, `동질성`, `만족도` |
| 외형 평가 계열 | `꼴불견`, `꼴사납다`, `꼴같잖다`, `눈꼴사납다` |
| 의례·제도·사물 명사 | `괘씸죄`, `경조`, `근조`, `책임`, `편리`, `만사`, `단지` |

### 축 설계에서 막혔던 것 — 넷 다 해결됨

**(1) "아름다움 일반"을 받는 축이 없었다 → 스타일로**

`아름답다`, `예쁘다`, `이쁘다`, `어여쁘다`, `아리땁다`, `곱상하다`, `잘생기다`, `미모`, `미감`, `미적`, `미`, `아름다움`, `매력`, `개성미`, `교양미` 15개를 보류로 뒀었다. 새 축을 만들지 / 스타일에 넣을지 / 제외할지를 물었고 **사람이 "스타일"로 결정**했다. 뒤에 `이상`·`이상적`·`이상형`(理想) 3개도 합류해 **총 18개**가 스타일로 간다.

파일럿 500개에 있던 같은 성격의 낱말(`수려하다`, `예쁘장하다`, `곱다랗다`)도 같은 처리를 받아야 일관된다 — `classification-v2.json` 쪽을 손볼 때 함께 반영할 것.

**(4) 날씨를 담을 축이 없었다 → 계절 축에 합침 (2026-09-16)**

축 배정 앞 100개에서 걸렸다. `폭우`를 `에너지`(쏟아지는 기세)와 `계절`(장맛비)에 억지로 나눠 담았는데 둘 다 근거가 약했다. **비·눈·구름 자체는 온도도 빛도 색감도 아니다.**

전체 2,647개에 뜻풀이까지 날씨인 대표가 **약 70개** 있다 — `비`·`가랑비`·`봄비`·`궂은비` / `눈`·`눈꽃`·`눈가루` / `먹구름`·`뭉게구름`·`비구름` / `봄바람`·`겨울바람`·`찬바람`·`돌개바람` / `번개`·`서리`·`안개`·`노을`·`햇볕`·`폭염`.

**사람이 계절 축에 합치기로 결정**했다. 축을 새로 만들지 않고 이름을 `계절·날씨` 로 넓혔다.

- **축 개수는 11개 그대로다.** §10 지시서·컴파일러·문서를 최소로 고치고 끝난다
- 날씨와 계절은 뿌리가 같다 — `봄비`·`겨울바람`·`가을볕`은 한 낱말에 둘이 붙어 있어 나눌 실익이 없다
- 여전히 **다축이다.** `폭염`은 `온도` + `계절·날씨`, `노을`은 `시간대` + `빛` + `계절·날씨` 가 될 수 있다

> **DB 쪽 숙제가 된다.** 0120 의 check 제약과 `mood_candidates.axis` 에는 `계절` 이 들어 있다.
> 0121 에서 `계절` → `계절·날씨` 이행을 함께 처리해야 한다. `/admin/photo-purpose/mood` 목록의 축 필터도 그때 같이 바꾼다 — 지금 바꾸면 DB 값과 어긋나 필터가 빈다.

**(2) 시간대 축이 없었다 → 축 신설**

파일럿 기준을 이어 `한밤`·`한밤중`·`조조`·`아침` 등을 N으로 처리했고, `새벽`·`황혼`·`해거름`·`저녁노을`처럼 **빛이 함께 서술된 것**만 Y로 넣었다. 그 결과 `밤`·`낮`·`저녁`·`오전`·`오후`·`야밤`은 Y인데 `한밤`·`아침`·`오밤중`은 N인 어긋남이 남아 있었다.

**사람이 시간대 축을 세우기로 결정**해 이 어긋남을 풀었다. 축은 10개에서 **11개**가 된다.

| | |
|---|---|
| 이미 Y라 그대로 | 밤, 낮, 저녁, 오전, 오후, 새벽, 새벽녘, 초저녁, 한낮, 대낮, 야밤, 밤중, 어스름, 미명, 황혼, 해거름, 저물녘, 일출, 일몰, 동트다 … |
| N → **Y** (13개) | 아침, 한밤, 한밤중, 오밤중, 조조, 야간, 심야, 정오, 자정, 하오, 아침나절, 저녁녘, 새벽같이 |

`새벽`·`황혼`처럼 빛이 함께 서술된 낱말은 **시간대 + 빛 두 축에 모두** 들어간다. 다축을 허용하기로 한 결정이 여기서 바로 쓰인다.

**시간대 축에 넣지 않은 것** — 시각을 가리키지만 성격이 다르다.

| 갈래 | 보기 | 왜 빼는가 |
|---|---|---|
| 하루 전체의 지속 | 온종일, 종일, 진종일, 하루, 하루해, 주야, 밤낮 | 특정 시간대가 아니라 "내내" |
| 밤 동안의 지속 | 밤새, 밤새껏, 철야, 날밤 | 〃 |
| 낮 길이의 단위 | 나절, 반나절, 한나절 | 시간 길이 단위 |
| 특정 날짜의 밤 | 간밤, 지난밤, 전야, 엊저녁, 제야, 이브 | "어제의" 같은 지시가 붙어 장면을 서술하지 못한다 |
| 옛 시각 구분 | 일경, 이경, 삼경, 오경, 초경 | 고어 시각 단위 |
| 절기·명절 | 동지, 하지, 춘분, 추분, 설날 | 날짜다. 계절 축 소관 |

**(3) 참조뿐이라 판단 못 하던 것 → §7-7에서 전량 해소**

> DB `mood_vocabulary.axis` 의 check 제약에는 아직 **축 10개만** 들어 있다. 마이그레이션 0121에서 `시간대` 를 넣어야 한다 (§3).

## 9. 대표 무드 그래프 (2026-09-16)

축 배정에 들어가기 전에 **사람이 순서를 바꿨다** — 5,176개를 11축에 나누기 전에, 낱말끼리의 위아래 관계부터 세운다.

이유는 이렇다. 목록에 `예쁘다`와 `어여쁘다`가 나란히 있으면 사용자에게 둘 다 보여 주게 된다. **대표만 화면에 보이고 나머지는 그 밑에 숨는 구조**가 먼저 필요하다.

```
■ 예쁘다  ← 대표
  └ 어여쁘다 · 아리땁다 · 곱상하다 · 수려하다
■ 멋지다
  └ 힙하다 · 쿨하다 · 세련되다
```

> 대표 밑의 식구도 **검색어로는 살아 있어야 한다.** 사람이 "잘하면 2,500개도 사용자가 볼 수 있다"고 했다.
> 식구를 버리는 게 아니라 접어 두는 것이다.

### 9-1. SigLIP은 한국어를 못 읽는다 (실측)

낱말끼리 얼마나 가까운지 재려고 이미 있는 SigLIP2를 썼는데, **한국어를 그대로 넣으면 못 쓴다.**

| 넣은 것 | 유의어 최저 | 무관어 최고 | 여유 |
|---|---:|---:|---|
| 한국어 낱말 | 0.856 | 0.930 | **−0.074 (뒤집힘)** |
| 한국어 뜻풀이 | 0.895 | 0.881 | +0.014 (아슬아슬) |
| **영어 프롬프트** | 0.849 | 0.756 | **+0.093** |

`예쁘다~울퉁불퉁하다`(0.930)가 `예쁘다~아리땁다`(0.928)보다 가깝게 나온다. 벡터가 0.9 근처에 뭉개져 유의어와 무관어가 안 갈린다. SigLIP2가 영어 중심으로 학습된 탓이다.

**그래서 낱말마다 짧은 영어 문구가 필요해졌다.** 번역이 아니라 **"이 낱말이 가리키는 사진의 모습"** 이다.

```
그윽이   번역 → "deeply"                ← 아무 사진도 안 걸린다
        필요 → "deeply and serenely"   ← 은은하고 깊은 분위기가 걸린다
```

버리는 일은 아니다. `mood_candidates.english_prompt` 컬럼이 이미 있고, 140개 사진 검증(§4)도 영어 프롬프트로 돌렸다.

### 9-2. 프롬프트 5,176개 — 로컬 LLM

사람이 로컬 모델을 쓰기로 정해 **ollama + qwen3:14b**(텍스트 전용)를 깔았다.

> `qwen3`(텍스트)와 `qwen3-vl`(비전)은 다른 계열이다. 이 작업은 사진을 보지 않으므로 텍스트 전용이면 된다.
> 페르소나 쪽 `qwen3-vl` 실측(문서 23)과 혼동하지 말 것.

**파일럿을 먼저 돌렸다.** 같은 150개를 제가 손으로 쓴 것과 모델이 쓴 것으로 나란히 비교했고, 모델이 오히려 나은 경우가 많았다 — `신뢰감`을 제가 "sense of trust"로 써서 `낭패감`("sense of dismay")과 붙여 버린 사고를 모델은 "calm confident gaze"로 피했다. 모델이 `expression`·`gaze`·`scene` 을 붙이는 버릇이 **추상 명사를 "화면에 뭐가 보이는가"로 끌어내려** 사진 검색에 유리하다.

| | |
|---|---|
| 모델 | `qwen3:14b` (Q4, 9.3GB) |
| 속도 | 초당 4.1개 — **5,176개 21분** |
| 조건 | SigLIP 컨테이너를 내려 VRAM 확보 → GPU에 100% 적재 |
| 형식 오류 | 0건 (한글 섞임·빈 값·칸 어긋남 없음) |

### 9-3. 프롬프트가 같으면 곧 묶음이다

생성 결과 **5,176개가 서로 다른 프롬프트 3,641개로 줄었다.** 같은 프롬프트를 받은 낱말은 모델이 같은 뜻으로 본 것이고, 그게 1차 군집이었다.

**검수에서 237개(4.6%)를 고쳤다.** 과하게 뭉친 것을 뜻풀이대로 갈랐다.

```
flickering light (31개)
  ├ 깜박이다 · 껌벅이다 …      → blinking on and off      점멸
  ├ 반짝이다 · 빤짝빤짝 …      → sparkling glints          반짝임
  ├ 가물가물 · 까물까물 …      → faint fading light        사그라짐
  └ 희끗희끗하다              → white speckled patches    아예 다른 말이었다
```

**가장 심했던 건 흔들림 계열**이다. 프롬프트 **66종에 낱말 136개**가 흩어져 있었다(`swaying lightly` / `swaying gently` / `gently swaying` …). 뜻풀이대로 열두 갈래로 재정리했다 — 매달려 흔들림(대롱대롱) / 나부낌(나풀나풀) / 큰 물결(너울너울) / 바람이 붊(살랑살랑) / 넓은 천(펄럭펄럭) / 해져서 늘어짐(너덜너덜) …

잘못 낀 것도 빼냈다: `울렁대다`(가슴 두근거림)·`전전긍긍`(무서워 떪)·`설설`(물이 끓음)·`심금`(마음)이 흔들림 칸에 있었다.

### 9-4. 층층이 묶기 — 임계값이 곧 그래프의 층

프롬프트 3,616개를 SigLIP으로 임베딩하고 **평균연결 응집 군집**으로 묶었다. 단일연결은 낱말 하나가 걸쳐 있으면 무관한 두 무리를 사슬처럼 이어 버린다.

| 층 | 묶음 | 묶인 낱말 | 최대 | 성격 |
|---|---:|---:|---:|---|
| 0.94 | 3,255 | 2,789 | 25 | 표기·활용형 차이 (`흠칫`/`흠칫하다`) |
| **0.91** | **2,647** | 3,473 | 28 | **대표 무드 — 검수하는 층** |
| 0.88 | 1,937 | 4,097 | 56 | 인접 감정까지 묶임 |
| 0.82 | 860 | 4,815 | 215 | 큰 갈래 |

**0.91을 넣은 이유가 있다.** 처음엔 0.88을 대표 층으로 봤는데 56개짜리 덩어리에 `경탄`(감탄)과 `공포`(두려움)가 같이 있었다. 0.91을 껴 넣으니 놀람 28개와 불안·두려움 21개로 정확히 갈렸다 — 손으로 가를 필요가 없어졌다.

### 9-5. 대표 뽑기 — 자동의 한계

각 묶음의 대표를 **어휘등급**으로 뽑았다. 사용 빈도 자료가 없으므로(§1) 등급이 "더 흔한 말"의 대용품이고, 그 사실을 감추지 않는다.

**등급만으로는 안 됐다.** 뜻이 넓거나 동음이의인 쉬운 낱말이 무리를 가로챈다 — `단순`(초급)이 `또렷하다` 무리를, `성`이 `화나다` 무리를 먹었다. 벡터 중심도를 먼저 보게 고치니 그건 풀렸지만 이번엔 쉬운 말이 밀려났다(`슬프다` → `그렁그렁하다`).

**어느 쪽으로 기울여도 한쪽이 깨진다. 낱말이 무리의 뜻을 대표하는지는 의미 판단이라 벡터가 못 한다.** 그래서 갈랐다.

- **식구 5개 이상 146개** — 사람 눈에 먼저 닿는 것들. 전수로 봤고 **98개의 대표를 바꿨다**
- **나머지 2,501개** — 대부분 `흠칫`/`흠칫하다` 같은 활용형 짝이라 자동 결과를 쓴다

**바꾼 대표 98개의 갈래**

| 갈래 | 보기 |
|---|---|
| 뜻이 어긋남 | `슬픔`→**서운하다**, `파란색`→**쾌청하다**, `나쁘다`→**싫어하다**, `젊다`→**발랄하다** |
| 동음이의라 검색어가 못 됨 | `성`→**화나다** |
| 활용형이 대표가 됨 | `외로움`→**외롭다**, `창피`→**창피하다**, `깜박대다`→**깜박이다** |
| 사전에서만 쓰는 말 | `고온`→**폭염**, `큰비`→**폭우**, `결빙`→**서리**, `광야`→**허허벌판** |

**뒤엉킨 무리 2개는 손으로 쪼갰다** (프롬프트도 함께 고쳐 다시 돌려도 같은 결과가 나온다).

```
놀라다(28) → 놀라다 +11 · 경탄 +6 · 어이없다 +4 · 얼빠지다 +3
사명감(11) → 사명감 +5 · 무뚝뚝하다 +3 · 근엄하다
```

### 9-6. 검수 화면

`/admin/photo-purpose/mood/review` — `사진 목적&무드` 탭의 **무드 검수**.

묶음 크기로 세 탭(식구 5개 이상 146 / 1~4개 797 / 홀로 1,704)이 겹치지 않게 갈린다. 카드마다 **확인 · 쪼개기 · 버림 · 대표 바꾸기**가 있고, 펼치면 식구 전원의 품사·등급·뜻풀이가 보인다. 검색은 대표뿐 아니라 **식구와 영어 프롬프트에도** 걸린다.

**피드백 칸은 카드 맨 아래에 늘 열려 있고 판정과 따로 저장된다.** 처음엔 메모가 판정 버튼에 얹혀 있었는데, 쪼개기로 본 묶음에 한 줄 덧붙이려면 버튼을 다시 눌러야 하고 그러면 판정이 확인으로 덮였다. 이제 판정 없이 메모만 남길 수 있고, 그런 기록은 `status` 가 없어 **진행 수에 세지 않는다** — 피드백을 적었다고 판정이 되면 남은 일을 셀 수 없다.

**판정은 `scripts/embed/out/mood-vocabulary/head-review.json` 에만 쌓이고 DB에는 아무것도 쓰지 않는다.**

> **다른 PC에서도 검수할 수 있다.** 화면이 읽는 자료는 `scripts/embed/mood-review-bundle.json`(1MB)로 **저장소에 커밋돼 있다.**
> 원본 산출물은 `scripts/embed/out/`(Git 제외, 만든 PC에만 있음)이라 그대로 읽으면 다른 PC에서 화면이 뜨지 않는다.
> `build_mood_review_bundle.py` 가 검수에 필요한 것만(그래프 + 낱말별 품사·등급·뜻풀이 3개) 추려 번들을 다시 만든다.
> **검수에는 SigLIP도 qwen도 필요 없다.** 둘은 어휘를 새로 늘리거나 사진으로 검증할 때 다시 쓴다(§12).

### 9-7. 검수 결과 — 자동 결과를 그대로 쓴다 (2026-09-16)

**사람이 화면을 훑어본 뒤 이 상태로 확정했다. 판정 0건, 메모 4건.**

식구 5개 이상 146개는 §9-5에서 이미 손으로 봤고(대표 98개 교체), 나머지 2,501개는 대부분 `흠칫`/`흠칫하다` 같은 활용형 짝이다. 전수로 버튼을 누르는 대신 훑어보고 **자동 결과를 받아들였다.**

> `head-review.json` 에는 아래 메모 4건만 있다. `status` 가 없으므로 진행 수는 `0 / 2,647` 이고, 이는 **안 한 일이 아니라 누르지 않기로 한 결정**이다.

| 묶음 | 메모 |
|---|---|
| 깜박이다 | 명멸은 빛이 깜빡이는 것인데, 사진에서 '깜빡임'은 빛 쪽으로 먼저 읽히나 눈 쪽으로 먼저 읽히나 |
| 상쾌하다 | 풋풋하다·싱그럽다는 조금 다른 것 같다 |
| 더럽다 | 주접이 더러운 건가 |
| 창피하다 | 미안스럽다는 조금 다른 것 같다 |

**넷 다 축 배정에서 답이 난다.** "이 낱말의 어느 뜻을 근거로 축을 붙이나"가 같은 질문이기 때문이다(§10-3 `sense참조`). 그래프를 고치려고 여기로 돌아오지 말 것.

### 9-8. 판정을 그래프에 되먹이는 코드는 없다

화면은 **기록만 한다.** `head-review.json` 을 읽는 코드는 화면(`mood-review-data.ts`)뿐이고, 그래프 파일(`mood-heads-0.91.json`)로 돌아가는 경로가 없다. §9-5의 사람 결정도 이 화면이 아니라 손으로 반영한 것이라(`picked_by: "사람"` 을 쓰는 스크립트가 없다) 되먹임 코드가 만들어질 계기가 없었다.

이번에는 판정이 0건이라 문제가 되지 않았다. **나중에 판정을 쌓는다면** 넷의 난이도가 다르다는 것부터 보라.

| 판정 | 그래프에 할 일 |
|---|---|
| 확인 | 없음 |
| 버림 | 묶음 제거 — 기계적 |
| 대표 변경 | head↔member 교체 — 기계적 (화면이 `head` 를 이미 받아 둔다) |
| **쪼개기** | **자동 불가.** 화면은 "쪼개라"만 받고 "어떻게"는 안 받는다 |

쪼개기의 반영 경로는 그래프 수정이 아니라 **파이프라인 앞쪽으로 되돌아가는 것**이다 — §9-3처럼 영어 프롬프트를 갈라 쓰고 `embed_mood_prompts.py` → `cluster_mood_graph.py` → `pick_mood_heads.py` 를 다시 돌린다. 그래서 쪼개기를 누를 때는 **어떻게 갈라야 하는지를 피드백 칸에 함께 적어야** 한다. 안 적으면 그 묶음을 처음부터 다시 판단해야 한다.

## 10. 다음 단계 — 축 배정 작업 지시

**Y 5,176개에 축을 붙인다.** 무드 여부는 §7에서 이미 갈렸으니 다시 판단하지 않는다.

> **§9의 그래프가 먼저다.** 대표 2,647개에 축을 붙이면 식구는 대표를 따라간다 — 5,176번이 아니라 2,647번으로 줄어든다.
> **그래프는 §9-7에서 확정됐다. 검수를 다시 하지 마라.**

### 10-1. 다축이 무슨 뜻인가

**한 낱말이 축 하나에만 들어가는 게 아니다.** 붙는 축은 전부 **대등**하다.

| 낱말 | 축 |
|---|---|
| `황혼` | 시간대 + 빛 |
| `씁쓰름하다` | 감정 + 질감 |
| `쌀쌀하다` | 온도 + 계절 |
| `아늑하다` | 감정 + 공간 |
| `고즈넉하다` | 감정 + 에너지 + 공간 |

`황혼`을 시간대에만 넣으면 "노을빛 사진" 검색에서 빠지고, 빛에만 넣으면 "해 질 무렵" 검색에서 빠진다.

> **파일럿의 대표축/보조축 구분은 폐기됐다 (2026-09-16).** 대표만 검색에 쓰이면 같은 문제가 생긴다.
> 출력 형식도 그래서 바뀐다 — 아래 9-3.

### 10-2. 입력

```bash
cd scripts/embed && python build_mood_axis_input.py        # → out/mood-vocabulary/axes.txt + axes-index.json
```

**대표 2,647개만 담긴다** — 식구는 대표를 따라가므로 낱말 5,176번이 아니라 2,647번이다.

자료는 저장소에 커밋된 `mood-review-bundle.json` 에서 나온다. **`out/` 이 없는 PC에서도 만들 수 있다** — 산출물을 만든 PC가 아니어도 축 배정을 시작할 수 있다는 뜻이다.

한 항목은 이렇게 생겼다.

```
[0001] 깜박이다  |  식구 24  |  blinking on and off
   · 동사 / 중급
     s1. 불빛이 밝았다 어두워졌다 하다. 또는 그렇게 되게 하다.
     s2. 눈이 자꾸 감겼다 뜨였다 하다. 또는 그렇게 되게 하다.
     s3. 기억이나 의식 등이 잠깐 흐려지다.
   · 식구: 깜박 · 깜박거리다 · 깜빡이다 · 명멸 …
   · 검수 메모: 명멸은 빛이 깜빡거리는 것인데 …
```

- `[0001]` — 항목 번호. **출력에 그대로 쓴다.** `1` 로 써도 받는다
- `s1`, `s2` … — **대표의** sense 번호. **여기 없는 번호를 쓰면 컴파일러가 거부한다**
- `· 식구` — 참고용이다. 식구의 뜻풀이에는 번호가 없다. **축의 근거는 대표의 뜻이다**
- `· 검수 메모` — 그래프 검수에서 남긴 물음(§9-7). **여기가 답할 자리다**
- 대표 2,647개는 **전부 뜻풀이가 있다.** sense 칸을 `-` 로 둘 일은 없다

> 2,647개를 한 번에 다루기 버거우면 조각으로 나눈다. 번호는 전체 기준을 유지하므로 합칠 때 겹치지 않는다.
> ```bash
> python build_mood_axis_input.py --stem axes-1 --from 1 --to 500
> ```
> 다만 컴파일러는 **그 조각의 항목이 전부 채워졌는지**를 검사한다. 조각마다 따로 컴파일한다.

### 10-3. 출력

항목당 정확히 한 줄, `|||` 로 구분한다. 머리말·번호매기기·코드펜스를 붙이지 마라.

```
번호|||축|||sense참조|||사진 용례|||근거

1|||질감,감정|||s1,s3,s4|||표면이 거칠지 않고 매끄럽게 보이는 사진|||s1·s3 촉감을 직접 서술한다. s4 성격이 다정하다는 뜻도 함께 남긴다
7|||시간대,빛|||s1|||해 질 무렵 붉게 물든 하늘|||해가 지는 때이면서 그때의 빛을 함께 가리킨다
```

| 칸 | 규칙 |
|---|---|
| 번호 | 입력의 `[001]` 번호. 빠뜨림·중복·신규 금지 |
| 축 | §8의 11개 중에서. 쉼표로 여러 개. **최소 1개**, 우열 없음 |
| sense참조 | `s1,s3` 형식. 뜻풀이가 있으면 **반드시 1개 이상**. 없으면 `-` |
| 사진 용례 | 한 줄 필수 |
| 근거 | **항상 필수.** 인용한 뜻풀이가 왜 그 축인지 한국어로 짧게 |

`kind` 칸은 없다 — 입력이 이미 무드로 확정된 5,176개뿐이다.

### 10-4. 이미 내린 판정 — 여기에 맞춰라

파일럿 500개에서 실제로 내린 결정이다. 같은 성격의 표현은 같게 가야 앞 구간과 어긋나지 않는다. 근거까지 `classification-v2.json` 과 `decisions-raw.txt` 에 남아 있다.

| 표현 | 축 | 근거 |
|---|---|---|
| 부드럽다 | 질감, 감정 | 살갗에 닿는 느낌이 거칠거나 뻣뻣하지 않고 미끄럽다 |
| 거칠다 | 질감, 에너지 | 표면이 곱거나 부드럽지 않다 |
| 따뜻하다 | 온도, 감정, 관계 | 온도가 알맞게 높다 / 분위기가 정답고 편안하다 |
| 어리다 | 빛 | 빛이나 그림자가 희미하게 비치다 (나이가 적다는 동음이의는 근거 아님) |
| 샛노랗다 | 색감 | 진하게 노랗다 — 사전 범주가 '식생활 > 맛'으로 **잘못** 붙어 있어도 뜻풀이를 따른다 |
| 씁쓰름하다 | 감정 | s2 기분이 썩 좋지 않다 (s1 맛은 근거 아님) |
| 왁자지껄하다 | 에너지 | 매우 떠들썩하고 소란스럽다 — 장면 전체의 상태 |
| 고풍스럽다 | 스타일 | 보기에 옛것과 같은 **멋**이 있다 |

**부사** — 시각 상태를 가리키는 부사(`휘황히` `환히` `뜨듯이`)는 근거에 **대표형과 묶어야 한다**고 적는다. 활용형이 태그 목록에 따로 뜨면 지저분해진다.
